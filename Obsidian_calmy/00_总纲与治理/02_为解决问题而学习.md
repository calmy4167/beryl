# 十、为解决问题而学习

> 最新产品理念 · 生效日期：2026-09-07  
> 本章是对前九章的增量裁决。历史正文继续保留，用于呈现设计演化；凡与本章冲突的“学习时长、连续打卡、课程完成、自律提升”目标，均以本章为准。

## 一、核心判断

Calmy 不帮助用户“为了学习而学习”，也不把“成为更自律的人”当作产品目的。

学习只在一种情况下进入核心流程：

> **现实中有一个用户愿意面对的问题，而解决它所需的信息、方法或能力还不够。**

因此，学习不是与工作、关系、健康、创作并列的孤立世界。它是某个 Matter 内部的一种手段：发现缺口时按需取得，取得后立即回到现实使用，够用以后停止。

自律也不是结果。能够持续行动有时有价值，但连续性只是某种条件，不代表方向正确、问题有进展或生命被更好地使用。Calmy 不给“坚持”本身发奖，也不因中断而惩罚。

## 二、问题驱动学习闭环

正式闭环统一为：

```text
现实问题
  → 希望发生什么变化
  → 什么证据表示有进展
  → 当前缺少什么信息、方法或能力
  → 只学当下必要的一小部分
  → 立即用于一次行动、产物、决定或实验
  → 接收现实反馈
  → 继续、换方法、暂停，或确认已经足够
```

学习的最小单位不再是“一章课”“一小时”或“连续一天”，而是：

> **为了完成下一次现实验证，我现在必须弄懂什么？**

如果不需要学习就能行动，系统不应制造学习任务。如果一条资料暂时没有明确用途，可以保留为 Seed 或 Resource，不应自动进入 Today。

## 三、什么叫“问题”

问题不等于狭窄、短期、功利的任务。它可以是：

- 实际困难：怎样修复当前故障、完成一次沟通、作出一个决定；
- 关系张力：这次冲突真正发生了什么，下一次怎样验证新的沟通方式；
- 创作命题：这件作品想表达什么，怎样做出第一个可被看见的版本；
- 好奇问题：某个现象为什么发生，怎样接触证据而不是只消费解释；
- 探索假设：我怀疑某种方法有效，怎样用一次小实验检验；
- 长期课题：职业、身体、家庭或人生阶段中仍未解决的矛盾。

用户主动选择“我想弄清什么”就足以形成探索方向，不要求所有学习都立刻产生经济收益。同时，休息、欣赏、娱乐、散步和普通生活不必被包装成学习，也不必证明有用。

## 四、Matter、Today、Flow 与 Library 如何改变

### Matter

“学习 Java”“读 50 本书”“每天学两小时”默认不是合格 Matter。系统应温和追问：

- 你现在具体卡在哪里？
- 你希望现实发生什么变化？
- 什么证据能说明这次已经够用？
- 你下一次会把它用在哪里？

一个更合适的 Matter 是：“独立完成鉴权模块”“能在客户会议中解释方案并回应追问”或“弄清这个历史判断由哪些一手证据支持”。

可按需保留六个字段：问题、期望变化、进展证据、当前缺口、下一次验证、停止条件。它们可以渐进补全，不要求用户首次创建时填一张复杂表单。

### Today

Today 优先展示可产生反馈的动作：

- 不写“学习事务 2 小时”，写“读懂当前失败用例涉及的事务边界，并让一个测试通过”；
- 不写“练英语 30 分钟”，写“准备并录下 2 分钟产品说明，请一位听众指出听不懂的地方”；
- 不写“看完沟通课程”，写“选一个当前冲突，尝试一条课程中的提问方式并记录回应”。

时间可以帮助判断容量，但不能替代动作结果。

### Flow

原“学习模式”在用户界面改为“解题模式”。进入前先选择当前问题、需要的证据和应用位置；每次只提供填补当前缺口的有限内容。核心动作改为：

- **用于当前问题**：保留关联并准备现实动作；
- **试一下**：直接建立一次验证；
- **已足够**：结束内容供给，不再用更多资料制造压力；
- **再见**：当前无关，降低再次出现。

底层“正在学习 / 已学会”状态可以为了旧数据兼容暂时保留，但不再主导界面和指标。

### Library

Library 保存来源、证据、历史使用和可复用材料。收藏本身不算进展。只有当内容帮助形成判断、产物、行动或新的可验证问题时，系统才记录它与 Matter 的关系。

## 五、LIMS 与报告如何改变

LIMS 结构仍然有价值，但检测对象应从“我今天够不够自律”转向“当前方案是否帮助问题向前”。

默认检测项优先是：

- 问题是否被更准确地描述；
- 是否识别出当前关键缺口；
- 是否产生了可检查的产物或决定；
- 新知识是否在现实中被使用；
- 使用后返回了什么事实与反例；
- 是否已经达到停止条件。

学习时长、答题数、正确率和连续天数只有在三种情况下可以出现：用户明确选择它作为诊断信号；外部考试、资格或制度确实要求；研究问题本身正在检验该变量。即使出现，它们也不能单独给出“成功、失败、自律、懒惰”的人格结论。

报告不再主要回答“学了多少”，而回答：

1. 我试图解决什么问题；
2. 原先以为缺什么，后来证据怎样修正了判断；
3. 我取得并使用了什么最小知识；
4. 现实产生了什么结果、反例或新的限制；
5. 下一轮继续、换方法、暂停还是已经足够。

## 六、AI 的行为边界

当用户说“我要学习 X”时，AI 不直接生成长期课程表。它先帮助澄清：

- 当前什么情境触发了这个需求；
- 用户要作出什么行动、产物或判断；
- 现有能力与所需能力之间缺哪一块；
- 最小查证或练习是什么；
- 怎样验证，什么时候停止。

AI 可以解释、查证、生成练习、比较方案和准备材料，但必须把用户送回应用。它不能用“你应该坚持”“今天还没学”“连续记录中断”评价用户，也不能把过去的学习行为推断为稳定人格。

## 七、成功指标与反指标

优先指标：

- 从提出问题到第一次现实应用/验证的时间；
- 用户能否说清问题、缺口、使用位置与停止条件；
- 一次学习是否产生可验证产物、决定、反馈或反例；
- 用户能否因为“已经足够”而停止继续收集；
- 问题是否更清楚，下一步是否更具体、更可承受。

反指标：

- 学习时长、连续天数、课程完成量、答题量、收藏量；
- 以“更自律”“更努力”“没有中断”证明产品价值；
- 无应用位置的知识推荐和无限课程；
- 因暂停、停止、换方向或发现问题问错而制造失败感。

## 八、跨模块执行规则

1. 报告体系以问题演化和现实证据组织，不以学习总结组织。
2. LIMS 与实验体系允许过程指标，但结论必须回到问题与应用结果。
3. 产品体验默认从“你正在解决什么”进入，不从“今天学多久”进入。
4. 自定义平台可以配置学习时长，但必须标明它是用户/外部标准选择的诊断变量，不是系统默认价值。
5. 软件之外的卡片、服务和空间应围绕当前问题与下一次实践，不制造学习身份和打卡仪式。
6. 历史文档中的学习时长、自律与连续性例子保留为演化记录；若未明确关联问题和应用证据，不得直接进入当前产品实现。

## 九、一句话产品表达

> **Calmy 不帮助你看起来一直在学习；它帮助你在现实问题出现时，找到当下需要知道的那一点，用出去，听见现实的回答，然后继续或停下。**
