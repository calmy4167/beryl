## 文档层级

1. **总文档**：汇编完整产品方向、原则和设计内容，在本 Obsidian 文档库内具有最高约束力。
2. **模块文档**：按产品领域拆分，便于局部维护；内容通过同步机制回写总文档。
3. **模块 README**：说明模块边界、依赖关系和阅读顺序，不替代正式设计正文。
4. **草稿与实现文档**：可以补充细节，但不得暗中改变总文档中的核心定义。

## 双向同步规则

- 只修改总文档：同步工具会把变更拆分到对应模块。
- 只修改模块文档：同步工具会按既定顺序合并回总文档。
- 总文档和模块同时修改：自动停止并生成冲突报告，禁止静默覆盖。
- 新增正式模块：先更新 `90_同步与变更/同步配置.json`，再执行同步。

常用命令：

```powershell
# 自动判断同步方向
.\90_同步与变更\Calmy-文档同步.ps1 -Mode Auto

# 查看同步状态
.\90_同步与变更\Calmy-文档同步.ps1 -Mode Status

# 持续监视并自动同步
.\90_同步与变更\Calmy-文档同步.ps1 -Mode Watch
```

## 编辑原则

- 核心概念发生变化时，必须同步检查受影响的报告、LIMS、交互、自定义、权限和服务设计模块。
- 不删除历史判断；发生替代时标注“废止、替代、原因和日期”。
- Measurement、Observation、Meaning、事实、解释和结论必须保持区分。
- AI 可以整理、查找异常与反证，但最终 Meaning 和 Conclusion 由人确认。
- 学习只用于填补真实问题的当前缺口，并必须回到应用或验证；学习时长、连续天数、课程完成和“更自律”不得作为默认产品结果。
