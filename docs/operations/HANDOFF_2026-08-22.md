## 当前实现事实

- 生产入口是 `index.html → src/react/main.tsx → src/react/App.tsx`。
- React 已承接核心 Today、Capture、Matters、Review、Cycle、我的和扩展模块路由。
- 桌面端具备左主栏和默认收起的独立右栏；窄桌面和移动端使用 More 抽屉。
- 现有领域、应用用例、异步 Repository、IndexedDB durable 边界、导入导出、同步兼容层和测试证据以实现总档案为准。
- Finance、Pomo、Inbox 的直接同步写入已收口到异步 Repository；Finance/Inbox 跨仓储流程已提取为 Application Use Case 并完成幂等测试，不应恢复旧版同步写入作为新事实源。
- 实体迁移回滚必须使用 `rollbackMigrationDurable`；旧的同步 `rollbackMigration` 仅保留给自定义 Storage/兼容测试，不作为生产管理页入口。
- `applyEntityRecords` 现在是异步入口；新增同步调用必须 `await`，以保证远端实体应用完成 durable flush 后再推进同步流程。
- 共享协作异步写入口支持末尾的调用方命令 ID；需要跨网络重试的创建、更新、状态变更和 Record 修订应复用同一个命令 ID，避免重复实体与审计。
- React Review 使用 `listActionRecordDocumentsAsync` 读取 Action/Record 证据；新增 React 跨域查询应优先复用异步查询入口，不要重新调用同步 `listRealityDocuments`。
- 全量 React Reality 查询使用 `listRealityDocumentsAsync`；新增 React 页面应复用该入口，只有 Vue 兼容层和未迁移旧模块继续使用同步查询。
- Vue、Vue Router、Element Plus 和旧 Vue 页面仍是迁移兼容层，不是当前生产主入口。

### 2026-08-28 档案校准

- 当前 React 主路径的 Reality 查询已统一到异步入口；`src/react/bootstrap.ts` 中保留的同步模块统计 reader 仅服务旧统计兼容，不是 React 页面数据查询入口。
- 实体同步应用远端记录时会先比较本地变更日志版本，并在真正写入后等待 durable flush；共享协作调用方命令 ID 会贯穿实体写入与审计，重复提交不新增事实。
- 当前自动化基线为 57 个 Vitest 文件、278 个测试通过；Node 15/15、同步协议 22/22、IndexedDB 浏览器运行时、类型检查、构建、PWA、性能和 UI smoke 均通过。实体同步同设备版本递增、批量顺序、失败时不推进游标以及 React 工作台键盘边界回归已补齐。OW-04 的真实设备、键盘连续操作、读屏和大字号验收仍待人工执行。
