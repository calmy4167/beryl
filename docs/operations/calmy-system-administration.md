# Calmy 系统管理模块运行说明

## 能力边界

系统管理账号用于登录后台和管理系统能力。系统角色不会授予访问其他用户 Vault、密文、密钥包或业务 Entity 的权限。Calmy 的 Space 表达长期关系环境，Person 和 Relation 表达现实人物与关系，SceneParticipant 表达场景参与身份；这些均不是账号部门或岗位，也不映射为 SystemRole。

| 内置角色 | 能力 |
| --- | --- |
| 超级管理员 | 全部系统管理能力；不可删除或编辑权限 |
| 用户管理员 | 用户列表、创建、资料状态、停用、删除、重置密码、解锁、角色分配，以及只读查看角色 |
| 安全管理员 | 登录安全策略、解锁、会话查看和撤销 |
| 审计查看员 | 登录日志、操作日志和只读在线会话 |
| 普通用户 | 不含后台管理能力 |

系统角色的 capability 只在 Worker API 中执行校验，前端路由和导航隐藏仅用于交互。默认安全策略允许 6–256 位密码，不强制字符组合；账号首次使用或密码被管理员重置后必须修改密码。登录验证码默认关闭。失败锁定默认是 30 秒内失败 5 次后锁定 30 秒。密码默认不过期。

## 数据与日志

用户身份仅保存登录所需账号资料和 PBKDF2-SHA256 密码哈希。临时密码仅在创建或重置响应中显示一次。Session 保存 token 哈希，不保存可复用令牌明文。登录日志可以包含规范化账号、结果、时间、IP、设备和 User-Agent。操作日志只允许保存变更字段名称，不保存字段值。以上日志不接触 Vault 内容。

日志保留期默认 180 天，由后台日志读取时按 `security.audit.retentionDays` 清理过期审计行。清理只针对登录与操作日志，不删除用户、身份、会话或 Vault 数据。

## 本地数据库迁移

先备份**本地/目标 D1**，确认 Worker 使用的 D1 binding 指向正确环境。迁移会在 identity 表中增加账号资料和 Session 元数据列，并创建 RBAC、安全设置、登录挑战及审计表，不迁移或读取 Vault 内容。

在 `backend` 目录运行：

```powershell
npx wrangler d1 migrations apply <本地数据库名称> --local
```

启动本地 Worker：

```powershell
npx wrangler dev --local
```

Worker 运行代码会创建必要的空表；已有数据库新增列必须先应用 `0002_system_administration.sql`。若迁移失败，不要继续启动依赖新列的 Worker。恢复迁移前备份，或在本地 D1 删除并重建后重新运行已验证的迁移。生产库不得使用 `--local` 之外的环境参数，生产迁移和部署必须经过单独的发布授权与备份流程。

## 创建管理员及普通账号

首次管理员仍通过 `CALMY_BOOTSTRAP_SECRET` 调用 `/api/auth/bootstrap` 初始化。迁移会将旧 `admin` 账号映射为 `system.super_admin`，将旧 `user` 账号映射为 `system.basic_user`。新普通账号由有权限的系统管理员在“系统管理 → 用户管理”创建，系统生成随机临时密码，并要求首次登录修改。

当前默认策略允许设置 `123456`。用户可通过正常改密流程设置；管理员重置密码后，用户会获得一次性显示的随机临时密码，再自行改成符合当前策略的密码。不要把密码写入源代码、审计日志或工单。

## 部署边界

本地实现不会自动变更已部署 Worker 或生产 D1。正式上线前需单独备份并应用迁移，再部署 Worker 和前端。迁移新增列不能通过仅部署代码替代；需在该版本 Worker 启动前完成迁移。回滚优先回滚应用代码并保留新增列/表；SQLite 删除列并非可靠回滚路径，不要为回滚而删除身份或 Vault 数据。
