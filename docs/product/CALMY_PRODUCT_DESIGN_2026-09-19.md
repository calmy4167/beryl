# Calmy 产品总设计：人与世界之间的反思层

> 版本：2026-09-19
>
> 状态：当前产品方向
>
> 实现边界：本文定义产品本体与迁移目标，不表示当前界面、领域模型或外部工具集成已经完成。当前实现事实以实现档案和 `OPEN_WORK.md` 为准。

## 1. 产品从哪里出发

Calmy 不再把人生预设成许多等待管理的任务、目标或项目。

人始终处在某种世界之中：世界不断作用于人，人不断感知、理解、选择和回应；这些回应又逐渐塑造这个人。Calmy 关注的不是抽象的“一件事”，而是：

> 我正在面对什么，它为什么影响我，我准备怎样回应，它最终又把我带向哪里。

后台可以用结构化对象保存这种上下文，但用户不需要先理解 Matter、Action、Record、Cycle、Stage、Trajectory 或 Situation 才能使用产品。前台先说人的语言：

- 最近有什么一直在你脑子里？
- 现在发生了什么？
- 你觉得它意味着什么？
- 你准备怎样回应？
- 这样走下去，未来的你会怎么看？

## 2. 产品定义

Calmy 是人与世界之间的反思层，也可以从技术边界上称为 `Human Context OS`。

专业软件负责完成专业工作：

- Word 负责文档表达；
- Excel 负责结构化数据和计算；
- IDE 负责代码；
- Obsidian 负责知识组织；
- Calendar 负责时间安排；
- 微信、邮件负责通信；
- 浏览器负责进入互联网。

Calmy 不复制这些能力。Calmy 保存并理解它们之间通常会丢失的关系：

- 为什么打开这份文档；
- 为什么研究这些资料；
- 为什么要见这个人；
- 当时希望得到什么；
- 为什么作出这个决定；
- 最后发生了什么；
- 这段经历如何改变了自己。

因此，专业软件主要回答“怎么做”，Calmy 主要回答：

> 我正在面对什么，为什么这样做，结果意味着什么。

## 3. 产品目的：让未来参与今天的选择

Calmy 最有辨识度的能力是“提前后悔”：在仍然来得及选择时，让人提前经历一种可能的未来，并带着那份感受回到今天。

这不是简单的风险提示，也不是用恐惧劝人保守。产品采用更完整的“未来回望”：

- 做了以后，我可能后悔什么；
- 没有做，我可能后悔什么；
- 做了以后，我可能庆幸什么；
- 没有做，我可能庆幸什么。

系统可以帮助人从六个月、五年或生命终点等不同时间位置回望当前选择。死亡不成为独立模块，而是最长时间尺度的观察位置。

未来回望必须同时呈现行动和不行动的可能代价与可能收获。AI 生成的是可修改的情境，不是预言。它必须说明依据、不确定性和遗漏，并允许用户拒绝全部推演。

## 4. 小事少想，大事想深

不是所有内容都值得进入完整反思。Calmy 根据代价、可逆性、持续时间和影响范围调节介入程度：

- 低代价、容易反悔的日常选择，应帮助用户快速略过、留下或行动；
- 影响较久、涉及多人或部分不可逆的选择，可以帮助用户梳理事实、解释和可能路径；
- 高代价、低可逆、长期影响的选择，才适合进入完整的未来回望。

Calmy 的价值不是让人管理更多，而是让人只在值得管理的地方投入注意力。

## 5. 人与世界的循环

Calmy 的主线不是任务生命周期，而是人在世界中的往返：

```text
世界发生变化
  → 某些内容引起注意
  → 人形成理解
  → 人看见不同可能
  → 人作出选择
  → 人回到现实行动
  → 世界返回结果
  → 人从经历中改变
```

产品承担五种责任，但它们不是要求用户依次完成的五个模块：

### 看见

帮助用户看见世界正在发生什么、自己正在经历什么，以及什么正在持续占据注意力。

### 想清

帮助用户区分事实、感受、解释、身份焦虑和过去形成的倾向。系统不急着把生活压缩成任务。

### 选择

帮助用户看见不同可能，通过未来回望理解愿意获得什么、放弃什么、承担什么。

### 入世

停止操作 Calmy，进入现实或打开 Word、Excel、IDE、浏览器等合适工具完成行动。

### 回望

接收现实反馈，理解发生了什么、原来的判断是否成立，以及这段经历留下了什么。

Calmy 应出现在人与世界交换的关键节点，而不是占据整个过程。它是做事的开始和结束，不是做事的场所。

## 6. 两种使用深度

### 日常快速循环

绝大多数内容只需要很轻的处理：

```text
遇见
  → 要不要管
  → 略过 / 留下 / 去做
```

保存后可以直接离开；无需分类、建立项目或完成复盘。

### 重要问题的深度循环

只有真正重要、复杂或长期影响的处境，才逐步展开：

```text
我正在面对什么
  → 到底发生了什么
  → 我为什么这样理解
  → 还有哪些可能
  → 从未来回望
  → 我选择什么并愿意承担什么
  → 回到现实
  → 世界给出反馈
  → 回来看看它改变了什么
```

用户可以随时停止、略过、推迟或直接行动。系统不能把深度循环变成必填表单。

## 7. 思想如何进入产品

Calmy 不把哲学设计成页面，也不要求用户学习理论。不同思想只负责校正系统如何理解人：

- 唯识帮助理解感知、分别、执著和经验如何反复塑造理解；
- 现象学提醒系统，人始终已经身处具体情境，不是在世界外管理对象；
- 对关切的研究帮助系统理解，为什么有些内容会从世界中凸显并持续占据注意；
- 实用主义要求思考回到尝试和现实验证，不能无限延长；
- 控制论提供感知、判断、行动、反馈、调整的循环；
- 存在主义提醒系统，每次选择也在塑造“我将成为什么样的人”。

例如用户说“领导没回消息，我觉得他对我有意见”，界面无需显示佛教术语，而应帮助用户区分：

- 可以确认的事实是什么；
- 自己赋予了它什么含义；
- 是否存在其他解释；
- 为什么这件事如此重要；
- 过去是否反复出现类似理解。

## 8. 上下文是 Calmy 自己的核心能力

Calmy 不需要拥有文档、表格、代码、网页或谈话本身。它需要知道这些对象为什么彼此有关。

一个上下文至少可以逐步连接：

- 当前处境的自然语言描述；
- 已知事实和来源；
- 用户的感受、解释与关切；
- 相关人物、地点和时间；
- 文档、表格、网页、代码仓库、消息和日程的引用；
- 曾考虑的可能；
- 决定及当时理由；
- 现实反馈；
- 后来形成的模式与变化。

这些信息按需出现，不要求首次输入时完整填写。外部对象优先以稳定引用、摘要、权限状态和来源连接；除非离线、检索或用户明确选择需要，不复制完整内容。

## 9. 外部工具如何进入系统

外部工具属于“回到现实”的一部分，不是 Calmy 内部的弱化功能模块。

例如，用户决定认真评估是否换工作。Calmy 保存背景、顾虑、判断标准、相关人物、已有证据、决定时间和未来回望；具体工作仍由合适工具完成：

- 浏览器研究岗位；
- Excel 比较数据；
- Word 整理方案；
- IDE 完成项目；
- Obsidian 保存专业知识；
- Calendar 安排面谈。

Calmy 通过链接、导入、协议、插件或自动化与这些工具协作。是否接入某个工具，取决于它能否减少重复录入、保留来源、清楚表达权限并安全回收结果，而不是取决于 Calmy 能否复制该工具的功能。

## 10. 长期理解从经历中长出来

用户不应手工创建“模式”或“轨迹”。长期理解只能从有来源的经历中逐渐观察出来：

```text
经历是点
关系把点连成线
重复形成模式
模式随时间显出方向
```

系统可以提出候选，例如某类冲突反复出现、某种焦虑经常引发同一种回应，或某类长期工作总在相似阶段中断。但这些都必须：

- 指向具体证据和时间范围；
- 使用“记录显示”“可能”一类可推翻表达；
- 允许用户修改、否认、删除或暂不处理；
- 避免把历史行为变成人格标签或命运判断。

## 11. AI 的位置

AI 可以帮助连接散落信息、区分事实和解释、发现遗漏、构造多个未来情境、准备外部工具所需材料，并在现实反馈回来后比较原判断。

AI 不能：

- 把模拟写成预测；
- 只展示最坏未来来推动服从；
- 替用户作出价值判断；
- 把一次行为定义成稳定人格；
- 静默修改事实、决定和长期理解；
- 用掌握的私人上下文制造焦虑、依赖或回访压力。

关键推断必须显示来源、时间范围和不确定性。用户始终可以不同意，并保留改变自己的空间。

## 12. 前台语言与后台模型分开

前台优先使用自然问题和具体动作，不向用户暴露领域模型作为使用门槛。

推荐表达：

- 我正在面对什么；
- 到底发生了什么；
- 为什么我会这样理解；
- 还有什么可能；
- 去未来看一眼；
- 我准备怎么做；
- 后来发生了什么；
- 这改变了什么；
- 先放下。

Matter、Action、Record、Cycle、Stage、Trajectory、Seed 等现有名称暂时作为实现兼容词。后续是否保留，由数据迁移、外部协议和真实用户理解测试决定，不能通过简单改名假装完成产品转型。

## 13. 当前实现的迁移边界

当前代码仍以 Today、Capture、Matters、Review 和既有领域对象为主要组织方式。新方向采用渐进迁移：

1. 先改变用户语言和首个完整体验，不直接删除稳定数据；
2. 用现有对象承载最小试验，验证“正在面对”和未来回望是否真正有价值；
3. 明确上下文、外部引用、决定理由和现实反馈所需的数据缺口；
4. 为旧数据设计兼容读取、导出和可回滚迁移；
5. 经真实试用后，才决定是否引入新的内部聚合或替换旧导航；
6. 最后再移除失去用途的旧概念、页面和兼容代码。

在迁移完成前：

- 新总设计定义方向；
- 旧 Attention OS 总稿解释现有页面和兼容实现；
- 实现档案只陈述当前事实；
- `OPEN_WORK.md` 保存尚未完成的迁移和验收。

## 14. 成功如何判断

Calmy 的价值不由页面数量、记录数量、完成数量、在线时间或连续使用天数证明。

优先验证：

- 用户能否用自己的话表达正在面对的处境，而不是被迫先分类；
- 小事是否很快离开系统，大事是否得到恰当深度；
- 未来回望是否让用户看到行动与不行动两边原先忽略的代价；
- 用户是否更清楚自己为什么作出选择、愿意承担什么；
- 外部工具是否减少重复录入，并保留完整上下文；
- 现实反馈回来后，用户能否修正原来的解释；
- 系统提出的长期模式是否有证据、可推翻且没有制造人格定型；
- 使用 Calmy 的维护成本是否低于它带来的现实收益。

## 15. 停止线

出现以下情况时，不应继续扩大实现：

- 把“正在面对”重新做成另一种项目管理分类；
- 让所有日常选择进入深度反思；
- 用未来模拟制造恐惧、保守或对 AI 的服从；
- 在 Calmy 中复制 Word、Excel、IDE、Obsidian 等成熟产品；
- 为了建立上下文，默认复制用户所有文件和通信内容；
- 用哲学术语作为页面结构或用户使用门槛；
- 在没有真实证据时定义用户的人格、模式或人生方向；
- 新旧数据无法导出、解释或回滚；
- 文档方向更新后，把尚未迁移的代码描述成已经完成。

## 16. 一句话定义

> Calmy 是人与世界之间的反思层：帮助人看见自己正在面对什么，在行动之前经历可能的未来，在行动之后看见这段经历把自己变成了什么。
