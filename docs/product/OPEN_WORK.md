## P0：发布前必须完成

### OW-03 IndexedDB 权威边界深化

已补齐备份前 pending writes 等待、实体迁移计划的 durable 快照、迁移回滚 outbox、实体级远端记录应用后的 durable flush，以及本地未上传版本与远端记录的实体级 LWW 裁决；实体版本已改为同设备跨刷新单调递增，批量待同步记录按最旧到最新读取，避免同毫秒覆盖和超过批次上限时跳过早期变更；共享协作异步写入已支持调用方命令 ID 和重复提交幂等审计；首次实体同步失败不会标记 ready，远端本地写入失败不会推进游标。React 主路径的跨域 Reality 查询与全局搜索已切到异步 Repository。剩余范围收敛为实体日志/实体值原子持久化、首次同步完整合并与成功确认、同步游标 durable 确认、Capture 建议跨集合幂等、键级高级同步复核，以及同步统计/旧 Vue 查询兼容层；localStorage 只作为兼容回退，不再成为新的写入事实源。

验收：刷新、离线重开、存储失败、并发 revision 冲突和备份/迁移前 pending writes 均有可复现测试。

### OW-04 人工端侧与辅助技术验收

在真实移动设备、键盘、屏幕阅读器和大字号环境中复核核心四页、双侧栏、移动 More 抽屉、表单输入、保存状态、Focus/弹层关闭和错误恢复。自动化 smoke 已通过，但不能替代人工审计。

验收：无 P0 可访问性或数据丢失问题；320px、200% 缩放和系统大字号不丢失主行动与退出入口。

> 2026-08-28 对齐结论：57 个 Vitest 文件 / 278 个测试、Node 15/15、同步协议 22/22、IndexedDB 浏览器运行时、PWA、性能基线和 UI smoke 均通过；自动化已覆盖双侧栏、移动 More 抽屉、键盘焦点、核心保存控件和远端应用失败保护，但真实移动设备、连续读屏、大字号和异常恢复仍不能由自动化结果代替。

## P1：核心闭环稳定后的工程收口

### OW-06 Vue 兼容层退出评估

`src/main.ts`、`src/App.vue`、`src/router`、`src/views`、Vue Router 和 Element Plus 当前属于迁移兼容层；只有在依赖扫描、真实路由回归和回滚方案完成后，才分批删除。React 入口和 React 页面当前是生产主路径。

验收：所有生产路由、登录、设置、导入导出、同步和边缘模块均无 Vue 运行时依赖；删除每批兼容代码后全量测试与构建通过。

### OW-07 页面与领域编排拆分

继续拆分大型 `src/react/App.tsx` 和页面文件，将路由、壳层、页面状态、展示组件和 Application Use Case 分离；同时评估扩展模块的按需样式/资源拆分，不改变领域模型和现有 URL。

验收：页面职责可单独测试；跨页面行为通过用例或共享协议复用；切换模块不重复挂载无关监听器；核心首屏不因扩展模块样式和组件 eager 加载而膨胀。

### OW-08 扩展模块质量回归

为 Inbox、Tasks、Habits、Finance、Goals、Pomo、Diary、Posts、Library、Calendar、People、Graph、Scene 和 Admin 补齐离线、导入导出、同步、错误、空状态和可访问性回归，并明确哪些模块仍是兼容/实验能力。

验收：扩展模块不会破坏核心四页，不产生重复实体或第二套同步状态；实验能力不会误显示为稳定能力。

### OW-09 品牌与存储键长期迁移

制定 `beryl-*` 存储键、事件名、包名和用户可见文案的兼容读取与渐进迁移方案。禁止直接改名导致旧用户数据丢失；迁移完成前保留兼容读取和可验证回滚。

### OW-10 真实试点与指标验证

组织 8–12 位目标用户进行 2–4 周试用，观察首次价值时间、7 日闭环率、主动降载/暂停、数据恢复信任和系统是否增加压力。不得以页面数量、在线时长、浏览数量或连续使用代替产品价值。

### OW-15 Attention Surface 与身体优先闭环

将 Today 继续收敛为“现在 / 思考 / 轨迹”的 Attention Surface；保持当前四入口、双侧栏、旧模块 More/兼容路由。增加可跳过的轻量身体状态、Attention Gate 和明确现实出口，不新增第二套 Matter、Experience、Memory 或 Attention 实体。

2026-08-29 已完成 Today 页面切片：身体状态可跳过并影响叙事提示；现在区域只突出一个现实主行动；思考、轨迹、主动放下和现实记录均已降级为按需展开；主行动会先进入进行中并提示关闭 Calmy 回到现实。Capture 五种 Attention Gate 动作也已接入统一应用用例，原文可进入 Action、Matter、Record、Seed 或 archived；剩余范围收敛为 OW-04 的人工设备/读屏验收。

边界：本项定义用户体验和用例行为；`OW-07` 只负责页面拆分与性能结构，二者不得各自实现一套 Today 状态。

验收：用户在 10 秒内能确认一个现实行动；身体状态不填写也可完成流程；疲惫状态可以降载或放下；点击主行动后清楚提示离开系统去现实中行动。

### OW-16 AI 记忆分层与用户控制

在现有 Record、Observation、Insight、Seed 和偏好数据上建立 Fact / Reflection / AI Inference / Preference / Principle 的可见分层；所有 AI 判断保留证据、置信度和确认状态，并支持查看、修改、否认和删除。

2026-08-29 已完成首个可用切片：新增“AI 对我的理解”页面，复用现有 Record 与 Insight；事实、反思、AI 推断、偏好、原则分层可见。AI 推断支持查看依据、确认、修改、否认和可恢复移除；偏好与原则只能由用户主动写入并确认，确认不会改写原始事实。Insight 增加可选记忆层、确认时间和否认时间元数据，并沿用现有统一仓储、版本号和命令幂等边界。

边界：本项不接入新的模型供应商或知识网络，只先完成数据治理和用户控制；更深 AI 能力仍属于 `OW-12`。

验收：AI 推断不能自动成为事实、稳定偏好或人生原则；拒绝/删除后不再参与已确认建议；重复命令和跨集合确认不产生重复实体。

### OW-17 Trajectory 与结束能力

让 Trajectory 支持推进、稳定、停滞、回退、绕路、失去、恢复、重启和未知；统一 Matter/Cycle/Action 的暂停、结束、归档、恢复和 Review“放下”语义。

2026-08-29 已完成首个生命周期切片：Matter 与统一 Cycle/DailyState 共用扩展后的九种轨迹词汇；事项页可直接修改趋势，并将暂停、恢复、结束/归档分开呈现。结束事项显示为“已结束”，不会被当作失败；归档事项可恢复到暂停状态。原有 Action 看板继续负责待开始、进行中、完成、跳过和取消，复盘与 Today 保留放下出口。Trajectory 的自动推断仍只使用 Record 证据，新增的“失去 / 重启 / 未知”先作为用户可确认的表达，不在证据不足时擅自推断。

验收：趋势均可回到 Record 证据并由用户确认或推翻；结束事项不显示为失败；无需继续、无需记录和放下均有清晰出口。

## P2：受控扩展能力

### OW-11 Flow / 沉浸流实现

Flow 目前已完成产品、UX、路线图和验收设计，但尚未作为完整内容能力实现。按路线图分阶段实现：统一 Seed 与来源链路 → 有限浏览层 → Focus → 漫游/学习/回响/专题 → 收下/再见/学会/行动/关联 → 可解释推荐和偏好设置。

验收标准详见统一产品与体验设计的 Flow 与停止线章节；不得先做无限滚动、自动播放、连续奖励或独立同步协议。

### OW-12 AI 理解层深化

真实 AI provider/offline model、知识网络和更深的建议能力暂缓。`OW-16` 的首个记忆治理切片已完成；后续仍需根据核心闭环试点证据扩展，本项不得重新创建另一套用户记忆。

### OW-13 Obsidian Companion Bridge 真实联调

协议、Local REST 适配和浏览器 Vault 相关切片已存在，但真实 Companion Bridge/MessagePort 外部联调仍受外部插件和环境限制。继续标记为实验/阻塞，不进入核心路径，不把协议测试写成真实服务已接通。

### OW-14 共享空间与关系能力试点

Shared Space、多人权限、协作撤回、审计和删除传播需要独立隐私评审与真实试点；在权限和撤回边界完整前，只保留兼容能力，不升级为默认产品入口。
