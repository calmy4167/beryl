# 2026-09-19 文档与界面统一审计

> 性质：实现快照。产品范围仍以产品决策、统一产品设计和 `OPEN_WORK.md` 为准。

## 范围与方法

本轮核对了根目录说明、`docs/` 当前文档、产品参考与历史资料、`Obsidian_calmy/` 模块库、Obsidian 插件说明与原型说明；不把生成物、依赖、测试 HTML、`_v1-backup/` 或 Obsidian 备份当作当前产品规范。

审计按三件事进行：确认每份材料的权威状态、搜索与路由/事实源/UI 相关的陈述、将仍有效的当前文档改为同一套表达。历史文件保留产生当时的事实与证据，避免用今天的结论覆盖追溯记录。

## 结论

当前产品的重复设置问题已经收敛：`/#/app/admin` 是唯一设置与同步主入口，使用完整 Vault / 实体迁移界面；`/#/app/admin/advanced` 是兼容地址，显示同一界面。完整管理页不再被描述为“高级设置”或第二套入口。

所有 React 页面共用一组视觉基础：色彩与表面层级、表单焦点、卡片、主按钮、标签页、空状态、动效与窄屏间距。它只改变表现和可访问性，不新建实体、数据源或同步协议。

## 对齐后的规则

1. 新产品规则先写入 `PRODUCT_DECISIONS_2026-08-19.md`，再更新统一产品设计和 `OPEN_WORK.md`。
2. 用户看得到的同一能力只保留一个主入口；旧地址只能兼容重定向或复用同一界面。
3. 页面样式通过共享令牌与组件规则调整，不以复制页面、复制 CSS 或新增独立数据模型解决体验问题。
4. 飞书、Vault、同步、导入导出和实体迁移都必须清楚说明数据去向、保存状态和失败后的下一步。
5. 发布前仍须完成 `OPEN_WORK.md` 中的真实设备、读屏、大字号与线上飞书验收。
