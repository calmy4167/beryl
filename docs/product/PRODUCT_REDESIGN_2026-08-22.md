# Calmy 产品重设计

> 评审版本：2026-08-22 · 状态：本轮产品基线

## 1. 一句话产品定义

Calmy 帮助处在复杂现实和状态波动中的个人，把“我该怎么办”转成今天可以承受的一小步，并从真实发生中调整下一步。

它不是一套更大的任务管理器，也不是把人生哲学一次性呈现给用户的知识系统。

## 2. 首版目标用户

优先用户不是“想管理所有人生数据的人”，而是同时满足以下特征的人：

- 正在处理一个持续数周以上的真实课题；
- 计划很多，但容易在压力、精力或不确定性中失去下一步；
- 愿意每天用 2–5 分钟做定向与复盘；
- 不希望被连续打卡、完成率和失败提示进一步施压。

不优先服务团队项目经理、重度知识库用户、财务记账用户或需要实时多人协作的家庭。

## 3. 唯一核心闭环

```text
Capture 现实
  → 判断是否成为 Matter
  → 为 Today 选择 1–3 个可承受行动
  → Record 真实发生（包括未完成和损耗）
  → Review 调整下一步
```

首个可验证价值是：新用户在 3 分钟内写下一个现实课题和第一步，第二天回来仍能看懂“为什么做、做到了什么、下一步如何调整”。

## 4. 功能分层

### L0：必须强而简单

| 能力 | 用户语言 | 首版要求 |
|---|---|---|
| Capture | 先记下来 | 一步保存；分类全部延后 |
| Matter | 我正在面对什么 | 创建、暂停、恢复、归档、说明为什么重要 |
| Today | 今天守住什么 | 承载状态、1–3 个行动、明确放下事项 |
| Record | 实际发生了什么 | 完成、未完成、回退、娱乐、损耗都可记录 |
| Review | 明天怎样调整 | 事实、条件、调整；不做道德评价 |

### L1：支撑核心闭环

- Cycle / Stage：默认显示为“这一轮”和“当前阶段”，高级用户再展开模型。
- Search：从任何页面调用，支持 Matter、行动、记录和人物上下文。
- 基础导入导出与离线保存：让用户相信数据可带走、可恢复。
- AI 建议：只建议链接、拆分和下一步；必须预览、确认、可撤销。

### L2：二级上下文

- People：只作为课题和记录的关联上下文。
- Library：历史、洞察和导出入口，不做独立知识管理系统。
- Calendar：只提供行动和记录的时间视图。

### L3：暂缓或实验区

- Graph、共享空间、多人权限、情侣/夫妻/家庭场景。
- 博客、习惯、财务、番茄钟、动态、目标等旧模块。
- 十神分类、五行完整术语、无限递归层级。
- 实时双向同步和无人值守 AI 自动执行。

已有代码可以保留作为迁移兼容，但不得默认出现在新用户主路径。

## 5. 关键产品原则

1. **现实先于系统**：记录真实发生，不要求现实服从预设分类。
2. **行动先于理论**：先给下一步，再提供为何如此的解释。
3. **减法是正式能力**：暂停、跳过、放下和降载都不是失败状态。
4. **一处事实，多种视图**：页面不复制实体，不形成第二套状态。
5. **渐进披露**：首屏不出现用户尚未需要的领域术语。
6. **用户确认**：AI、同步冲突和批量变更不得静默覆盖。

## 6. 删除、合并和降级

| 当前表现 | 裁决 | 原因 |
|---|---|---|
| Home 与 Today 并存 | 合并，登录后进入 Today | 两个首页争夺注意力 |
| Cases 与 Matters 并存 | 统一为 Matters；Cases 仅迁移兼容 | 同义概念造成数据和心智分叉 |
| Capture 与旧收集箱并存 | 统一为 Capture | 两个入口破坏低摩擦承诺 |
| People 为主导航 | 降为 Matter 上下文和“更多” | 首版不做关系系统 |
| Library / Calendar | 降为“更多” | 是检索视图，不是每日核心动作 |
| Graph / 场景切换 / 工具箱 | 默认隐藏，进入实验区 | 与 MVP 无关且理论负担高 |
| 五行 / 十神直接命名 | 默认转为自然语言 | 降低学习门槛和价值解释成本 |

## 7. 成功指标与反指标

### 主要指标

- 首次价值时间：首次 Matter + 第一条 Today 行动的中位时间不超过 3 分钟。
- Capture 保存：P50 不超过 10 秒，P90 不超过 20 秒。
- 7 日闭环率：7 天内至少完成两次 `Today → Record → Review` 的用户比例。
- 调整质量：Review 后修改、降载、暂停或明确下一步的比例。
- 数据信任：离线恢复、导出、重新导入任务成功率。

### 诊断指标

- Capture 从打开到保存的中位步骤数和耗时。
- Today 超过 3 个核心行动的比例。
- 核心业务导航数量，发布时不得超过 4 个。
- 首周触发高级模型、Graph、共享空间的比例；若很低，不应进入主导航。

### 反指标

- 不用“完成数量”“连续天数”“系统内停留时间”作为北极星。
- 不通过更多通知和红色失败状态拉高回访。
- AI 未经确认写入和同步静默覆盖的容忍目标均为 0。

## 8. 仍需验证的产品问题

- 用户更能理解“课题”“事项”还是“Matter”？首版只允许一个主名称。
- Morning Opening 是否必须独立存在，还是 Today 的首次编辑状态？
- Review 的最佳触发是用户主动、Today 收尾，还是温和提醒？
- “承载量”使用三级语言还是自由描述更自然？
- 用户是否真的需要 Cycle/Stage 可视化，还是只需要系统内部保留？
