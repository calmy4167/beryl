# Calmy 产品重设计

> 评审版本：2026-08-22 · 状态：本轮产品基线

## 1. 一句话产品定义

Calmy 帮助处在复杂现实和状态波动中的个人，把“我该怎么办”转成今天可以承受的一小步，并从真实发生中调整下一步。

它不是一套更大的任务管理器，也不是把人生哲学一次性呈现给用户的知识系统。

## 2. 首版目标用户

优先用户不是“想管理所有人生数据的人”，而是同时满足以下特征的人：

- 正在处理一个持续数周以上的真实课题；
- 计划很多，但容易在压力、精力或不确定性中失去下一步；
- 愿意每天用 2–5 分钟做定向与复盘；
- 不希望被连续打卡、完成率和失败提示进一步施压。

不优先服务团队项目经理、重度知识库用户、财务记账用户或需要实时多人协作的家庭。

## 3. 唯一核心闭环

```text
Capture 现实
  → 判断是否成为 Matter
  → 为 Today 选择 1–3 个可承受行动
  → Record 真实发生（包括未完成和损耗）
  → Review 调整下一步
```

首个可验证价值是：新用户在 3 分钟内写下一个现实课题和第一步，第二天回来仍能看懂“为什么做、做到了什么、下一步如何调整”。

## 4. 功能分层

### L0：必须强而简单

| 能力 | 用户语言 | 首版要求 |
|---|---|---|
| Capture | 先记下来 | 一步保存；分类全部延后 |
| Matter | 我正在面对什么 | 创建、暂停、恢复、归档、说明为什么重要 |
| Today | 今天守住什么 | 承载状态、1–3 个行动、明确放下事项 |
| Record | 实际发生了什么 | 完成、未完成、回退、娱乐、损耗都可记录 |
| Review | 明天怎样调整 | 事实、条件、调整；不做道德评价 |

### L1：支撑核心闭环

- Cycle / Stage：默认显示为“这一轮”和“当前阶段”，高级用户再展开模型。
- Search：从任何页面调用，支持 Matter、行动、记录和人物上下文。
- 基础导入导出与离线保存：让用户相信数据可带走、可恢复。
- AI 建议：只建议链接、拆分和下一步；必须预览、确认、可撤销。

### L2：二级上下文

- People：只作为课题和记录的关联上下文。
- Library：历史、洞察和导出入口，不做独立知识管理系统。
- Calendar：只提供行动和记录的时间视图。

### L3：暂缓或实验区

- Graph、共享空间、多人权限、情侣/夫妻/家庭场景。
- 博客、习惯、财务、番茄钟、动态、目标等旧模块。
- 十神分类、五行完整术语、无限递归层级。
- 实时双向同步和无人值守 AI 自动执行。

已有代码可以保留作为迁移兼容，但不得默认出现在新用户主路径。

## 5. 关键产品原则

1. **现实先于系统**：记录真实发生，不要求现实服从预设分类。
2. **行动先于理论**：先给下一步，再提供为何如此的解释。
3. **减法是正式能力**：暂停、跳过、放下和降载都不是失败状态。
4. **一处事实，多种视图**：页面不复制实体，不形成第二套状态。
5. **渐进披露**：首屏不出现用户尚未需要的领域术语。
6. **用户确认**：AI、同步冲突和批量变更不得静默覆盖。

## 6. 删除、合并和降级

| 当前表现 | 裁决 | 原因 |
|---|---|---|
| Home 与 Today 并存 | 合并，登录后进入 Today | 两个首页争夺注意力 |
| Cases 与 Matters 并存 | 统一为 Matters；Cases 仅迁移兼容 | 同义概念造成数据和心智分叉 |
| Capture 与旧收集箱并存 | 统一为 Capture | 两个入口破坏低摩擦承诺 |
| People 为主导航 | 降为 Matter 上下文和“更多” | 首版不做关系系统 |
| Library / Calendar | 降为“更多” | 是检索视图，不是每日核心动作 |
| Graph / 场景切换 / 工具箱 | 默认隐藏，进入实验区 | 与 MVP 无关且理论负担高 |
| 五行 / 十神直接命名 | 默认转为自然语言 | 降低学习门槛和价值解释成本 |

## 7. 成功指标与反指标

### 主要指标

- 首次价值时间：首次 Matter + 第一条 Today 行动的中位时间不超过 3 分钟。
- Capture 保存：P50 不超过 10 秒，P90 不超过 20 秒。
- 7 日闭环率：7 天内至少完成两次 `Today → Record → Review` 的用户比例。
- 调整质量：Review 后修改、降载、暂停或明确下一步的比例。
- 数据信任：离线恢复、导出、重新导入任务成功率。

### 诊断指标

- Capture 从打开到保存的中位步骤数和耗时。
- Today 超过 3 个核心行动的比例。
- 核心业务导航数量，发布时不得超过 4 个。
- 首周触发高级模型、Graph、共享空间的比例；若很低，不应进入主导航。

### 反指标

- 不用“完成数量”“连续天数”“系统内停留时间”作为北极星。
- 不通过更多通知和红色失败状态拉高回访。
- AI 未经确认写入和同步静默覆盖的容忍目标均为 0。

## 8. 仍需验证的产品问题

- 用户更能理解“课题”“事项”还是“Matter”？首版只允许一个主名称。
- Morning Opening 是否必须独立存在，还是 Today 的首次编辑状态？
- Review 的最佳触发是用户主动、Today 收尾，还是温和提醒？
- “承载量”使用三级语言还是自由描述更自然？
- 用户是否真的需要 Cycle/Stage 可视化，还是只需要系统内部保留？

## 9. 沉浸流（Flow）与产品边界补充

本节整合「沉浸流与产品边界」设计。它扩展现有产品能力，但不改变本文件已经确定的核心闭环、四个核心入口和“现实先于系统”的产品裁决。

### 9.1 Calmy 的使用边界

Calmy 是现实行动的入口和出口，不是生活本身、工作过程的替代品，也不是以内容消费为目标的平台。日常使用形成一个轻量循环：

```text
开始：明确意图、选择事项、获取必要上下文
  → 现实行动：离开系统，在真实环境中工作、生活、学习和建立关系
  → 结束：记录真实结果、复盘、沉淀经验并调整后续行动
```

系统可以帮助用户看清方向、减少遗忘、提供必要上下文并保留经验，但不应要求用户持续停留、用系统操作证明完成，或为了维护系统状态而频繁回来。

开始阶段只解决三件事：现在想做什么、为什么做、下一步是什么。内容、资料和提醒只能提供完成动作所需的少量上下文，不能把准备变成持续整理、标签管理或内容浏览。

过程阶段默认发生在 Calmy 之外。Calmy 只在用户主动需要时提供短暂查看、计时、提醒或记录入口，不以在线时长、浏览数量、连续打卡或操作次数定义进展。

结束阶段记录实际结果，允许跳过和稍后补充；用户可以将结果沉淀为 Seed、知识、经验或关联，也可以明确暂时结束、无需继续、转交现实中的下一位行动者。结束不等于填写完整报告。

### 9.2 Flow 的定位与入口

Flow 是内容再生命系统，不是新的内容仓库，也不是无限推荐流。它把用户已经拥有、正在学习、曾经记录或明确选择过的内容，在合适的时机重新送回用户面前，让内容从“存过”变成“再次理解、再次使用、再次行动”。

Flow 不是首版核心闭环的新替代入口，默认作为二级能力从 Today、Matter/Cycle 详情、Review、Library 和“更多”进入；端侧空间允许时可以有独立 Flow 视图，但不得压过 Today、Capture、Matters、Review 的主路径。顶部快速记录入口继续保留，打开 Sheet 后可记录随想、任务、日志、人物记录和行动结束结果。

Flow 的内容优先来自用户自己的资料、事项、学习和生活轨迹。外部内容可以接入，但必须有明确来源、用户意图、可退出路径和现实关联。

### 9.3 Flow 的两层体验

Flow 由两层组成：

- 浏览层（Flow 广场）：Web 可使用有限多列卡片，移动端使用纵向卡片流。它支持一句话、重要句子、竖屏/横屏视频、知识卡、视频引文、人物内容、学习内容、再次遇见内容和事项上下文卡。
- 沉浸层（Focus）：打开单条内容后进入短暂专注视图，展示视频、句子或知识，保留来源、退出、返回原页面和现实行动出口。Web 支持滚轮、方向键和 `J / K`，移动端支持上下切换，但连续切换不能成为唯一操作。

浏览层的目标是发现当前可能有用的一点内容，不是尽可能多地浏览。默认使用有限批次、时间范围或明确结束状态；Focus 中不遮挡退出按钮，不自动播放下一条，不隐藏内容来源。

### 9.4 内容来源与统一 Seed 模型

Flow 统一接入以下来源：本地上传视频、Eagle 中的视频/图片/素材、视频提取的句子/字幕/摘要/时间点片段、系统知识与方法、正在学习的资料、好句/随想/日记/快速记录，以及 Matter、Cycle、Review 沉淀出的 Seed、知识和经验；人物、主题、关系和长期关注方向也可以提供上下文。

所有内容必须保留原始来源和上下文。Flow 负责展示和再激活，不悄悄复制出无法追溯的孤立副本。

视频、句子、知识和资料不分别建立多套 Feed，而统一使用 Seed；Feed 只负责按当前情境挑选 Seed，不拥有内容本身：

```text
Seed
├─ id / type(video|quote|knowledge|image|note|mixed)
├─ source(eagle|local|calmy|video_extract|manual) / sourceRef
├─ title / content / mediaRef / extractedAt
├─ tags / person / topic
├─ matterRef / cycleRef / actionRef / relationRefs
├─ importance / userIntent / learningState
├─ lastSeenAt / seenCount / nextReviewAt
└─ createdAt / updatedAt / status
```

建议状态包括：未整理、已保存、正在学习、已学会、已关联、已行动、暂不需要、已归档。状态帮助系统理解关系，不应变成要求用户逐条维护的管理任务。

### 9.5 四种 Flow 模式

| 模式 | 用途 | 必须具备的边界 |
|---|---|---|
| 漫游 | 低压力地重新遇见已有内容 | 有限条数/时间；可快速再见；到边界后结束 |
| 学习 | 围绕主题、资料或学习目标复习 | 每次一小段；学会/稍后/不再提醒；结束生成现实应用动作 |
| 回响 | 让过去的句子、记录、复盘和 Seed 回到当前语境 | 展示时间、来源和当时关联；支持仍重要/已完成/需更新 |
| 专题 | 围绕 Matter、Cycle、人物、主题或阶段有限浏览 | 明确范围和退出点；只展示专题相关内容；结束给出带走项或下一步 |

学习模式可以展示来源、上下文和下次复习时间，但不以答题数量或连续天数制造压力。回响模式不是怀旧消费，只有与当前情境有关系时才提供行动或关联入口。

### 9.6 Flow 核心动作

| 动作 | 语义 | 系统行为 |
|---|---|---|
| 收下 | 值得保留或再次使用 | 保存为 Seed，稍后可关联或复习 |
| 再见 | 当前不需要，不代表内容错误 | 降低短期出现概率，不要求解释 |
| 学会 | 已理解或掌握 | 更新学习状态，必要时安排轻量复习 |
| 行动 | 应转化为现实动作 | 创建/更新低粒度下一步，并提示离开 Flow |
| 关联 | 与 Matter、Cycle、人物或主题有关 | 建立关系，保留来源和上下文 |
| 展开来源 | 查看原视频、记录、资料或时间点 | 回到来源页面，不生成孤立副本 |
| 退出 | 结束本次会话 | 返回进入前页面或 Today |

“行动”是最高优先级的现实转换出口；“收下”和“学会”不能成为继续消费的理由。

### 9.7 推荐与自然退出

推荐优先使用当前 Matter、Cycle、Review、用户主动主题、重要性、学习状态、复习窗口、现实场景关联度、未理解/未应用状态以及用户的收下/关联/学会/再见反馈。排序规则为：当前意图相关优先；来源清晰且可带来行动的自有内容优先；重要但长期未遇见的内容适度回响；同一内容/类型/主题去重并限频；低置信度推荐降权而不以数量填充。

在线时长、连续浏览条数、点击率、内容消费总量、通知打开率和日活不能成为 Flow 的唯一或核心优化目标。

每次进入 Flow 前显示轻量范围，例如“浏览 5 条”“复习一个主题”或“3 分钟”；到达边界后显示“今天先到这里”“已找到一条可带走的内容”或“回到当前事项”。发生“行动”或“学会”后优先显示现实下一步和退出按钮；连续跳过多条时允许换模式或结束；长时间停留时温和询问是否继续。退出默认回到进入前上下文。

Flow 禁止默认无限滚动、自动播放下一条、全屏遮挡退出、连续奖励、未读红点和焦虑式通知延长停留。

### 9.8 Flow 与现有模块的职责关系

- Today：展示低干扰 Flow 入口，但首屏仍以一条现实主行动为中心。
- Matters：Flow 专题可围绕 Matter，内容必须回到事项的 why、阶段和下一步。
- Cycle：可以围绕当前阶段进入专题模式，但得到必要上下文后要回到现实行动。
- Review：可以把结果沉淀为 Seed，也可以用回响模式带回过去的重要内容。
- Library：继续承担长期存储、检索和关联；Flow 只是资料再激活层。
- 我的：管理 Flow 来源、推荐强度、自动播放、声音、使用边界、通知、隐私、外观和同步偏好。
- Capture：继续原文优先保存；Flow 不改写 Capture 原文。

## 10. 统一产品判断标准补充

新增功能、页面和交互至少应回答以下问题：

| 判断 | 通过标准 |
|---|---|
| 更接近现实行动吗 | 更快明确并执行下一步，而不是增加浏览和整理 |
| 降低认知负担吗 | 默认只展示当前有用内容，深层信息按需展开 |
| 允许退出吗 | 可以保存、跳过、关闭和离开，不被迫完成系统流程 |
| 避免沉迷吗 | 不依赖连续浏览、停留时长、数量或奖励维持使用 |
| 保留现实语境吗 | 内容能回到真实来源、场景、事项和结果 |
| 值得维护吗 | 长期收益明确，维护成本低于行动价值 |

如果设计主要提升系统内停留、系统内完成感或系统内数据量，而不是现实行动和生活质量，应暂缓或拒绝。

## 11. 通用流程与维护纪律

日常开始：

```text
打开 Today → 看见主线与可用精力 → 选择现实事项
→ 可选进入 Flow 获取一条必要内容 → 明确下一步 → 离开系统行动
```

日常结束：

```text
回到 Calmy → 记录结果 → 轻量 Review → 沉淀 Seed/知识/经验
→ 更新后续行动 → 结束并离开
```

Flow 会话：

```text
进入 Flow → 选择漫游/学习/回响/专题 → 设置轻量边界
→ 有限浏览 → 收下/再见/学会/行动/关联
→ 到达边界或主动退出 → 返回进入前上下文
```

内容可先以未整理状态保存；系统可以自动建议关联，但用户可以忽略。归档、合并和去重的目标是降低噪音，不能制造新的维护工作。每次页面或组件变化，至少同步页面职责、默认/空/加载/错误/完成/退出状态、App/Web 映射、数据关联、组件令牌以及对现实行动、自然退出和反沉迷约束的影响。
