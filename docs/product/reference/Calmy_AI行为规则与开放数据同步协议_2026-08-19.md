# Calmy AI 行为规则与开放数据同步协议

> AI 理解层、用户确认、Calmy Open Format 与同步冲突规则。  
> 版本：v0.1 · 日期：2026-08-19 · 关联：[领域模型](Calmy_领域模型与状态机_2026-08-19.md)
>
> 本文件保留 AI、开放格式和同步协议参考；未完成实施项统一见 [`../OPEN_WORK.md`](../OPEN_WORK.md)，不在此处维护独立任务。

## 1. AI 的产品定位

AI 不是一个孤立聊天页，而是通过 Domain Layer 读取上下文的理解能力。它可以提取、连接、比较、总结和提出建议，但持久化的关键改变必须由用户确认。

| 能力 | 可以做 | 不能做 |
|---|---|---|
| Capture 结构化 | 识别 Person、Matter、Action、Record、Resource、Relation | 未经确认直接创建或归档对象 |
| 主要矛盾 | 从历史和当前状态提出候选矛盾 | 把判断当成事实 |
| 最小行动 | 根据承载和 Stage 提出 1–3 个候选 | 自动增加 Today 或无限拆任务 |
| 复盘 | 总结事实、条件、模式、Seed | 把回退和逃避解释成人格缺陷 |
| 冲突识别 | 提醒目标、时间、身体、心理、资源之间的张力 | 替用户强制暂停或删除事项 |
| 开放数据 | 生成 / 解析 Markdown + YAML | 绕过 Repository 直接写页面或文件 |

最高约束：

```text
现实 > 人 > 目标 > 原则 > 流程 > 数据结构
```

## 2. AI 输出的四种状态

| 状态 | 含义 | 是否写入领域数据 |
|---|---|---|
| `observation` | 对已有事实的摘录或引用 | 可写入草稿 Record，标记 `source=ai` |
| `suggestion` | 候选 Matter、Relation、Action、Insight、Seed | 不自动写入 |
| `draft` | 已根据用户意图整理出的待确认内容 | 需用户确认后写入 |
| `confirmed` | 用户明确接受的变更 | 通过 Domain Command 写入并审计 |

任何 AI 回复都应区分：**原始事实、系统推断、用户已确认**。三者不能使用同一种语气。

持久化规则：AI 可以生成 `observation` 和 `suggestion`，但不能直接写入 `trajectory`、`primary_contradiction`、`current_stage`、Matter 状态或删除 Record。必须先展示证据来源，由用户确认后通过 Domain Command 写入。

## 3. 上下文组装规则

1. 先读取当前页面上下文：当前 Matter、Cycle、Today、Action 或 Capture。
2. 再读取必要的短期历史：最近 Record、最近变更、当前状态和未解决 Seed。
3. 只有用户请求长期模式时，才扩大到 Trajectory、长期 Record 和相关 Matter。
4. 默认过滤不相关的 Person、共享空间内容和敏感字段；跨域读取必须有明确理由。
5. 每个上下文片段标记 `source_id`、`occurred_at`、`scope` 和 `confidence`。
6. 如果事实不足，AI 必须说明信息不足，并提出一个澄清问题，而不是补全事实。

## 4. 推荐输出契约

```json
{
  "kind": "suggestion",
  "summary": "当前主要矛盾可能是……",
  "evidence": ["rec_01", "rec_07"],
  "confidence": 0.78,
  "asserted_by": "ai",
  "proposals": [
    {
      "type": "action",
      "title": "……",
      "matter_id": "mat_01",
      "confidence": 0.78
    }
  ],
  "risk_flags": ["当前承载量与计划量可能冲突"],
  "requires_confirmation": true
}
```

UI 不应直接解析自然语言后写库；统一由 Domain Command 校验对象、权限、状态和版本。

## 5. AI 语言与心理安全

- 使用“记录显示 / 可能 / 候选 / 可以考虑”，避免“你就是 / 你应该 / 你失败了”。
- 不把娱乐、停顿、回退自动标为浪费；先区分主动恢复、有意识娱乐、无意识消耗和逃避。
- 不把 Practice 未完成直接等同于意志力不足；先检查睡眠、承载、资源、环境和主要矛盾。
- 涉及身体或心理风险时，表达为提醒与建议寻求专业帮助，不做诊断。
- 用户可以关闭建议、删除草稿、修改分类和拒绝长期记忆。
- AI 产生的 Insight / Seed 必须能回到来源 Record / Cycle；不能凭空生成“关于用户的真相”。
- 对用户状态的判断必须带 `evidence_ids`、`confidence`、`asserted_by` 和 `confirmed_by`。

## 6. Calmy Open Format

目标是可读、可迁移、可重新导入：Markdown 是正文，YAML Frontmatter 是稳定属性，附件使用普通文件，Relation 使用 Stable ID。

```yaml
---
calmy_id: mat_java_01
calmy_type: matter
b_version: 1
title: 学习 Java
status: active
owner_id: person_me
current_cycle_id: cyc_java_05
trajectory: recovering
revision: 7
created_at: 2026-06-20T10:30:00+08:00
updated_at: 2026-08-19T10:42:00+08:00
---
# 学习 Java

当前主要矛盾：能够理解代码，但独立设计完整业务结构的能力不足。
```

### 6.1 格式约束

- `calmy_id` 不变；文件名、标题、目录都可变。
- Frontmatter 尽量扁平；复杂关系使用独立实体和 ID。
- 正文保留人类可读内容，不能只导出数据库字段。
- 附件使用普通文件；索引、缓存、图数据应可重建。
- 每个实体必须带 `calmy_type` 和 `b_version`。

## 7. 同步三阶段

| 阶段 | 范围 | 必须解决 |
|---|---|---|
| 1. 导入 / 导出 | Calmy ↔ 文件夹 / 压缩包，无插件 | Stable ID、基础字段、关系恢复、附件路径 |
| 2. 增量同步 | `revision`、`hash`、`manifest`、`updated_at` | 只处理变化文件，发现删除与移动 |
| 3. 双向同步 | Calmy ↔ Markdown / Obsidian | 字段级冲突、文本差异、合并、权限与历史 |

第一阶段的目标是“数据能带走、能回来”，不是模拟实时同步。

### 7.1 Manifest 最小字段

```json
{
  "format_version": 1,
  "generated_at": "2026-08-19T10:42:00+08:00",
  "entities": [
    {
      "calmy_id": "mat_java_01",
      "path": "20 Matters/学习 Java.md",
      "hash": "sha256:…",
      "revision": 7,
      "last_synced_at": "2026-08-19T10:42:00+08:00"
    }
  ]
}
```

## 8. 冲突规则

| 场景 | 处理 | 用户看到什么 |
|---|---|---|
| 同一字段两侧修改 | 不采用最后写入者覆盖；保留两版值 | 当前值、另一侧值、时间、来源 |
| 长文本冲突 | 生成差异视图，允许手动合并 | 原文 A / 原文 B / 合并结果 |
| 文件移动或改名 | 凭 `calmy_id` 视为同一对象 | 路径变化记录为同步事件 |
| 文件被删除 | 先标记 `pending_deletion`，不立即删除领域对象 | 确认删除 / 恢复 / 忽略 |
| 多人共享冲突 | 增加 actor、scope、权限和共享范围 | 谁改了什么、谁有权确认 |

> 禁止事项：任何同步适配器不得静默覆盖用户修改；同步历史本身属于真实历史。

## 9. 权限与审计

- Domain Layer 是 AI 与同步写入的唯一入口；页面、AI、Adapter 都不能直接改数据库。
- AI 确认写入记录 `command_id`、`actor=ai_assisted`、`confirmed_by`、`source_ids` 和 before / after 摘要。
- 共享空间未来需要区分 `owner`、`editor`、`viewer`，并限制跨 Person 的隐私字段读取。
- 用户可以导出全部核心数据与审计信息；缓存、索引、图数据都可以重建。
- 敏感字段默认最小化进入模型上下文；不把整库作为默认 prompt。

### 9.1 关系与共享空间的额外限制

在 Relationship / Shared Space 尚未完成权限模型前，AI 只能处理当前用户明确授权的上下文：

- 不代表他人表达意图，不替他人创建或修改 Action。
- 不把私人 Record 自动带入共享空间。
- 不根据聊天内容推断他人的心理状态、忠诚度或关系结论。
- 共享建议必须标明可见范围、涉及的 Person 和建议接收者。
- 任何跨人读取都要携带 `scope` 和授权来源；缺少授权时宁可不回答。

## 10. 存储与适配器边界

```text
Calmy UI
   ↓
Domain Model / Commands
   ↓
Repository API
   ├─ IndexedDB Adapter
   ├─ D1 / Sync Adapter
   └─ Markdown Adapter ↔ Open Workspace
```

- IndexedDB：本地长期实体、Record、Inbox 和 mutation log。
- `localStorage`：主题、最近 View、轻量 UI 偏好，不保存长期事实。
- D1：同步镜像、远程访问和未来共享边界。
- Markdown Adapter：领域对象 ↔ Markdown + YAML + Assets。

MVP 期间，D1、Markdown 和 AI 都不是事实源。它们通过 Repository API 读取 IndexedDB 的当前投影，并通过 Domain Command 请求变更。

## 11. 上线门槛

- [ ] AI 所有持久化建议都可预览、拒绝、修改、确认；无隐藏写入。
- [ ] 每个建议都能回到源 Record / Matter / Cycle。
- [ ] 导出文件脱离 Calmy 仍可阅读，重新导入不丢核心关系。
- [ ] 构造两侧同时修改的测试，系统不静默覆盖。
- [ ] 断网时 Capture、Today、Record 可用，恢复网络后不丢数据。
- [ ] 负向记录、心理状态和停顿场景通过人工审阅与回归用例。
