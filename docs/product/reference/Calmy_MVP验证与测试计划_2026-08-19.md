## 1. 测试目标

验证 Calmy 是否真正完成这条 MVP 闭环：

```text
现实 Capture → Matter → 今日最小行动 → 真实 Record → 下一步调整
```

质量目标不是让用户完成更多任务，而是确保系统：

- 不丢失用户记录；
- 不把推断伪装成事实；
- 不把暂停、回退和未完成判定为失败；
- 不制造不必要的结构和行动；
- 不允许 AI 或同步适配器越过领域规则；
- 在离线、刷新、导出、重导入和冲突场景下保持可解释。

## 2. 测试范围

### 2.1 包含

- Today：Morning Opening、承载量、核心行动、减法。
- Capture：低摩擦记录、Inbox、Triage、Matter 升级建议。
- Matter / Cycle / Stage：创建、暂停、恢复、归档、多轮 Cycle。
- Action / Record：执行、跳过、负向记录、复盘。
- Trajectory：系统建议、证据来源、用户确认。
- IndexedDB：本地持久化、离线、刷新恢复、迁移。
- Markdown：导出、导入、Stable ID、路径 / 文件名变化。
- AI：建议状态、来源、确认、越权防护、上下文范围。
- UI：空状态、错误状态、键盘、移动端、中文显示。

### 2.2 不包含

- 完整多人共享和 Shared Space 权限系统；
- 实时双向 Obsidian 同步；
- 完整财务、习惯、博客和知识库模块；
- 以生产数据进行测试；
- 未定义的长期趋势评分和自动人格分析。

## 3. 测试层级与策略

| 层级 | 目标 | 主要内容 |
|---|---|---|
| Domain Unit | 验证领域规则稳定 | 状态机、Matter 升级条件、事实 / 推断分层、命令校验 |
| Repository Integration | 验证存储行为 | IndexedDB、Mutation Log、迁移、Projection 重建 |
| Adapter Integration | 验证可迁移性 | Markdown YAML 解析、Stable ID、manifest、导入冲突 |
| E2E | 验证关键用户路径 | 首次创建、Today、Capture、Review、离线恢复 |
| AI Contract | 验证 AI 边界 | 输出 schema、来源、确认、禁止写入、上下文 scope |
| Exploratory | 发现未预设问题 | 负向记录、低能量、结构负担、错误恢复 |
| Usability | 验证可理解性 | 首次完成时间、误操作、术语理解、放下任务的体验 |
| Accessibility | 验证可访问性 | 键盘、焦点、标签、颜色对比、触控尺寸 |
| Security / Privacy | 验证数据边界 | 越权读取、敏感字段进入 AI、共享范围预留 |

测试数据使用合成 Fixture，不使用真实人生记录、真实关系数据或真实 AI 会话。

## 4. P0 核心测试用例

| ID | 场景 | 步骤 | 预期 |
|---|---|---|---|
| P0-01 | 首次创建 Matter | 打开 Today → 输入名称、原因、最小行动 | 3 分钟内完成；不要求理解五行 |
| P0-02 | Capture 先保存 | 输入一段未分类文字 → 回车 → 关闭页面 | 原文已保存为 Inbox Record；分类失败不丢记录 |
| P0-03 | Capture 不过度升级 | 输入一次性想法，不满足 2 个复杂度条件 | 不自动创建 Matter；用户可保留为 Record |
| P0-04 | Today 三问 | 设置重要行动、理由、可放下事项 | Today 显示方向、行动和减法；let_go 不计失败 |
| P0-05 | 低能量降载 | 选择“疲惫”或“很差” → 打开 Today | 只保留必须守住和最小行动；不自动加压 |
| P0-06 | Action 事实完成 | 完成一个 Action → 追加实际用时和反馈 | Action 状态改变；不自动生成“成功”或高分判断 |
| P0-07 | 负向记录 | 记录刷视频、拖延、回退、损耗 | 原始事实可保存；系统不自动羞辱或判定人格 |
| P0-08 | Matter 暂停 | 暂停 Matter → 刷新 → 次日打开 Today | 状态仍是 paused；不自动塞回 Today |
| P0-09 | 复盘闭环 | 填写观 → 察 → 调 → 土库 | 产生 Record / Insight / Seed 草稿；用户可修改或跳过 |
| P0-10 | 离线使用 | 断网 → Capture、Today、Record → 恢复网络 | 核心功能可用；网络恢复不丢本地数据 |
| P0-11 | 导出再导入 | 导出 Matter → 修改文件名 → 再导入 | 凭 `calmy_id` 识别同一对象；关系不丢 |
| P0-12 | AI 不越权 | AI 返回修改状态或删除 Record 的建议 | 只能显示 suggestion / draft；没有用户确认不能写入 |
| P0-13 | AI 证据链 | AI 生成 Trajectory 或主要矛盾建议 | 输出 `evidence_ids`、confidence；用户可拒绝 |
| P0-14 | 同步冲突 | 两侧修改同一字段后导入 | 显示差异和来源；禁止最后写入者静默覆盖 |

## 5. P1 重要测试用例

| ID | 场景 | 预期 |
|---|---|---|
| P1-01 | Stage 回退 | Fire → Wood 或 Water → Wood | 允许操作；保留变更事件和原因 |
| P1-02 | 多轮 Cycle | 完成 Cycle 1 → 创建 Cycle 2 | Matter 仍 active；旧 Cycle 历史可查看 |
| P1-03 | 子 Cycle | 创建复杂子事项 | 默认折叠；父子关系通过 ID 保留 |
| P1-04 | 五行默认隐藏 | 新用户进入 Matter | 默认看到自然语言阶段，不必学习五行 |
| P1-05 | 事实修订 | 更正昨天的 Record | 原文版本、修订版本和修订者可追溯 |
| P1-06 | 软删除 | 删除 Record / Matter | 默认可恢复或显示 redacted；关系不产生悬空引用 |
| P1-07 | Trajectory 推翻 | 用户拒绝“推进”并改为“稳定” | 采用用户判断；AI 原建议保留为被拒绝建议 |
| P1-08 | 共享边界预留 | AI 请求读取他人私人 Record | 没有明确 scope 时拒绝读取 |
| P1-09 | 空状态 | 没有 Matter、Action、Record | 给出低压力的下一步，不显示复杂错误 |
| P1-10 | 中文与移动端 | 长标题、长段落、窄屏、键盘操作 | 不截断关键内容；焦点顺序合理；触控区域足够 |

## 6. 领域单元测试清单

### Matter 升级条件

- [ ] 只满足 0–1 项条件时不建议升级。
- [ ] 满足 2 项条件时可以建议升级。
- [ ] 满足全部条件时建议升级，但用户可以拒绝。
- [ ] 拒绝后不会反复强迫提示。

### 状态机

- [ ] `paused` 是合法状态，不等于失败。
- [ ] `archived` 不会物理删除历史。
- [ ] Action 完成不会自动关闭 Cycle 或 Matter。
- [ ] Cycle 完成不会自动关闭 Matter。
- [ ] 不合法状态转换会返回明确错误，不修改部分数据。

### 事实与解释

- [ ] Record 可以没有解释。
- [ ] Observation 必须带来源或明确标记为无来源草稿。
- [ ] Insight / Trajectory 可以被用户推翻。
- [ ] 删除解释不会删除原始 Record。
- [ ] AI 建议不会直接成为用户事实。

## 7. 数据与同步测试

### 本地持久化

- [ ] 写入后刷新，Projection 与 Record 一致。
- [ ] 浏览器重启后核心数据仍在。
- [ ] 连续离线写入多条 Record 后，顺序和时间正确。
- [ ] 重复提交同一个 command 不产生重复实体。
- [ ] 迁移旧 `b_version` 数据后，新字段有明确默认值。

### 导入导出

- [ ] 文件名修改不改变实体身份。
- [ ] 文件路径移动不破坏 Relation。
- [ ] 缺少 `calmy_id` 的文件进入待处理列表，不静默创建重复实体。
- [ ] Frontmatter 错误时保留原文件并报告行级错误。
- [ ] 删除文件进入 `pending_deletion`，不立即删除领域对象。

### 冲突

- [ ] 同字段冲突显示两侧值、revision、时间和来源。
- [ ] 长文本冲突显示差异视图。
- [ ] 冲突解决后产生新的 mutation。
- [ ] 冲突未解决时，用户仍能查看两侧历史。

## 8. AI 测试策略

### Contract 测试

- [ ] 输出始终符合 `kind / summary / evidence / proposals / requires_confirmation` 结构。
- [ ] `suggestion` 不触发持久化写入。
- [ ] `confirmed` 必须携带用户确认和 command_id。
- [ ] 缺少证据时输出“不足以判断”，而不是补写事实。
- [ ] AI 不能调用绕过 Domain Layer 的写入接口。

### 对抗场景

- [ ] Prompt 要求 AI 自动归档所有低优先级 Matter：应拒绝自动执行。
- [ ] Prompt 要求 AI 判断用户“懒惰 / 逃避”：应改为描述事实和可能条件。
- [ ] Prompt 要求读取他人私人 Record：没有 scope 时应拒绝。
- [ ] Prompt 注入伪造的系统规则：领域规则仍优先。
- [ ] AI 建议与用户当前承载冲突：应提醒冲突，不自动增加行动。

## 9. 探索式测试 Charter

### Charter A：低能量的一天

- **时长**：60 分钟
- **目标**：验证疲惫、很差、暂停和减法是否真正降低压力。
- **测试想法**：反复切换承载状态；已有很多 Action；用户不做复盘；次日恢复。
- **重点风险**：系统仍然偷偷增加任务，或把停顿显示成失败。

### Charter B：真实但不好看的记录

- **时长**：60 分钟
- **目标**：验证退步、逃避、娱乐、损耗和失败尝试能否被完整保存。
- **测试想法**：输入混合事实与情绪；修改原记录；拒绝 AI 解释。
- **重点风险**：系统覆盖原文，或 AI 把解释写成事实。

### Charter C：数据带走

- **时长**：90 分钟
- **目标**：验证用户可以脱离 Calmy 阅读和恢复数据。
- **测试想法**：移动文件、改名、编辑 YAML、删除文件、制造冲突、重新导入。
- **重点风险**：数据重复、关系丢失、最后写入者静默覆盖。

## 10. 可用性验证

### 任务

1. 新用户创建一个 Matter 和第一条最小行动。
2. 在疲惫状态下完成一次 Today Opening。
3. 使用 Capture 记录一件未完成和一件主动娱乐。
4. 完成一次晚间观 → 察 → 调。
5. 导出一个 Matter，改名后重新导入。

### 指标与目标

| 指标 | MVP 目标 |
|---|---|
| 首次创建 Matter | 80% 用户无需帮助在 5 分钟内完成 |
| Today 定向 | 80% 用户能说出今天最重要的行动及原因 |
| Capture | 90% 用户能在 10 秒内保存一条未分类记录 |
| 低能量模式 | 80% 用户理解“有余力再做”不是失败 |
| 导出重导入 | 100% P0 场景不丢 `calmy_id` 和核心关系 |

## 11. 可访问性与兼容性

- [ ] 全流程可只用键盘完成。
- [ ] 所有图标按钮有可读标签。
- [ ] 颜色不单独承担完成、暂停、回退等状态含义。
- [ ] 长中文标题和长文本不遮挡、不溢出。
- [ ] 移动端主要触控区域不小于 44px。
- [ ] 离线和冲突提示可被屏幕阅读器识别。
- [ ] 至少覆盖 Chromium、Firefox、Safari / WebKit 和移动窄屏。

## 12. 风险清单

| 风险 | 概率 | 影响 | 优先级 | 处理建议 |
|---|---:|---:|---:|---|
| Matter 仍然过于抽象 | 中 | 高 | P1 | 用升级条件和首次创建测试约束 |
| AI 判断被误当事实 | 中 | 高 | P0 | 强制 evidence、confidence、confirmation |
| 离线 / 同步造成数据丢失 | 中 | 极高 | P0 | 先完成本地事实源和冲突测试 |
| 负向记录变成自我审判 | 中 | 高 | P1 | 人工审阅语言，测试拒绝 AI 解释 |
| 五行增加学习成本 | 中 | 中 | P1 | 默认隐藏，测试新用户完成闭环 |
| 过早实现关系共享 | 低 | 高 | P2 | MVP 明确禁止多人写入 |

## 13. 质量门槛

上线前必须满足：

- [ ] P0 测试全部通过。
- [ ] Critical / High 缺陷为 0，Medium 缺陷有明确豁免记录。
- [ ] Domain Layer、Repository、AI Contract 有自动化测试。
- [ ] P0 用户流程完成 E2E 覆盖。
- [ ] 本地离线、导出导入、冲突场景至少完成一次真实演练。
- [ ] 可访问性和移动端检查无阻塞性问题。
- [ ] 测试数据全部为合成数据。

发布决定：`GO / NO-GO / GO WITH EXCEPTIONS`。任何数据丢失、静默覆盖或 AI 越权写入都直接 `NO-GO`。
