# Calmy 领域模型与状态机

> Entity、Relation、生命周期与存储映射。  
> 版本：v0.1 · 日期：2026-08-19 · 关联文档：[MVP 产品范围与不做清单](Calmy_MVP产品范围与不做清单_2026-08-19.md)
>
> 本文件保留领域语义和状态验收参考；未完成实施项统一见 [`../OPEN_WORK.md`](../OPEN_WORK.md)，不在此处维护独立任务。

## 1. 领域主骨架

```text
Person → Matter → Cycle → Stage → Action → Record
                     ↘ Resource / Relation / Insight / Seed / Trajectory
```

这条链表示一个人面对现实事项，在一轮迭代的某个阶段采取行动并产生事实记录。它不是唯一关系，也不是必须在 UI 中按链条逐层操作。

## 2. 实体定义

| 实体 | 职责 | 边界 |
|---|---|---|
| `Person` | 现实中的人及其上下文入口 | 不是所有内容都必须挂到某个人；自己是默认 Person |
| `Matter` | 需要被理解、推进、承载或复盘的现实事项 | 不是一句目标，也不是一张任务卡 |
| `Cycle` | 围绕 Matter 的一次阶段性迭代 | 完成 Cycle 不等于 Matter 永久完成 |
| `Stage` | Cycle 当前所处的过程语义 | 五行是过程模型，不是必须展示的玄学标签 |
| `Action` | 可以执行的动作 | 动作属于现实上下文，不能成为孤立清单 |
| `Record` | 已发生的事实、反馈、状态和认识 | 默认追加；更正要保留来源 |
| `Resource` | 时间、精力、钱、代码、资料等资源 | MVP 可先作为 Record 属性 |
| `Relation` | 实体之间的机器可追踪连接 | 机器使用 ID；人类阅读可另外显示双链 |
| `Insight` | 经实践形成的认识 | 必须可追溯到来源 Record 或 Cycle |
| `Seed` | 下一轮或下一阶段的起点 | 不是自动任务，需用户确认采纳 |
| `Trajectory` | 变化方向 | 是解释层，不能替代原始记录 |

## 3. 事实、推断、判断与行动分层

这是领域模型的核心约束。系统不能把用户的一次解释永久写成事实。

| 层级 | 例子 | 允许谁产生 | 是否可被推翻 |
|---|---|---|---|
| 事实 `Record` | 昨晚学习 40 分钟，刷视频 1 小时 | 用户、导入、设备 | 可更正，但保留原始版本 |
| 推断 `Observation` | 睡眠不足可能影响学习 | AI / 系统 | 必须保留来源和置信度 |
| 判断 `Insight / Trajectory` | 当前处于恢复期；晚间不适合长时间学习 | 用户确认或用户主动创建 | 可以被后续实践推翻 |
| 行动 `Action` | 明天只安排 45 分钟 Java | 用户确认；AI 只能提议 | 可取消、延期、重写 |

建议字段：

```yaml
evidence_ids:
  - rec_20260818_01
confidence: 0.72
asserted_by: ai
confirmed_by: person_me
reviewed_at: 2026-08-19T22:10:00+08:00
```

`Trajectory` 不应一开始完全自动计算。推荐流程是：

```text
原始 Record → 系统提出趋势候选 → 用户确认 / 修改 → Trajectory
```

## 4. 聚合边界

MVP 以 `Matter` 作为主要聚合根。Matter 负责当前 Cycle 引用、状态和主要矛盾；Cycle、Stage、Action、Record 通过 ID 关联，但不应在 UI 中被复制成多套事实。

| 聚合 | 包含 / 引用 | 修改规则 |
|---|---|---|
| Person Context | Person、关系摘要、关联 Matter | 可聚合查看；不持有 Matter 全部内容 |
| Matter | title、why、status、trajectory、current_cycle_id | 状态变更必须产生 mutation |
| Cycle | theme、stage、status、parent_cycle_id | 完成本轮不自动关闭 Matter |
| Today | date、load、focus_action_ids、must_protect、let_go | 每天一条可修订记录；不复制 Action |
| Record Log | 事实、反馈、复盘、负向变化、来源 | 以追加为主；删除默认转为撤销 / redacted |

## 5. Stable ID 与版本字段

| 字段 | 规则 | 示例 |
|---|---|---|
| `calmy_id` | 创建后不可变；不依赖标题、文件名和路径 | `mat_01K8H32` |
| `calmy_type` | 决定解析器与领域对象类型 | `matter / cycle / action / record` |
| `b_version` | 对象结构版本，用于迁移 | `1` |
| `revision` | 实体被修改的单调版本号 | `7` |
| `created_at` / `updated_at` | ISO 8601，保存时区 | `2026-08-19T10:30:00+08:00` |
| `source` | 变更来源 | `user / ai / import / sync` |
| `deleted_at` | 软删除或撤销时间 | `null` |

身份原则：**ID 是身份；文件名、标题和路径只是展示。**

## 6. 状态机

### 5.1 Matter

```text
draft → active → paused → active
active → archived
paused → archived
archived → restored → paused
```

- `draft`：允许补齐 why、主要矛盾和第一轮 Cycle。
- `paused`：合法状态；可以记录原因，也可以只记录事实。
- `archived`：不是删除；仍可搜索、导出和恢复。

### 5.2 Cycle

```text
planned → active → paused → active
active → completed
active / paused → abandoned
completed / abandoned → reopened  # 需要显式操作
```

### 5.3 Action

```text
planned → in_progress → done
planned → skipped
planned / in_progress → cancelled
skipped / cancelled → reopened  # 保留原状态事件
```

### 5.4 Stage

默认推荐顺序是 `Wood → Fire → Earth → Metal → Water`，但顺序不是硬约束。Stage 可以暂停、回退、跳转或重开。

| Stage | 核心问题 | 典型产出 |
|---|---|---|
| Wood | 真正要处理什么？ | 问题定义、方向、Seed、范围 |
| Fire | 现在怎么实践？ | 行动、尝试、代码、事件 |
| Earth | 如何承载成结构？ | 稳定产物、组织、环境、资源 |
| Metal | 什么该留、该删、该改？ | 标准、判断、校验、取舍 |
| Water | 现实告诉了我什么？ | Insight、经验、下一轮 Seed |

## 7. 领域不变量

1. 任何 `Action` 必须能追溯到至少一个 `Matter`；没有上下文的 Capture 只能处于 Inbox。
2. 任何 `Cycle` 必须属于一个 `Matter`；子 Cycle 通过 `parent_cycle_id` 连接，不依赖文件夹。
3. `Matter.current_cycle_id` 只能指向该 Matter 的 Cycle。
4. `Record.occurred_at` 与 `created_at` 分开；现实发生时间不能被录入时间覆盖。
5. 完成 Action 不自动生成“成功”结论；最多生成一个事实事件。
6. AI 不能直接改变 `status`、`trajectory`、`current_stage` 或删除 Record；必须经过用户确认。
7. 任何同步覆盖必须携带 `revision`、`source`、`conflict` 信息；禁止静默覆盖。

## 8. 示例对象

```yaml
calmy_id: mat_java_01
calmy_type: matter
b_version: 1
title: 学习 Java
status: active
current_cycle_id: cyc_java_05
trajectory: recovering
primary_contradiction: 能理解代码但缺少独立设计完整业务结构的能力
revision: 7
```

```yaml
calmy_id: act_20260819_jwt
calmy_type: action
matter_id: mat_java_01
cycle_id: cyc_java_05
title: 完成 JwtService 的最小实现并跑通测试
status: planned
```

## 9. 关系表达

机器层使用稳定 ID：

```yaml
matter_id: mat_java_01
parent_cycle_id: cyc_java_05
source_record_ids:
  - rec_20260818_01
```

人类阅读层可以显示 Markdown 双链：

```markdown
Matter → [[学习 Java]]
当前 Cycle → [[Cycle 05 - 独立项目能力]]
```

Calmy 以 ID 为准；双链只是可读视图。

## 10. 存储映射

| 层 | MVP 职责 | 长期职责 |
|---|---|---|
| IndexedDB | 本地实体、Record、Inbox、mutation log | 本地优先主存储与离线读取 |
| localStorage | 主题、最近 View、轻量偏好 | 不保存长期实体和同步事实 |
| D1 / SQLite | 登录后的同步镜像与共享预留 | 远程访问、同步、多人数据边界 |
| Markdown Adapter | 导入 / 导出对象与关系 | Calmy Open Format、Obsidian、其他工具 |
| Domain Layer | 统一校验、命令、事件和迁移 | 屏蔽 UI 与存储差异 |

页面、AI、同步 Adapter 都不能绕过 Domain Layer 直接写数据库。

## 11.1 MVP 的事实源与事件历史

第一版采用单一本地主事实源，避免同时维护多个“主数据库”：

```text
IndexedDB = 本地事实源
Domain Command = 唯一写入入口
Current Projection = 当前可快速读取的状态
Mutation Log = 对象变更历史
Markdown = 可迁移镜像 / 外部工作区
D1 = 后续同步镜像
```

需要区分两种历史：

| 类型 | 含义 | 示例 |
|---|---|---|
| Reality Record | 现实中发生了什么 | 昨晚学习 40 分钟；今天状态疲惫 |
| Domain Mutation | 系统对象如何被修改 | Matter 从 active 变为 paused |

两者不能互相替代。Reality Record 描述生活，Mutation Log 描述系统变化。

### 删除与更正

- Record 默认追加，不直接覆盖原文。
- 用户更正事实时，保留原始版本、修订版本和修订原因。
- 删除默认是软删除或 `redacted`，除非用户明确要求物理删除。
- 删除对象后，关系和历史事件仍应保留可解释的引用。
- Projection 可以重建；Record 和 Mutation Log 不能依赖 Projection 才存在。

## 12. 命令与事件建议

推荐以命令进入领域层，以事件保存历史：

```text
CreateMatter → MatterCreated
PauseMatter → MatterPaused
CreateAction → ActionCreated
CompleteAction → ActionCompleted
RecordReality → RecordCreated
ConfirmAiSuggestion → SuggestionConfirmed + DomainMutation
ImportMarkdown → ImportApplied / ImportConflictDetected
```

事件不是为了制造复杂架构，而是为了回答：什么时候、由谁、基于什么，把对象改成了现在的状态。

## 13. 工程验收清单

- [ ] Matter 可创建、更新、暂停、恢复、归档，并产生 mutation。
- [ ] 一个 Matter 可以拥有多个 Cycle，每轮有主题和结果。
- [ ] Today、Matter、Search 查看的是同一 Action / Record，而不是复制品。
- [ ] 刷新、离线后数据可恢复；迁移旧版本不会丢字段。
- [ ] 文件移动或重命名后，重新导入仍凭 `calmy_id` 恢复关系。
- [ ] 同步冲突显示差异，不使用最后写入者覆盖全部内容。
