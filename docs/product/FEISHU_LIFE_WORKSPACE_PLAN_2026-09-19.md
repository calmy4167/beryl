# Calmy 飞书生活工作台规划

> 日期：2026-09-19 · 状态：规划提案，对应 D-014（proposed）
>
> 本文回应用户对系统繁琐、重复维护及未来扩展的反馈。它定义下一阶段建议，不代表今天、项目、回顾已完成飞书化。当前实现、授权和部署以[飞书接入协议](reference/Calmy_Feishu_数据适配与授权协议_2026-09-19.md)为准；既有稳定裁决继续有效。

## 1. 定位与取舍

将 Calmy 收敛为飞书数据的个人生活工作台：飞书保存项目、任务与周报；Calmy 帮用户选出今天值得做的事、快速操作、查看进展与调整下一步。

日常收益应来自少录入、少寻找、少切换。完整理念保留在设计文档，用户操作默认使用“项目、任务、记录、下一步”等自然语言。每项日常功能都应允许用户不分类、不设置日期、不填写目标或不复盘。

首个试点是用户自己已有的 Base，先验证个人使用，再开放多人。默认体验暂不扩展到独立财务、健康、习惯、知识图谱、完整 Cycle 或 AI 人生规划。

## 2. 已实现与仍存在的差距

已实现：Worker 侧应用身份适配、四张表读取、任务新增与状态更新接口、四类工作台视图、自动分页、接口错误反馈。

已验证：四张真实表可读取，生产构建与 Worker 打包通过，6 项本地接口测试通过。真实新增、状态写回和线上授权读取仍需部署后验证；部署由用户完成。

目前已增加可显式选择的飞书工作区来源：Today、Capture、Matters 和事项看板可以读取同一 Base；Capture 在飞书模式下创建任务，Today 只保存任务 record ID 引用，事项看板共享任务状态。任务工作台增加看板 / 表格切换、拖拽换状态和右侧原记录详情。拖拽写回得到飞书确认后立即更新当前卡片，完整数据在后台刷新；后续继续减少重复读取 schema 和无关数据。Review 和旧工具模块仍沿用本地领域数据。活跃页面每 15 秒检查更新，字段按工作区记录字段 ID 绑定，状态选项来自 schema；线上 Worker 与 Pages 仍需用户部署后验收，暂不承诺秒级事件推送或离线写回。

当前应用使用 HashRouter：逻辑路由为 `/app/feishu`，网页访问形式为 `/#/app/feishu`。

## 3. 建议的默认界面

飞书模式建议使用三个主入口与一个全局“新建”按钮。该建议在完成验收并确认采用前，不替换既有四入口导航。

| 入口 | 用户要解决的问题 | 默认展示 |
| --- | --- | --- |
| 今天 | 现在准备做什么？ | 自己选出的 1 个主任务、最多 2 个备选；临近截止和逾期任务按需展开 |
| 项目 | 哪些事情正在推进？ | 项目目的、当前状态、下一项行动；项目内可切换任务列表和看板 |
| 回顾 | 有什么变化，下一步怎么办？ | 本周完成、停滞或待重新判断的事情；已有周报与一段可选进度记录 |
| 全局新建 | 快速记下一项行动 | 仅标题必填；项目、执行人、优先级和日期按需展开 |

表格用于集中编辑，看板用于查看状态，今天用于做选择。三种视图读写同一条飞书记录。点击卡片打开详情侧栏，默认只显示标题、状态、项目、执行人、日期及已有内容；新增字段进入可展开的“更多字段”。

成员、连接配置、旧模块、AI、统计及高级字段设置放在“更多”或上下文入口。任务与项目的状态选项从飞书 schema 读取；界面不得因为增加了状态而隐藏对应记录。

## 4. 日常操作与生活使用建议

一个合适的日常过程是：打开今天 → 选一件事 → 去做 → 改状态或留一句进度 → 离开。回顾由用户主动打开，无需完成整套流程才能保存。

- 今天选择是个人关注安排，不能通过改任务截止日期来冒充；没有日期的任务也可以进入今天。
- 截止日期只用于真实期限。未填写日期、优先级或项目的任务应正常保存与展示。
- 项目用于需要多次行动的事情。短小行动直接作为任务，不强制每个问题建立项目。
- 宽泛主题可以保留，但最好补一个近期可验证的变化。例如“英语”当前关注“完成一次英文自我介绍”，下一步是“录一段一分钟自我介绍”。
- 新想法、参考信息和真实行动的去向应由用户选择。首版“新建”明确创建任务；通用随手记需另行确认已有表或新增收集箱表，不应自动把所有想法变成待办，也不能把它们随意塞进“解决方案”。
- 回顾可以只写一句“发生了什么”。需要调整时再补“卡在哪里、下一步是什么”，避免强制长篇周报。
- 完成度仅作为概况。任务勾选数量不直接等于现实问题被解决；暂停或不再继续也可以是合理选择。

## 5. 数据归属与连接方式

| 数据 | 建议归属 | 规则 |
| --- | --- | --- |
| 项目、任务、执行人、状态、日期、周报 | 飞书 | 按飞书 record_id 读写，复用现有表与公式，不复制成第二套可编辑任务 |
| 今日选中记录、卡片布局、字段显示、个人筛选 | Calmy 个人设置 | 保存工作区、用户、日期及记录 ID；跨设备需求出现后再增加服务端持久化 |
| 今日列表、周概况、项目摘要 | 派生视图 | 从当前记录计算；不得独立保存一份可修改的完成度 |
| 飞书记录快照 | IndexedDB 缓存 | 标明更新时间；离线先只读，可保留清楚标识的本机草稿 |
| 原有本地项目与任务 | 现有本地工作区 | 保持独立；需要迁移时先预览、核对关系、记录映射，再切换来源 |

每个工作区明确绑定一个主来源。飞书工作区通过 Workspace/Provider 边界进入应用用例；今天、项目和回顾共同使用该来源。缓存不参与原有 `b_tasks` 业务同步，不把同一任务同时作为本地实体和飞书实体编辑。

连接配置应能独立使用，避免用户为了访问飞书被要求切换整套本地备份或云同步模式。界面显示“连接正常、上次更新、保存中、已保存到飞书、未保存”等可理解状态。

写入需要网络确认。结果未知时不得盲目重复创建，避免网络超时后出现重复任务；应保留操作状态并提供核对与恢复路径。首版不承诺完整离线写入队列。

## 6. 降低飞书表变更成本

下一阶段建立可配置字段映射：连接一个 Base 后列出表和字段，让用户选择“任务标题、状态、项目关系、日期、执行人”等逻辑角色，而不是把每种表结构写成页面代码。

映射保存 table_id 与 field_id，并通过 schema 获取当前显示名称和类型，供读取与写入使用。字段改名但 ID 未变时保持映射；新增字段默认不展示；删除或类型变化只提示受影响字段并阻止不兼容写入。具体 API 请求格式按官方接口验证，不假定所有接口均直接接受字段 ID。

同时补齐关联记录名称、人员显示、日期、公式数值和百分比转换。保留飞书计算字段为只读，不在 Calmy 重写完成度；优先复用现有四张表，不要求用户重建 Base。技术参考：[列出字段](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-field/list)、[列出记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/list)。

## 7. 开发顺序与验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| A：把当前接入做稳 | 线上授权读取、受控新增/更新、保存反馈、字段映射和动态状态 | Calmy 写入后飞书可见；飞书修改后刷新可见；失败不显示成功，不因新增状态丢记录 |
| B：让每天有用 | 飞书工作区来源、今天、快速新建、项目内列表/看板 | 一条任务只有一个记录 ID；没有日期可选入今天；标题必填即可创建 |
| C：让回顾省事 | 周概况、项目进展、简单周报编辑、个人筛选和缓存快照 | 用户能少录入地说明本周变化；公式只读；网络失败时能识别缓存与未保存状态 |
| D：经试用后扩展 | 跨设备个人设置、飞书登录、工作区与角色 | 用户身份、Base 访问范围和个人设置隔离；离开工作区或撤销授权后无法继续访问 |

不预估固定工期：A 的线上往返与表结构验收结果会决定 B 的工作量。活跃工程任务统一进入 OW-19，不在本规划另建一份互相竞争的待办清单。

## 8. 多人账号与 AI

成员表用于项目参与者和执行人，不能直接充当 Calmy 登录账号或授权角色。登录身份使用稳定用户标识，不能按显示名称匹配；部门字段也不自动决定系统权限。

多人阶段需要服务端会话、工作区隔离和后端权限校验，共享同步密码仅适用于当前单用户试验。应用身份与用户身份权限相互独立，不能把应用能读整张 Base 的权限理解为每个登录用户都能读整张 Base。[飞书官方权限说明](https://www.feishu.cn/content/article/7615520954977881029)

共享 Base 根据协作需求选择用户身份访问，或应用身份加服务端明确权限；用户自有 Base、跨租户连接优先评估 OAuth 用户授权、Token 刷新及撤销授权。多人方案完成前，不开放现有共享密码接口作为团队账户系统。

AI 后置。先考虑任务拆小、进度草稿、相关记录检索等能减少操作的能力；建议包含依据和确认动作。AI 不自动改任务状态、替用户制定生活目标或以完整人格档案作为使用前提。

## 9. 首轮试用的判断标准

先由用户自己使用一到两周，作为产品验证建议，不建立额外自动提醒或打卡要求。记录少量真实体验：是否能快速选出下一步，是否减少了飞书与系统之间的切换，是否重复录入，维护系统花了多久，以及不用某个功能会不会影响生活。

可试验的体验目标：约 10 秒确定一项行动，约 20 秒创建一条简单任务，回顾只需写一句也有用。这些是待验证目标，不是已实现性能指标。

如果日常仍需要频繁管理字段、修复关系、补齐表单或同时维护两套数据，优先缩减功能并修复连接与录入流程。当前最值得推进的组合是：稳定映射 + 今天选任务 + 一键新增 + 清楚的保存反馈。
