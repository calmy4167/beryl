# Calmy × 飞书官方能力同步清单

> 日期：2026-09-19 · 状态：持续维护清单 · 归属：D-016
>
> 目标：飞书是数据和协作能力的主来源，Calmy 逐步覆盖官方多维表格能力，并提供更适合个人现实管理的界面。此清单记录“官方存在的能力”和“Calmy 已完成的适配”之间的差距；清单完成不等于所有能力一次性开发完成。

## 1. 同步原则

1. 先以飞书官方开发者文档和用户当前 Base 的 schema 为准，再设计 Calmy 页面。
2. 新字段、新状态和新视图默认可读取、可隐藏但不丢失；未知字段不能让整张表加载失败。
3. 写入必须经过权限、字段类型和用户确认；不支持的写入明确提示，不伪造“已保存”。
4. 保留飞书 `app_token`、`table_id`、`view_id`、`field_id`、`record_id`；Calmy 的筛选、布局和 Today 选择属于界面状态，不复制成第二套任务事实。
5. “实时”分为三档：手动刷新、前台轮询、事件推送。没有完成事件订阅、去重、断线恢复和权限验证前，不称为实时同步。
6. 飞书新发布能力先进入本清单的“待官方核验”，核验接口、权限、限流和真实 Base 后再进入实现。

官方参考入口：[多维表格 API 总览](https://open.feishu.cn/document/server-docs/docs/bitable-v1/bitable-overview)、[列出字段](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-field/list)、[列出记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/list)、[新增记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/create)。

状态：`✅ 已实现`、`🟡 部分实现`、`⬜ 待实现`、`— 暂不纳入`。

## 2. 数据模型和 API

| 能力 | 当前状态 | 适配要求 |
| --- | --- | --- |
| Base / 数据表 / 视图身份 | 🟡 | 保存 app_token、table_id、view_id；工作区切换和失效提示 |
| 字段 schema 与 field_id 映射 | 🟡 | 字段改名保持可用；删除、类型变化阻止不兼容写入 |
| 文本、数字、单选、多选、复选、日期时间 | 🟡 | 读取格式化，写入按字段类型转换 |
| 人员、群组、部门 | 🟡 | 读取显示名；多人 OAuth 后按用户权限过滤 |
| 超链接、电话、邮箱、条码、地理位置 | ⬜ | 先只读，再按类型增加编辑控件 |
| 附件、图片、文件上传下载 | ⬜ | 增加媒体代理、权限和大小限制；不把密钥放浏览器 |
| 公式、查找引用、汇总、进度 | 🟡 | 只读展示计算结果，不在 Calmy 重算飞书公式 |
| 双向关联与反向关联 | 🟡 | 读取 record_id 并显示名称；写入关系前校验目标表权限 |
| 记录列表、分页、过滤、排序 | 🟡 | 保持分页游标；前端筛选与飞书服务端筛选分层 |
| 单条新增、更新、删除 | 🟡 | 当前仅任务新增/状态更新；删除需二次确认和审计 |
| 批量新增、更新、删除 | ⬜ | 增加预览、分批、失败重试和部分成功报告 |
| 查找、去重、幂等写入 | ⬜ | 网络结果未知时禁止盲目重建记录 |
| 字段、表、视图的创建与配置 | — | 首阶段不改 Base 结构，保留在飞书官方界面维护 |

## 3. 飞书官方界面能力映射

| 官方体验 | Calmy 目标 | 状态 |
| --- | --- | --- |
| 表格视图 | 显示字段、搜索、行详情、基础编辑 | 🟡 |
| 看板视图 | 按状态分组、拖拽换状态、动态状态列 | 🟡 |
| 卡片 / 右侧详情 | 显示原记录字段、record_id、关联名称 | 🟡 |
| 网格字段显示 / 隐藏 / 顺序 | 按工作区个人设置保存 | ⬜ |
| 筛选、排序、分组 | 保存为 Calmy 视图配置，不改飞书原视图 | ⬜ |
| 甘特图 / 时间线 | 读取日期和关系后展示；不复制任务 | ⬜ |
| 日历视图 | 读取日期字段；无日期记录仍可展示 | ⬜ |
| 画廊视图 | 作为项目 / 资料的可选视图 | ⬜ |
| 表单视图 | 仅在确认目标字段和权限后接入 | ⬜ |
| 仪表盘 / 统计 | 优先读取飞书结果或做明确的派生只读统计 | ⬜ |
| 评论、@提及、关注、通知 | 先评估官方 API、隐私和消息权限 | ⬜ |
| 分享链接、协作成员和访问范围 | 显示权限边界；不在 Calmy 自行放大权限 | ⬜ |
| 自动化、按钮、流程、脚本 | 作为飞书侧能力连接，不在 Calmy 复制一套自动化引擎 | ⬜ |
| AI 字段和智能能力 | 只展示飞书返回结果；必须标明生成来源和确认边界 | ⬜ |

## 4. 同步、授权和多人能力

| 能力 | 当前状态 | 后续要求 |
| --- | --- | --- |
| `tenant_access_token` 单用户 Base | 🟡 | Worker 保存密钥；线上配置和真实写回验收 |
| `user_access_token` / OAuth | ⬜ | 用户授权、刷新、撤销、跨租户和 Base 隔离 |
| 多个 Base / 多个工作区 | ⬜ | 每个连接独立保存 token、schema 映射和缓存 |
| Base / 表 / 视图权限 | ⬜ | 权限不足时按表显示错误，不污染其他表 |
| 事件订阅 / webhook | ⬜ | 去重、签名、断线恢复、权限撤销后停止接收 |
| 前台轮询 | ✅ | 活跃飞书页面 15 秒检查；页面隐藏时停止 |
| 离线读取缓存 | ✅ | IndexedDB 保存完整读取快照；离线显示更新时间并只读，写入仍要求联网确认 |
| 冲突与结果未知 | 🟡 | 保留输入和错误；先让用户核对飞书再重试 |
| 限流、超时、分页和大数据量 | 🟡 | 指数退避只用于读取；写操作不自动重复创建 |
| 审计、导出、删除传播 | ⬜ | 先做用户可见记录和恢复边界，再开放危险操作 |

## 5. 当前已完成范围

- Worker 侧使用应用身份获取飞书 token，App Secret 不进入前端。
- 已读取用户 Base 的项目、任务、周报、成员四张表。
- 已支持任务新增、状态更新、分页读取和业务错误反馈。
- Today、Capture、事项、事项看板支持飞书来源切换。
- 任务支持看板 / 表格切换、拖拽换状态和右侧原记录详情。
- 字段绑定保存 field_id；状态列来自当前 schema；飞书页面前台轮询。

## 6. 开发顺序和完成标准

### P0：先把当前 Base 用稳

- [ ] 用户部署 Worker 和 Pages，并验证配置状态、读取、任务新增、状态更新。
- [ ] 验证飞书端直接修改后，Calmy 轮询和手动刷新可见。
- [ ] 验证字段改名、新状态、新增字段、字段类型变化和权限不足。
- [ ] 验证拖拽失败不会显示成功，也不会重复创建任务。
- [ ] 拖拽写入成功后立即更新当前卡片，后台再刷新相关数据；不等待四张表全部读取完成。
- [ ] 记录拖拽响应耗时、Worker 请求耗时和飞书 API 耗时；超时或结果未知时保留原位置并提示核对。
- [ ] schema、关联表和非当前视图数据使用缓存或按需刷新，避免每次拖拽重复读取全部数据。

### P1：接近官方日常体验

- [ ] 表格字段显示/隐藏/顺序和个人视图保存。
- [ ] 筛选、排序、分组、甘特、日历和项目详情。
- [ ] 附件、人员、关系字段的安全读写。
- [ ] 批量操作的预览、权限检查和部分失败报告。

### P2：协作和自动化

- [ ] OAuth、多个 Base、多人和工作区权限隔离。
- [ ] 事件订阅、Webhook、事件去重和断线恢复。
- [ ] 评论、关注、通知、分享和官方自动化能力评估。
- [ ] AI 字段、飞书智能能力和 Calmy AI 的来源区分。

### P3：持续跟随官方变化

- [ ] 每次飞书官方 API / 多维表格能力变化，先更新本清单。
- [ ] 增加 schema / capability regression test。
- [ ] 对不支持的官方能力显示“暂未接入”，不得静默丢字段或记录。
- [ ] 线上发布前更新实现状态、验收证据和部署说明。

## 7. 明确不承诺

“全部同步”不是把飞书所有产品（文档、群聊、审批、人事、日历等）都复制进 Calmy。当前范围是多维表格及其授权、协作和相关自动化接口；其他飞书产品必须单独立项、单独授权和单独验收。
