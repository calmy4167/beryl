# Calmy 重设计路线图与验收门槛

> 更新日期：2026-08-22 · 原则：先收敛产品，再完成工程闭环，最后开放扩展能力。

> 当前未完成任务统一维护在 [`OPEN_WORK.md`](OPEN_WORK.md)；本文件负责阶段顺序、验收门槛和停止线。

## 阶段 0：冻结与基线

目标：停止继续扩大叠加态。

- 冻结新模块、新主导航和新领域对象。
- 采用本重设计包作为当前产品基线。
- 为现有路由和能力标注 `core / secondary / labs / legacy`。
- 固化当前数据备份和回滚方式。

退出门槛：团队能用一张表回答“首版做什么、不做什么、哪里只是兼容代码”。

## 阶段 1：产品壳收敛

目标：不删除数据能力，只重建默认体验。

- 品牌显示统一为 Calmy。
- 登录后默认进入 Today。
- 桌面和移动端主导航统一为 Today、Capture、Matters、Review。
- People、Library、Calendar、搜索和设置进入 More。
- Cases、旧 inbox、Graph、场景和工具箱退出默认导航。
- 页面文案替换 MVP、十神、五行等内部或开发术语。

退出门槛：5 位未读设计文档的试用者中至少 4 位能在 3 分钟内找到并完成“新建课题 + 添加今天行动”。

## 阶段 2：持久化与用例闭环

目标：产品承诺和真实写入路径一致。

- 建立核心 Application Use Cases 和统一异步状态。
- Today、Capture、Matters、Review 不再直接调用同步 Repository。
- 明确本地已保存、同步待处理、同步失败和冲突状态。
- 旧模型停止新增写入，提供迁移和只读兼容。

退出门槛：刷新、离线重开、存储失败、并发 revision 冲突均有自动化和用户可理解反馈；无静默丢失或覆盖。

## 阶段 3：端到端体验

目标：连续使用，而不只是页面存在。

- 完成首次使用、Morning Opening、行动记录、Evening Review。
- Capture 保存与整理分离，AI 建议可忽略、修改、撤销。
- 完成导出 → 清空隔离环境 → 重新导入的真实样本往返。
- 完成人工键盘、读屏、移动端和大字号审计。

退出门槛：核心闭环连续 14 天试用无阻断级数据问题；P0 缺陷为 0。

## 阶段 4：小规模试点

目标：验证产品价值而非功能数量。

- 招募 8–12 位符合目标情境的用户，使用 2–4 周。
- 记录首次价值时间、7 日闭环率、主动降载/暂停比例、数据信任问题。
- 每周只修阻断和高频认知问题，不在试点中扩展模块。

进入下一阶段的建议条件：至少 60% 试用者在 7 天内完成两次完整闭环，并且多数用户能用自己的话解释 Calmy 帮助了什么。

## 阶段 5：受控扩展

按真实需求依次考虑：

1. 搜索与 Library 深化；
2. People 作为上下文；
3. Trajectory 和更长周期回顾；
4. 可靠增量同步和真实 Companion Bridge 联调；
5. 共享空间与权限；
6. Graph 或高级理论视图。

每项扩展都必须有使用证据、隐私评审、降级策略和单独 Accepted 决策。

## 发布 Go / No-Go

### Go

- 核心四页无阻断缺陷；
- 数据可恢复、可导出、可重新导入；
- 所有关键写入都能区分本地保存与同步状态；
- 人工移动端和可访问性检查通过；
- UI 中没有把实验能力描述为已稳定能力；
- 产品试点达到核心闭环指标。

### No-Go

- 页面仍在不同存储路径写同一实体；
- Cases / Matters 或 inbox / Capture 仍允许双向新增；
- 离线或刷新可能丢失最后一次核心写入；
- 冲突会静默覆盖；
- 用户必须理解五行、十神或复杂领域术语才能完成首日任务；
- 仅凭自动化测试数量或页面数量宣布“完整实现”。

## 6. Flow / 沉浸流的受控扩展计划

Flow 是在核心四页闭环稳定后逐步开放的二级能力。它不能改变 Today、Capture、Matters、Review 的首版承诺，也不能因为页面或代码已经存在就跳过产品验收。

### 6.1 开放顺序

1. **内容基础层**：统一 Seed 模型，接入 Calmy 现有资料、事项、Cycle、Review、日记、快速记录和可选的本地/Eagle/视频提取来源；每条内容保留 `sourceRef` 和上下文。
2. **有限浏览层**：实现 Flow 广场、有限批次、收下/再见、来源链路、离线状态和返回原上下文；默认不无限滚动。
3. **Focus 层**：实现单条视频/句子/知识沉浸视图，支持退出、来源、滚轮/方向键/`J/K` 和关闭自动播放/声音。
4. **四种模式**：依次开放漫游、学习、回响、专题；每种模式都有目的、范围、结束状态和现实行动出口。
5. **行动与关联**：支持学会、行动、关联；行动必须由用户确认，并写入现有 Action/Matter/Cycle 协议，不建立第二套状态。
6. **推荐与偏好**：接入当前事项、学习状态、复习窗口、来源和用户反馈等可解释规则；在“我的/设置与同步”提供来源、强度、自动播放、声音、边界和通知控制。

### 6.2 Flow 功能验收

- 支持本地视频、Eagle 素材、视频提取句子/字幕/摘要/时间点、知识、好句、学习资料、日记、快速记录、Seed 和 Matter/Cycle/Review 内容。
- 内容统一为 `video / quote / knowledge / image / note / mixed` Seed 类型，并支持来源、标签、人物、主题、Matter/Cycle、重要性、学习状态、用户意图、最近出现、出现次数、复习时间、关联和行动引用。
- 支持未整理、已保存、正在学习、已学会、已关联、已行动、暂不需要、已归档等状态；状态变化可追溯、可撤销或降级。
- 同时提供浏览层和 Focus 沉浸层；Focus 支持移动端上下切换和 Web 滚轮/方向键/`J/K`，但退出和来源始终可见。
- 支持漫游、学习、回响、专题四种模式；每种模式都有明确目的、内容边界和结束逻辑。
- 支持收下、再见、学会、行动、关联、展开来源和退出；再见不强制解释，行动必须回到现实下一步。
- 推荐规则可解释、可控、可降噪，优先当前意图和已有内容；同内容/类型/主题去重并限频。
- 默认没有无限滚动、自动播放下一条、连续奖励、未读红点和焦虑式提醒；在线时长、浏览量、连续天数、点击率和消费总量不作为核心指标。
- 支持进入前的轻量边界、结束卡、连续跳过/长时间停留提示和返回原上下文；退出不丢失已保存内容。
- 覆盖加载、空内容、无推荐、离线、来源不可用、播放失败、保存失败、冲突和恢复连接后的同步状态。

### 6.3 Flow 与现实行动验收

- 用户在 10 秒内能理解当前要做的现实动作，而不是被引导继续浏览。
- “行动”可以创建或更新一个低粒度下一步，且用户可以不关联、不整理、直接退出。
- 事项、资料、句子和视频均能查看真实来源或使用场景。
- 完成事项后不强制填写报告、进入统计、领取奖励或继续推荐。
- Review 可以沉淀 Seed，但不得自动把未确认内容写成正式行动或关联。
- 长时间未维护时优先收敛、隐藏低价值入口或保留未整理状态，不发送催促维护通知。

### 6.4 端侧与可访问性验收

- App 适合短暂查看、记录和结束；Web 适合多列浏览、资料整理、来源管理和专题编辑；两端共享同一 Seed、来源和退出语义。
- 键盘可以完成浏览、操作、退出和返回；移动端主要操作达到至少 44×44px。
- 读屏可以识别当前模式、来源、推荐理由、保存状态、结束卡和关闭方式。
- 支持 `prefers-reduced-motion`；自动播放、声音和动效均可关闭，默认保持克制。
- 320px、200% 缩放、系统大字号、浅色、深色和高对比环境下不丢失行动和退出入口。

### 6.5 Flow 的 No-Go 条件

- 为 Flow 单独建立内容仓库、用户状态或同步协议，造成第二套事实来源。
- 用推荐数量、在线时长、连续浏览或通知打开率替代现实行动价值。
- 默认无限加载、遮挡退出、自动播放下一条，或以奖励诱导继续停留。
- 外部来源无法追溯、无法关闭或在离线/失败时静默丢失操作。
- Flow 页面挤压 Today 首屏，或用户必须理解完整 Cycle/五行模型才能使用。
