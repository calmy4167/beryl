# Calmy UI / UX 重设计

> 评审版本：2026-08-22 · 目标：让核心价值在一个屏幕和一个闭环内可理解。

## 1. 新信息架构

### 一级导航

| 入口 | 用户问题 | 主行动 |
|---|---|---|
| Today | 今天真正要守住什么？ | 开始或记录当前行动 |
| Capture | 现在先记下什么？ | 保存原文 |
| Matters | 我正在面对哪些长期课题？ | 打开当前 Matter |
| Review | 发生了什么，下一步如何调？ | 完成今日调整 |

搜索使用全局命令入口；设置、导入导出、People、Library、Calendar 放在“更多”。Graph、场景和旧工具箱只在实验设置中可开启。

### 路由建议

```text
/app/today              默认入口
/app/capture            独立快速记录，也可用全局按钮/快捷键
/app/matters            当前、暂停、归档三个过滤状态
/app/matters/:id        Matter 工作区
/app/review             今日复盘与历史复盘
/app/more               搜索、人物、资料、日历、设置
/app/labs/*             图谱、场景、旧模块等实验功能
```

`/app/home` 重定向到 Today；`/app/cases*` 和 `/app/module/*` 保留迁移期兼容，不再进入导航。

## 2. 导航布局

### 桌面端

- 左栏固定 4 个主入口；Capture 使用高辨识度主按钮。
- 左栏底部只保留搜索、更多、账户/数据状态。
- 左栏支持收起/展开：收起后保留图标、当前项和可访问名称，桌面端可用按钮或 Ctrl/⌘ B 切换，状态在刷新后恢复；移动端继续使用底栏与 More。
- 四边分工：左边是主导航，上边是当前位置与保存状态，右边是当前上下文和三项快捷动作，下边是搜索/Capture/复盘等高频命令；四条边不重复承载完整模块列表。
- 右侧上下文栏在窄桌面自动收起，快捷动作保留在顶部或底部命令条，避免挤压主内容。
- 主内容最大阅读宽度约 920px；详情页可在右侧出现上下文检查器。
- 不在左栏重复中英文标签、阶段术语和工具分类。

### 移动端

- 底栏为 `Today / Matters / Capture / Review / More`。
- Capture 位于中间，可在任意页一步唤起底部编辑层。
- 触控目标至少 44×44px；系统安全区和键盘弹出不得遮挡保存按钮。
- More 内入口按“查找与历史 / 数据与隐私 / 实验功能”分组。

## 3. 核心页面

### Today

```text
今天，8 月 22 日                       [搜索]
你今天大概能承受多少？  低 / 中 / 高

守住这一件事
[行动标题]                     [开始]
因为：连接到 Matter 的 why

有余力再做（最多 2 条）
□ 行动

今天主动放下
[添加一件不做的事]

[记录刚刚发生的事]             [结束今天]
```

规则：首次进入只要求承载量和一条行动；理论解释、趋势和历史默认折叠。

Today 应按“晨间定向 / 白天行动 / 晚间复盘”渐进披露，而不是一次铺开全部输入。三问完成后折叠为摘要，复盘只在用户触发或适当时段出现。

### Capture

```text
先记下来
[多行原文输入                              ]
[保存]

保存后：已安全记录。
可选建议：连接到「职业转型」/ 变成下一步 / 暂不整理
```

保存与整理分成两个事务。AI 建议不阻塞保存，也不能改写原文。

### Matters

```text
我的课题                    [+ 新建]
[当前 3] [暂停 2] [归档]

职业转型
为什么：获得更可持续的工作方式
这一轮：完成作品集 · 下一步：整理案例
```

避免仪表盘式统计。列表只回答状态、意义、当前轮次和下一步。

### Matter 详情

```text
职业转型                         [更多]
为什么重要：……
状态：进行中 · 这一轮：完成作品集

下一步                         [+ 添加到 Today]
[行动卡]

最近发生
[Record 时间线]

这一轮与调整                    [展开]
关联人物 / 资料                 [展开]
```

暂停、归档、删除放在“更多”中；危险操作必须说明影响和可恢复性。

### Review

只用三步自然语言：

1. 观：今天实际发生了什么？
2. 察：哪些条件帮助或阻碍了？
3. 调：明天保留、降低、暂停或改变什么？

提交前显示“这会更新什么”；生成的下一步由用户确认。

## 4. 组件和反馈规则

- 每页只有一个视觉主按钮。
- 状态使用文字 + 形状，不只依赖颜色。
- 保存先显示本地持久化结果；同步状态单独表达，不能把“本地已保存”误写成“云端已同步”。
- 空状态给一个行动和一个例子，不展示完整领域模型。
- 删除统一支持撤销或归档；历史记录更正保留 revision。
- AI 内容必须标注“建议”，并提供接受、修改、忽略。
- 错误信息包含：发生了什么、数据是否安全、用户下一步能做什么。

## 5. 视觉方向

- 品牌统一为 Calmy；迁移完成前不得同时在主界面出现 Beryl 和 Calmy。
- 使用安静的中性色背景和单一强调色；强调色用于当前行动和主按钮，不给每个理论类别分配竞争色。
- 字体层级控制在页面标题、区块标题、正文、辅助文字四级。
- 卡片用于可操作对象，不把每段说明都包成卡片。
- 动效只帮助理解保存、展开、移动和撤销；支持 `prefers-reduced-motion`。

当前实现需要优先修正的可用性基线：

- 浅色 `--c-text-3: #969a91` 与页面背景对比约 2.62:1，不适合大量辅助文本。
- Today 仍保留少量 9–10px 辅助标签，但 900px 内的 button、select、input、移动品牌按钮和记录区保存控件已统一达到至少 44px；820px 平板记录区会重排，避免桌面多列挤压。
- 全局样式已加入 `prefers-reduced-motion` 处理；真实设备上的大字号、读屏和键盘连续操作仍需人工验收。
- local-first 产品仍从 Google Fonts 加载远程字体；默认首页还可能请求外部 Quote 内容。核心体验应无外部请求也完整、稳定、快速。

### 建议语义令牌

| 令牌 | 用途 |
|---|---|
| `surface/base` | 页面背景 |
| `surface/raised` | 卡片与弹层 |
| `text/primary` | 主要内容 |
| `text/muted` | 辅助信息 |
| `accent/action` | 主行动与当前状态 |
| `status/caution` | 阻塞、冲突、同步待处理 |
| `status/danger` | 不可逆风险，不用于普通未完成 |

建议优先收敛的组件：`PageHeader`、`PrimaryActionCard`、`MatterListItem`、`CapacitySelector`、`TimelineEvent`、`StatusChip`、`InlineCapture`、`TriageCard`、`ContextDrawer`、`EmptyState`、`ErrorPanel`、`ConflictResolver`、`SaveStatus`。

## 6. 文案替换原则

| 避免首屏使用 | 推荐表达 |
|---|---|
| Cycle | 这一轮 |
| Stage / 五行阶段 | 当前阶段 / 现在需要做什么 |
| Trajectory | 最近趋势 |
| Seed | 下一轮线索 |
| 负向现实 | 阻碍与损耗 |
| MVP Today / MVP 事项 | Today / 课题 |
| 工作台 | Today |

术语可以在“了解模型”帮助层解释，但不能成为完成任务的前置知识。

## 7. 可访问性与响应式验收

- 全流程只用键盘可以完成，焦点顺序和可见焦点明确。
- 读屏可以识别当前导航、表单错误、保存状态、弹窗标题和关闭方式。
- 200% 缩放、320px 宽度和系统大字号不丢失关键操作。
- 浅色、深色和高对比设置满足 WCAG AA 的文本与控件对比要求。
- 手工检查 VoiceOver 或 NVDA；静态测试不能替代读屏验证。

## 8. 产品评审中的 IA 分歧

UX 席提出过五入口方案：Home、Today、Matters、People、Library，并将 Review / Calendar 并入 Today。主审暂不采纳，理由是当前 MVP 已明确关系与知识库不是主流程，Home 与 Today 的重叠也是已知问题。

本轮采用四入口方案 `Today / Capture / Matters / Review`。在 2–4 周试点中比较两个问题：

- 用户是否把 Review 视为独立任务，还是自然地从 Today/History 进入；
- People / Library 的实际访问是否足以升级为一级入口。

没有行为证据前不增加一级导航。

## 9. 2026-08-22 视觉重构落地

本轮先完成核心壳层与 Today 的第一阶段收敛：

- 全局视觉令牌切换为温暖纸张背景、深墨色文字、陶土色单一行动强调色；卡片统一为 12px 圆角和低阴影。
- Today 改为主内容流 + 状态侧栏的桌面布局，容量检查、行动、现实记录和复盘不再平均争夺横向空间；窄屏自动回到单列。
- 桌面底部快捷命令栏取消，避免与左侧主导航、顶部搜索和右侧快捷动作重复；1280–1349px 紧凑桌面隐藏右栏，保留内容宽度。
- 增加完整的深色自定义 surface、文字、边框和原生控件令牌，避免 Element Plus 变暗而页面背景仍保持浅色的问题。
- 移动端继续保留底部四入口和“更多”抽屉，抽屉具备 dialog 名称、显式关闭按钮、Escape 关闭和焦点可见性。

后续仍按渐进披露推进：Today 的非核心边界与晚间复盘默认收起，Capture 的建议生成再进一步拆成独立动作，Matters 的冲突和附件维护继续下沉到设置与同步。

本轮第二阶段已落地：Review 顶部提供可编辑的“今天的复盘”并复用现有 revision/save-state 协议；Matters 将 Open Vault 导入导出收进“数据工具”，课题目录改为单列列表；Capture 主按钮视觉上明确为“保存原文”，技术型建议信息降为次级说明。
