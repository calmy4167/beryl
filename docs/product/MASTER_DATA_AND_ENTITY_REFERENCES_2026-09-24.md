# 主数据与实体引用设计

> 日期：2026-09-24  
> 状态：当前产品设计；决策 D-019 已接受，工程范围按 OW-22 分阶段推进。  
> 上位约束：[Calmy 产品总设计](CALMY_PRODUCT_DESIGN_2026-09-19.md)、[产品决策](PRODUCT_DECISIONS_2026-08-19.md)。

## 1. 目的

“主数据管理”不是把人物、目标或资料页面搬进一个总表，也不是要求用户为了使用业务模块先维护一套企业式后台。它由两个相邻但不同的部分组成：

1. **可复用内容素材**：例如句子、人物，以及未来经验证确有需要的地点、项目、资源、知识、文件、物品或账户。
2. **系统字典**：供表单或流程使用的类别、标签、来源，以及用户可配置的模块内状态选项。

前者表达“哪些具体内容/实体可以在别处复用”；后者表达“当前模块有哪些选项”。两者可以放在同一个一级入口下管理，但不能因此混成一种领域实体或同一套选择逻辑。

## 2. 信息架构

- 侧边栏增加一级入口“主数据管理”，对应稳定路由 `/app/master-data`。
- 页面内部至少分为“内容素材”和“系统字典”；内容素材首批提供句子与人物视图。模块名、字段名保持用户语言，领域类型不作为理解门槛。
- “主数据管理”是次级工作能力，不取代今天、记录、处境、回顾等日常主线，也不应把所有业务内容集中成巨型表格。
- 现有 `/app/people` 人物页面及旧人物兼容路由继续有效；首批实现可将已有页面复用为人物管理视图，但不得复制人物记录或创建第二份事实源。

## 3. 内容素材

首批内容素材：

- **句子**：可由用户保存的提醒、表达、摘录或常用文本；保存标题/正文，允许按类别、标签、来源检索。应用不得将其冒充为经过验证的建议、名言或权威事实。
- **人物**：复用已有 Person 主体、稳定 ID、角色/关系、领域、备注、标签与归档状态。人物名称被修改后，持有实体引用的页面应显示最新名称。

后续可能支持的类型包括地点、项目、标签、知识、资料、文件、书籍、习惯、物品、账户等；每种类型采用适合内容的字段与预览，而不是都显示为“请选择”。只在真实场景需要时增加新类型。

内容中心至少支持新增、编辑、搜索、按类型/状态筛选、归档或停用。最近使用、收藏、频率排序可用于缩短重复选择路径，但不应变成自律指标、活动排行榜或 AI 推荐结论。已有数据量很小时，优先显示搜索、最近使用和收藏，而非冗长分页。

一个待验证的使用假设是：多数选择由 Combobox 快速完成，少量场景进入 Drawer，极少数需要完整管理；“80/15/5”只描述交互层级方向，不是已测得的使用率、KPI 或产品承诺。

## 4. 系统字典与可配置状态

- 字典按模块和字段隔离，例如任务状态、目标状态、财务类别分别维护；不建立所有模块共用的一组“状态”。
- 字典视图可以管理类别、标签、来源及经该模块明确支持的状态选项。
- Select 仅用于少量、封闭选项；可搜索对象用 Combobox；多项标签/关系使用 Chips；层级分类用 TreeSelect。字典管理页不等于每个使用位置都必须弹出管理界面。
- 状态可以新增、重命名、排序或停用，但界面可配置并不自动意味着领域命令可执行。每种状态仍须遵守其模块的状态机和有效转换；在命令、筛选、统计和迁移支持前，不开放会令记录无法完成转换的新状态。
- 已有记录使用中的选项只能停用/归档，不能硬删除；历史记录继续按稳定选项 ID 或兼容旧值显示。名称变化不得重写事件历史或静默改变数据语义。
- 本阶段先验证模块隔离、旧值兼容和安全生命周期；跨模块状态复用、复杂条件规则不进入首版。

## 5. 业务页中的实体引用交互

选择器遵循“轻量直接选 + 复杂情况展开”的渐进式模式，而不是所有引用都用同一个弹窗：

```text
业务页面字段
  → 轻量搜索/最近/收藏（Combobox）
  → 浏览全部（右侧 Drawer）
  → 找不到时快速新建（创建并关联）
  → 已选对象显示为类型化 Entity Chip/Card
```

### 5.1 快速选择

- 默认直接搜索并选择；支持键盘上下移动、Enter 提交、Escape 关闭、明确焦点和可访问名称。
- 选择器可按场景展示最近使用、收藏、搜索结果和“浏览全部”；不在打开时倾倒数百个选项。
- 高频对象可由快捷方式触发，例如正文插入句子的 `/`、人物的 `@`；具体触发符号按输入环境验证，必须不破坏中文输入、移动端输入及原有键盘行为。
- 数据量很少的封闭枚举继续用轻量 Select，不为统一组件而强制全站更换控件。

### 5.2 复杂浏览

- 点击“浏览全部”时，从当前页面右侧展开 Drawer，让用户仍看见正在编辑的任务、记录或关系。
- Drawer 提供搜索、按该类型可用的筛选、最近/收藏、预览和选择；选择后自动回到调用它的页面并保留尚未提交的表单内容。
- Drawer 适用于需要比较、筛选或预览的实体选择。Modal 保留给独立的小任务、简单新增和确认，不作为所有主数据引用的默认容器。特别庞大数据可后续提供独立浏览页。

### 5.3 快速新建与已选状态

- 当前搜索无匹配项时提供“新建‘当前输入’”，打开轻量表单，复用用户当前输入并只询问必要字段。
- 首要操作名为“创建并关联”；创建成功后立即选中并返回当前业务上下文，失败时保留输入并说明原因。
- 关系字段保存带实体类型的稳定 ID，不把名称副本当作关系。展示为 Entity Chip/Card，至少呈现图标/类型与当前名称；可按类型增加轻量上下文、移除关联、查看详情。
- 有详情且信息有助于选择时，可以提供 hover/focus 快速预览和详情入口；不得以 hover 作为唯一信息通道。
- 预览字段由实体类型决定：人物可逐步呈现角色/关系、领域、标签、备注或有来源的最近互动；书籍可呈现封面/书名，知识可呈现标题/摘要，地点可呈现地址。当前模型没有的数据不得用示例内容伪造，扩展字段须有真实需求和隐私边界。
- 单选和多选由具体字段语义决定，不得默认把一个引用字段变成多选。

## 6. 引用与正文快照语义

需要区分“关系引用”与“文本插入”：

- **关系字段**（例如任务关联人物）：存储 `(entityType, entityId)`，显示时解析最新名称；人物改名后关系仍指向同一个人。
- **向正文插入一句话/姓名**：插入的是用户确认后的文字快照，后续素材编辑不能静默改写旧日记、事实、复盘或决定。如果保留 `sourceMaterialId`，它只提供来源溯源，不能成为回写正文的依据。
- 删除或归档被引用实体时，不级联删除业务记录。已有关系保持可解释（显示已归档/不可用对象或保留最后已知的安全标签），恢复实体后可以继续解析。
- 导入、导出、复制或同步须保留关系 ID、类型、快照和来源边界；不可把仅凭文字相同的对象自动合并为同一实体。

## 7. 现有代码与数据约束

- 现有统一实体 Repository 中已经有 `Person`、`Resource` 和 `Relation`。可复用 Resource 的 template 语义管理句子类素材；只有无法由现有领域对象表达且完成迁移设计时才增加新实体类型。
- `PeoplePage` 已管理统一 Person，旧 `b_chars` 数据和 `/app/module/chars` 兼容入口已有迁移/重定向边界。功能不得再次创建一组平行 `chars` 或人物库。
- IndexedDB/Repository 仍是本地事实源；主数据必须服从现有 durable 写入队列、备份恢复、实体级同步及导入导出。新集合/字段要经过相关白名单、开放格式和往返测试。
- 新 Picker 是 UI 交互层，不承担跨仓储业务事务；建立、更新和归档必须通过相应 Repository/Use Case，并沿用 revision、持久化错误反馈与撤销/迁移契约。

## 8. 分阶段实现

### 第一阶段：中心管理与可复用素材

增加主数据一级入口；整理句子素材并复用现有人物管理。先完成列表、搜索、新增/编辑/归档和本地 durable 持久化，不在空白的字典页伪装全量能力。

### 第二阶段：渐进式引用纵切

建立类型化 Picker 规则：轻量 Combobox、右侧 Drawer、快速创建并自动关联、Entity Chip/预览。先接入少数高频写作和关系字段（优先记录/收集、日记/回顾及任务-人物关系中的实际使用场景），保存稳定引用 ID 或正文快照；经端到端回归后再扩展。

### 第三阶段：模块级字典与流程状态

先为一个业务模块完成类别/标签/来源字典闭环，再按模块开放可配置状态。逐一确认命令状态机、列表筛选、历史展示、备份、同步、旧枚举迁移和回滚，再扩展到其他模块。

### 后续候选（不属于首批验收）

Ctrl+K 全局主数据搜索、超大规模独立浏览页、树形复杂词典、拖拽建立引用、上下文推荐，以及地点/书籍/文件等新类型；是否采用依赖真实数据量和用户操作证据。

## 9. 首批验收与停止线

- 用户从一级入口能管理并搜索句子素材；人物使用已有 Person 数据和 ID。
- 常用调用点可以快速搜索；浏览、复杂筛选不会遮断当前编辑上下文；Quick Create 保存成功即关联。
- 类型/标签展示区分清楚；所有交互有键盘路径、焦点状态、状态反馈和移动端布局。
- 关系字段不因显示名称变化而断链；正文快照不因主数据编辑而改变；归档不级联删除引用记录。
- 现有数据、离线启动、Repository durable 写入、备份恢复、同步及兼容地址通过回归。
- 若增加主数据要求用户先做大量分类、让常规操作普遍经过抽屉/弹窗，或迫使所有表单同时出现关系字段，则应缩减调用点；若开放新状态会绕过领域状态机，则暂停开放并保留现有状态语义。
