# OW-21「工作机会」纵向试点设计

日期：2026-09-20  
状态：方案草案；工作预设已有局部代码试改；待真实场景和用户语言验证  
依据：[Calmy 产品总设计](CALMY_PRODUCT_DESIGN_2026-09-19.md)、[D-018](PRODUCT_DECISIONS_2026-08-19.md#d-018-calmy-转向人与世界之间的反思层)、[未来回望原型设计](../superpowers/specs/2026-09-19-future-lookback-design.md)

## 1. 这份方案解决什么

用现有「工作与机会」预设，设计一条从表达处境、区分事实与解释、平衡地回望两种选择、作出决定、使用外部工具到记录现实反馈的纵向流程。它只定义试点边界，不表示完整流程已经实现，也不把当前预设称为真实用户场景。

目前唯一可用的场景描述是预设原句「争取一个新的工作机会」。没有真实参与者提供的职业、地区、工作状态、顾虑或判断标准；方案不得代入这些个人事实。此预设只能用于检查流程是否连贯，OW-21 的真实场景与语言验收仍未完成。

## 2. 试点场景与边界

**试点问题：** 用户正在考虑是否开始了解并争取一个新的工作机会。

**不预设：** 用户当前不满意、一定要离职、所在国家或地区、目标行业、家庭责任、经济压力、市场需求或成功概率。用户可以补充事实，也可以不补充并退出。

**流程选择：** 小而可逆的探索（例如只查看岗位信息）应能快速结束；只有用户认为影响重大、持续较久或不易撤回时，才进入完整回望。系统不自动判断用户的问题够不够重要，也不把探索变成求职计划。

## 3. 端到端体验

1. **说出处境。** 用开放输入表达「我正在考虑什么」。保留用户原话，不先要求选择 Matter、目标或项目类型。
2. **分开事实与解释。** 可选填写「已经发生的事」和「我对它的理解或担心」。例如，收到一条岗位信息属于可核对的事实；「我肯定不合适」属于判断。系统不替用户判定哪句话是真的。
3. **回望两种选择。** 以「去了解／争取」和「暂时不行动」为两条路径；每条路径都呈现可能的收获与代价：
   - 去了解／争取：可能获得的市场反馈、选择或成长；也可能投入时间、承受拒绝，或发现新机会并不适合。
   - 暂时不行动：可能保留稳定、避免当前投入或等待更合适时机；也可能暂时得不到外部反馈，或让当前问题继续存在。
   每项都写明事实来源、成立条件和未知信息。不得把不行动只写成损失，也不得把行动只写成收益。
4. **作出自己的选择。** 用户可选择行动、暂缓、放弃或仍不确定，并写下决定理由。系统不替用户给出“正确答案”。可选下一步必须是用户确认后才保存。
5. **进入合适的外部工具。** 例如在浏览器研究岗位，在 Word 修改简历，在 Excel 比较用户自选条件，在 Calendar 安排用户确认的沟通。Calmy 只提供链接与上下文，不复制专业编辑、搜索、表格或日历功能。
6. **带回现实反馈。** 用户可记录实际发生的回应、结果和自己的感受，并看到它与原处境、行动之间的联系。没有反馈时不提示为失败，不自动推断用户放弃。

第 3 步应验证用户是否看见两种选择各自的收获和代价；仅展示「行动能得到／不行动会错过」不足以满足 D-018 的平衡要求。

## 4. 最小数据与现有对象映射

首轮不新增 Situation 或外部引用实体。先用现有对象做显式映射，只有真实试用证明无法承载时才扩展。

| 用户需要保存的内容 | 当前可用承载 | 规则与缺口 |
|---|---|---|
| 原始处境和决定草稿 | Capture | 选择任一主题后都可选填写事实和解释，也可附一个外部链接；只有用户明确确认保存后，才与选择、反思、下一步一起写入可读 Capture 正文。不得保存推演文案。Capture 不自动变成长期处境。 |
| 持续处理的处境 | Matter | 用户明确选择长期保留后再创建；`title` 保存简短标题，`problem` 保存处境，`why` 保存用户认可的理由，`evidenceIds` 关联证据。旧 Matter 字段均保持可选和兼容。 |
| 可核对事实 | Record，`type: fact` | 仅记录用户确认或带来源的内容。现实体验或观察可用 `observation`；正文标明来源，不把推测写成事实。 |
| 用户解释、担心和决定理由 | Record，`type: insight` 或 `review` | 以用户自己的话保存，并明确它是解释/判断；与事实记录分开，不推断人格或稳定偏好。 |
| 用户确认的下一步 | Action，可选 `matterId` | 只在用户确认后创建；不从自由文本自动生成行动。空白下一步不创建 Action。 |
| 行动后的现实反馈 | 首轮另存 Capture；长期可映射到 Record | 当前页面允许用户回来后手动记下反馈，并在正文引用选择记录的 Capture ID。它不是图谱关系，也没有自动带入外部结果；原选择 Capture 被删除后，反馈仍独立保留，正文 ID 可能失去对应对象。此时反馈草稿仍在页面，可用当前页面保留的选择、反思和上下文重新保存一条 Capture，再保存反馈。以后可由用户决定是否转成关联 Matter/Action 的 Record。 |
| 外部岗位、文件或沟通对象 | 当前没有专用外部引用字段 | 用户可附一个完整 HTTP(S) URL；保存后页面提供打开链接，Calmy 不读取页面内容。链接作为可读文本保存在原 Capture；不能承诺结构化权限、稳定链接、自动刷新或跨服务同步。若链接关联成为高频需求，再设计带来源和权限状态的窄引用接口。 |
| 未来情境、来源、条件和版本 | 不持久化为用户实体 | 模板与来源由产品版本维护；页面可展示依据，但不得写进用户事实记录或伪装成个人经历。 |

当前 Matter、Action、Record 和 Capture 的字段见 `src/domain/{matter,action,record,capture}/model.ts`。这张映射表是试点约定，不是新增领域模型。

## 5. 外部工具边界

| 工具 | Calmy 可以做 | Calmy 不做 |
|---|---|---|
| 浏览器、招聘网站 | 用户主动打开岗位或职业信息；返回后由用户选择是否记录链接和反馈 | 不抓取账号内容、不自动投递、不声称掌握实时本地岗位市场 |
| Word | 用户在原工具中维护简历或求职材料；Calmy 可保存用户选择的链接 | 不在 Calmy 重做文档编辑、不复制完整简历 |
| Excel | 用户在自己的表格中比较薪酬、条件或岗位；Calmy 保存决定理由与必要链接 | 不复制专业表格、公式或数据模型 |
| Calendar | 用户确认后打开或创建面谈安排 | 不自动写日历、不把建议时间当成已确认安排 |
| 邮件、即时通信 | 用户自行沟通；回到 Calmy 后可记录自己愿意保存的回应 | 不读取收件箱、不代发消息、不复制通信客户端 |
| IDE、Obsidian | 本工作场景首轮不接入；如后续场景确有需要，另行验证 | 不为了列齐工具而增加无场景的集成 |

首轮以用户提供的普通链接和手动带回反馈为边界：保存后用户可以在新标签打开链接，回到 Calmy 后另存一条现实反馈 Capture，该条 Capture 在正文中引用原选择记录 ID。不要求插件、授权、抓取或双向同步；反馈不写回外部工具。外部工具打开失败时，用户仍能完成反思并退出。

## 6. 旧数据、导出与回退

- 不重命名、不删除现有 Matter、Action、Record、Capture 字段或路由；新体验先作为实验入口。
- 现有未来回望保存结果继续以可读 Capture 保留。关闭实验入口不删除已保存内容；再次启用后仍可从 Capture 查看。
- 如试点后把 Capture 显式提升为 Matter，必须保留原 Capture ID 或明确来源关联，避免重复记录；提升失败时原 Capture 不变。
- 现有备份允许集合包括 Capture、Matter、Action、Record 及其命令/修订数据，并排除认证和同步密钥。首轮新增信息只能落在这些可导出的正文或字段中；上线前仍需对实际备份往返做单独验收。
- 回退方式是隐藏实验入口、保留兼容路由和已有记录，停止新增体验写入；不做破坏性数据库迁移。若试点证明需要结构化外部引用，必须先定义旧记录读取、导出和回滚映射。
- 现实反馈 Capture 不随原选择 Capture 自动删除；原记录删除后，反馈正文中的编号可能成为悬空引用。这是首轮采用独立 Capture 的已知限制。
- 用户可在设置中导出当前数据；不将推演模板或来源文案并入个人档案。

实现依据：[备份允许字段](../../src/core/backup.ts)与现有数据模型。此处描述当前代码边界和后续验收要求，不代替真实导出/恢复验证。

## 7. 真实用户语言验证

**当前状态：未执行。** 预设和本方案不能算用户验证。建议首轮邀请 5 位近期真实考虑过工作机会、且愿意参与的用户，一对一完成 20–30 分钟可跳过的体验；不要求披露雇主、薪酬、姓名或可识别材料，不录制个人信息。参与者可随时改用虚构例子或退出。

主持人只读任务，不解释内部术语：

1. 「请用你自己的话告诉我，你最近在面对什么；不想分享真实细节时可以用虚构例子。」
2. 「哪些是已经发生的事，哪些是你对它的理解或担心？」
3. 「看完两种选择后，各自可能得到什么、付出什么？哪些说法有依据，哪些仍不知道？」
4. 「你现在更想做、暂缓、放下，还是还不确定？是什么让你这样选？」
5. 「如果你打开了外部工具，回来后你会怎样把实际反馈带回这里？」

记录观察而非评价参与者：是否不经解释就能开始；是否自然区分事实与解释；是否能说出行动与暂缓两边的收获及代价；是否把可能性误解为预测；是否知道如何打开和返回外部工具；是否认为输入量或重复录入太多。

首轮通过条件建议：至少 4/5 人能独立说明两边各自的可能收获与代价；无人把推演理解为保证或个性化预测；至少 4/5 人能指出其决定理由和现实反馈在哪里保存；出现明显施压、诱导离职、地域市场误导或把解释当事实时，先修正文案再继续。该人数和阈值是首轮建议，需随试点样本和观察修订，不代表统计显著性。

## 8. 现有原型差距与下一步

现有 `/app/future` 已有四个可编辑预设、半年/五年回望、来源链接、反思和用户确认后保存 Capture。当前代码还让四个预设分别列出行动与暂缓的可能收获和代价，所有主题都能可选区分事实与解释，并可附链接；用户确认后才保存。自定义内容依然暂停推演。保存后可以打开该链接，并手动另存一条引用原 Capture ID 的反馈 Capture。仍缺少：

1. 用户决定、行动对象、外部工具与反馈之间的稳定领域关联；当前反馈只通过正文中的 Capture ID 作可读关联；
2. 结构化外部引用（当前明确暂缓）；
3. 基于真实工作场景的语言验证和外部工具实际往返验收。

当前工作预设引用的 CareerOneStop 指南由美国劳工部赞助，内容建议研究职业、定向准备简历和建立相关联系；它只能支持一般求职步骤，不能证明任何用户所在地区的市场需求、薪酬、录用概率或职业结果。未确认用户地区和目标前，页面不得把它呈现成当地市场证据。[CareerOneStop 工作指南](https://cloudfront.careeronestop.org/TridionMultimedia/tcm24-50399_PDF_changeoccupationuserguideACC.pdf)

实施顺序：下一步用真实场景检查前台语言、事实/解释区分、四种可能性、链接打开和手动反馈回收；根据观察决定 Capture ID 的可读关联是否足够，再讨论结构化外部引用或新领域聚合。OW-21 在真实验证完成前保持未完成。
