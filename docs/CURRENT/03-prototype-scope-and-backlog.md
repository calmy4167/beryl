# 雏形范围与暂缓清单

> 更新：2026-10-05。产品方向未定时的建议优先级，不是永久路线图。详细历史任务仍保存在[`OPEN_WORK.md`](../product/OPEN_WORK.md)，不再由其旧推荐顺序自动驱动当前投入。

## 已由用户核验的暂缓项

### 2026-10-05：跨用户协作与分享整组暂缓

用户确认雏形阶段暂不投入跨用户分享、邀请、成员管理、可见范围选择、ADR-002 密钥封套和多人模型 §1–45 全面达标；本阶段只保留设计文档、边界说明和恢复条件。恢复前置条件是产品方向明确、真实多人场景验证确有需要，并完成独立密码学审查。

### 2026-10-05：Portable Vault 深化暂缓

用户确认雏形阶段保留现有 Open Format 导出/导入和 JSON 备份；真实用户目录往返、增量写入、外部编辑冲突审阅、目录权限恢复和附件对象存储/R2 只记录，不继续投入。恢复条件是现有导出/恢复能力在真实试用中被证明不足，并有代表性数据和浏览器权限验证方案。

### 2026-10-05：系统管理收敛为普通后台

用户确认系统管理按常见后台管理模式收敛，保留用户、角色、菜单/权限、基础会话和必要操作日志等普通能力；不继续建设复杂的领域级权限编排、运营风控、多人协作管理或管理员解密业务数据能力。现有代码可作为基础，后续只按实际使用补齐普通后台缺口。

### 2026-10-05：Obsidian Companion Bridge 暂缓

用户确认雏形阶段不做 Companion Bridge 实时联调；保留现有 Obsidian Adapter、协议和恢复线索。只有在核心场景验证后确实需要 Obsidian 双向通信时，才重新评估生产 transport 和插件联调。

### 2026-10-05：飞书高级集成暂缓

用户确认雏形阶段不继续投入飞书 OAuth、多工作区、线上写回、跨设备设置和真实租户权限/部署验收；现有适配代码和接口保留，等核心产品方向确定后再决定是否继续。

### 2026-10-05：AI、Flow 与全模块质量收口排到最后

用户确认 AI 理解层深化、Flow 全量实现，以及各模块完整的离线/同步/错误/空状态/无障碍验收排到最后阶段；当前只保证选定核心场景能跑通，不把这些工作列入雏形开发。

### 2026-10-05：视觉审计与品牌迁移暂缓

用户确认暂不做 335 组逐像素截图审计和大规模几何台账维护；`beryl` 旧品牌键、缓存名和服务名先保留兼容，等产品方向和命名稳定后再统一迁移。

### 2026-10-05：Obsidian_calmy 扩展语料只读保留

用户确认 `Obsidian_calmy` 中的报告体系、LIMS/实验体系、可配置平台、软件之外的产品设计和其他思想语料只保留、只记录，不纳入当前产品开发；若未来要实现其中方向，需先单独确认产品价值和范围。

## 雏形阶段先完成

目标是尽快验证一条真实用户能理解的核心场景，同时让试用产生的数据可恢复。

1. 选定一个场景，打通表达现实、作出选择、保存结果和回看反馈的一条纵向流程；页面和现有对象可按验证结果调整。
2. 保证该流程的本地写入、错误提示和恢复行为可理解；至少能导出或备份关键数据，并说明尚未覆盖的资料类型。
3. 确认开发构建与所需的核心回归门禁可运行。2026-10-05 审计曾记录类型检查错误和前端测试失败；本轮文档整理未重跑这些命令，修复代码不在本轮范围。
4. 做小范围场景/语言验证，记录用户能否独立完成流程，再决定是否扩展业务模型。

这几项是“能学习、能保住数据”的最小条件，不要求完成全站所有页面或冻结最终产品方向。

## 方向确定前可暂缓

| 暂缓项 | 当前理由 | 重新启动条件 |
|---|---|---|
| 跨账号分享、邀请、成员管理、可见范围 UI、ADR-002 密钥封套 | 雏形不需要多人协作；ADR-002 尚未通过独立密码学审查，跨用户分享当前未实现 | 出现经验证的多人场景，并满足独立安全审查门槛 |
| 多人模型 §1–45 全面达标 | D-021 保留其为参考基准，但不将全面达标作为当前完成门 | 真实场景证明其中某一能力是核心需求 |
| 复杂系统管理、领域级权限编排、运营风控 | 已确认收敛为普通后台；当前已有代码先保留，不按复杂平台继续扩张 | 普通用户/角色/菜单/会话/日志能力无法满足实际运营 |
| Portable Vault 完整目录往返、增量写入、冲突 UI、附件对象存储/R2 | 现有格式/备份已提供起步能力，完整目录工作需真实浏览器和目录验证 | 用户试用证明现有导出/恢复不足，且通过代表性数据验收 |
| Obsidian Companion Bridge 真实联调 | 当前只有协议/测试，没有生产 transport；不阻塞核心流程 | 目标用户确实需要插件双向联动 |
| 飞书 OAuth、多工作区、线上写回和跨设备设置 | 已确认暂缓；现有适配代码保留，不是本地雏形的前置条件 | 核心场景确定需要飞书作为数据源 |
| AI 理解层深化、Flow 全量实现、逐模块完整离线/同步/无障碍验收 | 已确认排到最后；当前只保证核心场景可运行 | 方向冻结、准备公开发布或真实用户使用需要 |
| 逐像素截图审计、截图/几何台账维护 | 已确认暂缓；像素对齐不能验证产品方向 | 明确启动视觉验收任务时再选取必要页面 |
| 品牌键/旧集合批量改名 | 已确认暂缓；先保留兼容，避免在方向未定时引入迁移风险 | 有稳定的新命名方案及可验证回滚计划 |

Obsidian_calmy 中的报告、LIMS、可配置平台和软件之外的产品构想作为只读灵感素材保留；它们不是当前代码待办，也不在此阶段合并或删除。

## 任何阶段都要保护的数据边界

不要把“暂缓功能”误读为“可以破坏现存数据”。稳定 ID、导入/导出兼容、备份覆盖、用户归属和 ADR-001 零知识边界仍按[硬约束清单](05-boundaries.md)处理。若某个核心场景确实需要改变边界，先明确迁移成本和安全决策，再动代码。

## 当前下一步

产品负责人选择一个要验证的真实场景。开始之前只需写清用户、触发时刻、希望完成的决定/动作和现实反馈；在此之前暂停新增模块和远期规划。
