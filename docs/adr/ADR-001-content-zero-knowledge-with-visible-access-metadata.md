# ADR-001：Calmy 采用零知识优先的数据架构

- **状态：** Accepted
- **日期：** 2026-09-29
- **范围：** 身份、多人协作、Vault、同步、Search、Graph、AI、备份与开放数据
- **产品依据：** [Calmy 多人场景、模块关系与数据共享核心设计方案](../../Calmy-多人场景-模块关系与数据共享核心设计方案.md)
- **配套约束：** [开放数据与 Portable Vault](../product/CALMY_OPEN_DATA_AND_PORTABLE_VAULT_2026-09-24.md)

## 决策

Calmy 采用**零知识优先（Zero-Knowledge First）的本地优先架构**。核心原则是：

> **服务器负责确认“谁有资格取得某份数据”，客户端负责理解“这份数据是什么”。**

Calmy 云端服务器原则上不持有用户私人业务内容的明文。云端是同步与协作基础设施，不是用户数据的唯一事实来源。

## 背景

Calmy 可能长期保存日记、健康、财务、人际关系、家庭数据、私人记录、文件、照片、回忆、行为历史和 AI 使用上下文。这些内容高度私密；让服务器集中持有业务明文，会使 Calmy 逐渐成为掌握用户完整生活数据的平台，与“帮助用户管理自己生活的数据工具”的定位冲突。

## 三层数据边界

### Control Plane（控制面）

服务器可以处理确认身份、授权和同步所需的控制信息：

```text
User ID、Device ID、Entity ID、Scope ID、Permission、Controller
版本号、同步序列、删除状态、Key Envelope、授权关系
```

控制面回答：**谁可以取得哪份数据？** 其中标识应尽量使用不透明 ID；授权关系仍会泄露必要元数据。

### Encrypted Data Plane（加密数据面）

服务器保存和传输加密 Entity Payload、附件、文件和备份。正常同步不得依赖业务内容明文。

### Local Semantic Plane（本地语义面）

只有用户可信设备解密后，才能理解标题、正文、Person、Thing、Scene、Domain、健康和财务内容、日记、文件内容、Relation 与 Graph。服务器知道数据存在，但不知道它表达什么。

例如，客户端可以把一条“爸爸今天血压 135/90，医生建议暂时观察”的记录理解为 HealthRecord、Health Domain、爸爸 Subject 和相关 Thing；服务端只需处理不透明 Entity ID、权限信息、版本、Ciphertext 与 Key Envelope。

## 身份与密钥

登录密码不能直接作为内容加密密钥。凭据、设备密钥、用户密钥、内容密钥和恢复密钥彼此分离。管理员可以重置登录凭据、停用账号和撤销 Session，但这些操作不赋予管理员解密私人内容的能力。

具体密钥封装必须采用经过审查的标准密码原语，不自行设计算法。设备新增、公钥真实性校验、换机、恢复、轮换和兼容策略须在实现前完成安全设计。

## 共享与撤权

每个 Entity 使用其 Content Key 加密。分享时，授权方客户端把相应密钥封装给获准用户；服务器保存密文、密钥封套和用于同步授权的控制面关系，不能解密内容。

撤权会阻止未来读取和同步、移除或失效对应密钥封套，并为未来版本轮换 Content Key。撤权不能远程收回已经下载、解密、复制、截图或导出的内容。

## Search、Graph 与 AI

- **Search：** 密文同步至客户端后解密并建立本地索引；服务器不默认建立私人全文索引。
- **Graph：** 客户端依据已解密且获准访问的 Person、Thing、Scene、Entity、Relation、Domain 构建；服务器无需掌握完整生活关系图。
- **AI：** AI 默认不能自动读取整个 Vault。客户端先在本地完成授权查询并形成最小 Context；用户明确选择并确认后，才把选定内容发给外部 AI。发送内容离开纯本地零知识边界。
- **推荐与筛选：** 优先在本地使用已授权解密数据计算。
- **备份与导出：** 备份保持加密；需要用户可读的导出由客户端解密生成，并清楚提示保存位置。不得导出会话、凭据或解密密钥。

## 存储职责与离线优先

- **D1：** 身份、Session、设备、Entity Header、Permission、Scope/成员关系、Key Envelope、版本、同步变更日志和审计元数据。这里的 Scope ID 与关系标识应是不透明标识，不存语义筛选条件或业务正文。
- **R2：** 加密附件、图片、视频、PDF、大型 Payload 和加密备份。
- **IndexedDB：** 本地解密后的 Entity、Relation、Domain、本地 Search/Graph 索引、待提交 Mutation、Sync Cursor 和本机 View Cache。

正常写入路径为：

```text
用户操作 → 立即写本地 → 本地加密 → Mutation Queue → 后台同步密文
```

本机持久化状态与云端同步确认状态必须分开表达。离线设备保留已下载副本；重新联网后再获取服务端撤权状态。

## 管理员与产品边界

Calmy 不采用以下模式：

- 管理员天然能查看所有用户数据；
- 数据库保存全部业务明文；
- 登录密码直接充当数据密钥；
- 各模块各自实现独立 ACL；
- 服务器默认建立私人全文索引；
- AI 默认读取整个个人数据库；
- 管理员重置密码即可获得用户私人数据。

## 元数据泄露与恢复风险

零知识不代表服务器什么都不知道。服务端仍可能观察某 User 有多少 Entity、Entity 大小、同步时间、哪些 User 之间存在授权关系、数据是否更新及设备登录信息。这些属于 Metadata Leakage，应如实告知用户。

若用户所有可信设备丢失且 Recovery Key 也丢失，Calmy 管理员可能无法恢复私人数据。创建 Vault 时必须明确说明，并提供 Recovery Key、恢复包、可信设备恢复和安全导出机制。

准确的产品表述是：

> **私人业务内容默认端到端加密，Calmy 服务端无法直接读取用户 Vault 的业务明文。**

## 例外治理

如有功能确实需要服务端获知某类信息，必须逐项完成必要性分析、隐私影响评估、数据边界说明和用户知情，并通过新的 ADR 决策。默认不知道，确有必要时才逐项开放。

## 后续设计约束

本 ADR 是 Calmy 后续身份、共享、Vault、同步、Search、Graph、AI 和开放数据设计的基础架构原则。全产品访问设计必须将查询分为两条明确边界：

1. **服务端授权查询：** 基于认证 User、设备、Opaque Entity/Scope ID、Permission、Controller 和授权版本，只决定哪些密文及 Key Envelope 可以同步；不解释业务语义。
2. **客户端语义查询：** 客户端解密服务端已授权返回的数据，再按 Owner/Subject、Person、Thing、Scene、Space、Domain、Relation 等语义筛选、搜索、构图和生成 View/AI Context。

服务端不得根据语义条件过滤明文；客户端也不得把本地语义查询结果当作服务端授权的替代品。两者共同构成完整访问路径。
