## 1. 设计目标

将 Calmy 从多套样式叠加的普通后台界面，重构为具有真实材料层次、稳定操作重量和成熟信息密度的产品工作台。

这里的“质感”同时包含两部分：

1. **看起来有实感**：背景、工作面、抬升面和浮层有清楚层级；边界、阴影、圆角、字号和间距精确；颜色承担状态与结构，不悬空装饰。
2. **使用起来有实感**：导航、按钮、抽屉、输入、保存和完成状态有连续反馈；操作结果持续存在；空、加载、错误、禁用和溢出状态都能自然进入同一系统。

产品目标不变：用户进入 Calmy 后，应在短时间内看清一件重要的现实问题、形成自己认可的下一步，并回到现实。系统提供方法、材料和证据，但不替用户选择。

## 2. 已确认的方向

### 2.1 产品界面，不是概念海报

- 使用真实 HTML、CSS、React 组件和现有数据呈现，不以生成图片中的布局作为不可落地的视觉事实。
- 不用装饰性插画、虚构 KPI、进度环、统计图表或大量同尺寸卡片填充首页。
- 彩色区域必须承载真实上下文，例如关联处境、下次回看或状态；不能只作为无意义装饰。
- 主页面允许有较高信息密度，但只有一个主要行动。

### 2.2 视觉基线

- 浅亮应用框架、冷灰工作区、真实白色表面。
- 午夜蓝承担稳定结构，电光蓝承担主要操作和当前状态。
- 珊瑚、琥珀、青绿和紫色只用于状态区分、记录类型和局部上下文。
- 圆角比早期原型更紧凑，接近成熟企业产品，而不是柔软的卡片拼盘。
- 信息通过开放列表、行、轨道和面板组织；容器只在需要表达表面或浮层时出现。

### 2.3 参考系统的使用边界

芋道、若依及用户提供的成熟 SaaS 截图只用于校准稳定壳层、栏位关系、菜单收起、控件密度、选中连续性和完成度。Calmy 不复制它们的权限后台、表格首页、KPI 面板或业务内容。

## 3. 空间与材料系统

### 3.1 桌面应用框架

宽屏桌面使用有边界的应用框架：

- 外层画布：冷灰 `#E9EDF4`，可有极轻的品牌色环境光，但不使用大面积玻璃模糊。
- 应用框架：真实白色，桌面最大宽度约 `1480px`，大屏保留 `24–32px` 外间距；窄桌面贴近视口。
- 外框圆角：`18px`；普通面板依次使用 `12px / 10px / 8px / 6px`。
- 工作区：`#F7F9FC`，与白色导航和浮层形成可辨识的表面差异。
- 只保留三档深度：框架、抬升工作面、浮层/抽屉。阴影必须具有偏移和软扩散，禁止无方向的彩色光晕。

### 3.2 间距与密度

使用以 `4px` 为基数的间距系统。桌面默认：

- 顶栏高度约 `70px`；
- 页面内边距约 `26px 32px`；
- 主焦点区高度约 `252px`；
- 高频列表行约 `52–56px`；
- 同组信息使用 `8–12px` 间距，不同区块使用 `20–32px` 间距；
- 正文信息尽量在首屏出现，避免通过过大的空白或卡片内边距制造“高级感”。

提高密度时优先加入真实上下文与减少无效留白，不增加无意义模块。

### 3.3 排版与图标

- 中文界面采用可读、稳定的现代无衬线字体栈；生产实现应确认可获取字体，再决定是否自托管，不在加载失败时破坏中文可读性。
- 页面标题、主要内容、分组标题、正文、辅助信息和状态文字形成明确的六级层次。
- 数字、时间和保存状态使用表格数字或稳定宽度，避免刷新时跳动。
- 图标来自同一套真实 SVG 图标系统，统一线宽、视口和选中方式；禁止用 Unicode 符号或 Emoji 代替产品图标。

### 4.1 左侧主导航

- 展开宽度约 `232px`，收起宽度约 `76px`。
- 收起后保留品牌图形、四个主入口图标、功能入口、当前选中位置和用户头像。
- 收起状态继续使用现有本机偏好键 `calmy_sidebar_collapsed`，不进入业务数据或同步。
- 展开/收起使用连续宽度过渡；标签渐隐，图标位置稳定，不能先消失再闪现。
- 当前项使用一个在菜单项之间连续滑动的深蓝渐变选中层，而不是每个菜单项分别闪烁进入。
- 当前页面具有 `aria-current="page"`；收起状态下每个图标按钮仍有可读名称和提示。

### 4.2 顶栏

- 固定承载日期或页面身份、全局搜索和保存/同步状态。
- 不与页面内部主操作竞争；页面主操作只出现在页面内容中。
- 顶栏与工作区以细边界分离，不使用独立大阴影。

### 4.3 右侧情境区

- 默认形态为 `66px` 情境工具轨道；用户主动打开后扩展为约 `356px`。
- 桌面宽度不足时自动关闭抽屉，只保留轨道或移入功能目录。
- 情境抽屉只显示当前页面有关的方法、证据、相似经历和现实出口，不成为第二份全站菜单。
- 工具切换使用颜色和选中层连续过渡，不对整块内容做透明度闪烁。
- 用户可以关闭情境抽屉，关闭后主工作区获得空间；状态复用现有 `calmy_right_sidebar_collapsed` 偏好。

## 5. 动效系统

动效用于解释状态与空间关系，不用于装饰。

### 5.1 已确认时序

- 按钮按压：`100–140ms`，向下位移 `1–2px`，阴影同步收紧。
- 菜单选中层：约 `340ms`，使用 `cubic-bezier(.16, 1, .3, 1)` 连续滑动。
- 左侧栏展开/收起：约 `360ms`，宽度、标签透明度和折叠箭头同步。
- 右侧抽屉：约 `320ms`，保持从工具轨道向外展开的空间连续性。
- 普通 hover / focus / 状态色：`140–220ms`。

### 5.2 禁止项

- 页面切换时先整体降低透明度再恢复；
- 通过移除并重新添加 class 强制重播关键帧；
- 每个区域相同的淡入上移；
- 弹跳、弹性曲线或超过日常操作容忍范围的长动画；
- 让默认状态不可见，依赖 JavaScript 动画后才出现。

### 5.3 减少动态效果

`prefers-reduced-motion: reduce` 下取消空间位移和长过渡，但保留颜色、边界和文字状态变化，确保操作结果仍可感知。

## 6. Today 首页结构

Today 是全站视觉与行为的第一验证面，桌面首屏按以下顺序组织：

1. **页面身份**：今天、简短说明、最后保存时间。
2. **唯一主焦点**：此刻最重要的事、关联处境、下次回看和一个主按钮。
3. **快速记录**：单行输入，提交后真实新增记录并更新保存状态。
4. **今天的记录**：紧凑时间行，使用颜色标识记录类型，不把每条记录包成卡片。
5. **正在发生**：等待现实反馈和未决取舍等真实上下文，使用列表行而非 KPI。
6. **情境抽屉**：寻找主要矛盾的方法、可追溯的相似经历和“下一步已经足够”的现实出口。

空状态、少量内容、典型内容、长标题、多条记录和加载/保存失败必须在同一布局中成立。

### 6.1 与现有 Today 逻辑的映射

- `useTodayWorkspace`、Action、Matter、Record、保存状态和飞书/本地来源逻辑保持不变。
- `TodayNowPanel` 映射到主焦点工作面，不改变主行动选择、进行中和完成语义。
- `TodayRealityRecordPanel` 收敛为快速记录入口，复杂字段按需展开，保存仍通过现有用例。
- `TodayRecentRecords` 映射为开放时间列表。
- `TodayContextPanels`、身体状态、轨迹、探索和复盘入口进入情境抽屉或次级展开区，不与主焦点竞争。
- `TodayLetGoPanel` 和 `TodayAddActionPanel` 保留能力，但通过次级区或显式入口展示，不在首屏形成额外主表单。

## 7. 其他页面的系统化迁移

全站不强制复制 Today 的版面，只继承壳层、令牌、控件和交互语言：

- **记录**：输入工作面 + 最近记录列表；保存状态和来源清楚可见。
- **处境**：高密度列表/分栏详情；选择态稳定，长标题和大量条目可读。
- **回顾**：时间范围、证据列表和反思编辑区；不以完成率卡片作为首页信息。
- **看板/任务**：保留列和拖动语义；减少卡片圆角和浮层感，状态颜色遵循全站令牌。
- **资料/探索/文章**：搜索、过滤、开放列表与阅读面；不复制后台表格，也不使用无限信息流。
- **人物/图谱/记忆**：以证据、来源和关系为主；AI 推断与事实保持视觉区分。
- **飞书/设置/兼容 Vue 页面**：通过共享令牌匹配 React 壳层，保留现有授权、同步、迁移和错误边界。

## 8. 组件和样式边界

实施时建立一套共享的产品 UI 基础层：

- `AppFrame`、`PrimaryNav`、`SlidingNavSelection`、`PageTopBar`、`ContextDock`、`ContextDrawer`；
- `FocusSurface`、`PrimaryAction`、`CompactInput`、`DataRow`、`StatusMark`、`EmptyState`、`StatusMessage`；
- 展开、收起、选中、保存、加载、失败、禁用和减少动态效果状态。

现有 `react.css`、`ui-refresh.css` 和 `product-ui.css` 中存在重叠的颜色、圆角、阴影和页面覆盖。实施不得继续增加第四套全局体系。新令牌进入一个明确的主题入口；页面专用规则只描述该页面的结构，通用控件必须复用基础层。

## 9. 响应式行为

- `≥ 1360px`：展开左栏、主工作区、情境轨道；抽屉是否展开由用户状态决定。
- `1180–1359px`：默认收起左栏或情境抽屉，保证主工作区宽度。
- `901–1179px`：使用紧凑桌面/平板壳层；次级情境内容进入覆盖抽屉。
- `≤ 900px`：使用现有移动顶栏和底部四入口导航；Today 变为单列，情境内容使用底部抽屉或页面内按需展开。
- 中文长标题、200% 页面缩放和系统大字号不能遮挡主操作。

## 10. 数据与业务边界

本次只替换前端表达和组件架构：

- 不修改领域模型、Repository、IndexedDB、同步协议、认证、路由语义或飞书接口；
- 不增加虚构数据、个人判断、AI 结论、统计分数或完成率；
- 演示数据只存在于隔离原型，生产页面必须读取现有真实状态；
- 不因为视觉改造改变 Action、Matter、Record、Review、Flow 或“主动放下”的行为。

## 11. 实施顺序

1. 建立新令牌、可回退的壳层和导航收起/情境抽屉状态。
2. 用 Today 完成端到端纵向切片，接入现有真实数据和交互。
3. 逐一迁移记录、处境、回顾四个主入口。
4. 按页面类型迁移扩展模块和 Vue 兼容页。
5. 在桌面、窄桌面和移动端完成视觉、键盘、保存状态和减少动态效果验证。
6. 所有页面迁移并通过回归后，才移除旧的重叠样式和实验开关。

不得在第一批次一次性重写所有页面，也不得在新壳层稳定前删除旧 UI 回退路径。

## 12. 验收标准

### 12.1 视觉与密度

- 首屏无需滚动即可看到主焦点、快速记录、至少三条记录和一个正在发生的真实上下文。
- 眯眼观察时，主行动明显高于记录和情境内容；彩色区不成为第二焦点。
- 桌面展开和收起状态均无布局跳跃、文字裁切和空白断层。
- 全站不出现四套以上的圆角、阴影或按钮语言。

### 12.2 交互实感

- 左侧栏、右侧抽屉、导航选中层和主按钮具有连续、可中断、无闪烁的反馈。
- 输入提交后新增内容并显示真实保存状态；失败时说明问题和恢复方式。
- 键盘能够完成导航、抽屉、记录和主行动操作；焦点始终可见。
- 减少动态效果下，所有状态仍然清楚。

### 12.3 功能与回归

- 四个主入口、扩展目录、搜索、动态详情、兼容路由和 Vue 设置页继续可达。
- 现有 Today 主行动、记录、保存、复盘、放下、飞书/本地来源和离线逻辑保持原语义。
- 桌面与移动端均通过构建、针对性组件测试、浏览器交互回归和截图对照。

## 13. 不在本次范围内

- 后端业务逻辑、数据库和同步架构重写；
- 新的 AI 决策系统、推荐流或自动替用户确定主要矛盾；
- 用 KPI、图表或连续使用指标增加信息密度；
- 复制芋道、若依或参考图中的权限后台、业务模块与演示数据；
- 在真实设备、读屏器和长期试点完成前宣称整个产品体验已验证。
