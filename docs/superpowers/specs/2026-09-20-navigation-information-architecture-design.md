# Calmy 导航与功能地图设计

日期：2026-09-20

状态：本地试改已按用户反馈调整；分组与“我的”页仍待体验确认

方向：用户已确认“清晰主线 + 按功能分组”，并要求先改一版试用；后续明确要求模块名尽量使用两个字，已应用于日常入口、分组内模块和页面标识。本地试改保留路由和数据；是否继续采用由用户体验后决定。

关联方向：[Calmy 产品总设计](../../product/CALMY_PRODUCT_DESIGN_2026-09-19.md)

## 1. 目的

让用户容易找到日常主线，也能按用途找到扩展功能。导航应减少重复入口和内部术语，不要求用户先理解 Calmy 的后台对象或产品理念。

本设计整理信息层级和入口职责，并已按试改范围呈现在本地预览中。现有路由、数据模型及功能保持兼容；是否保留或扩大这次调整，由用户体验后决定。

## 2. 约束与边界

- 遵从 D-018：Calmy 是人与世界之间的反思层。“看见、想清、选择、入世、回望”是产品责任，不是必须依次完成的导航模块。
- 遵从 OW-21 停止线：在完整真实场景和前台语言验证前，不批量重命名后台对象、不重写全部导航、不新增完整 Situation 数据模型。
- 兼容 `/app/today`、`/app/capture`、`/app/matters`、`/app/review` 及所有扩展模块路由和旧别名。
- 不删除功能，不迁移或重写用户数据，不改变同步行为。
- 新文案优先使用简短、自然的中文；`Matter`、`Capture`、`Cycle`、`Flow` 等名称可以继续作为代码或兼容术语，不作为用户必须掌握的导航概念。
- 分组是查找功能的方式，不是要求用户依序完成的工作流程。

## 3. 当前信息架构

当前桌面壳层同时呈现：

- 左侧四个主入口：Today、Capture、事项、复盘；
- 右侧快捷栏：包含 Capture、事项看板、我的、AI 对我的理解，以及按页面显示的快捷动作；
- “更多”抽屉：列出 Cycle、事项看板、飞书、资料、Flow、我的、AI 理解、人物、日历、收件箱、任务、习惯、财务、目标、番茄钟、日记、文章、设置、图谱、场景和未来回望等入口；
- 手机底栏保留四个主入口，“更多”抽屉列出扩展入口；
- “我的”页面另外列出全部模块，并在“系统与数据”区再次列出设置、资料、人物、图谱和 AI 理解。

由此形成几份部分重叠的目录：桌面左栏、右栏、抽屉和“我的”模块列表。扩展入口也混合了工作功能、个人工具、试验页面和设置；一些英文内部名称缺少对用户的解释。

## 4. 方案比较与选择

### 方案 A：只按业务模块组织导航

把所有页面按模块类别放入树状导航。

- 优点：接近常见工作台和管理系统，扩展模块容易找到。
- 代价：主线容易被大量入口淹没，Calmy 也会更像模块集合。

### 方案 B：只保留极简入口并依靠搜索

导航只保留少数页面，其余功能主要从全局搜索进入。

- 优点：界面入口少。
- 代价：用户难以发现功能；搜索不适合作为首次查找或浏览功能的唯一方式。

### 方案 C：主线在前、扩展功能集中分组（推荐）

主导航保留少数高频日常入口；扩展能力统一进入分组目录。右侧栏只负责当前页面的上下文和快捷动作，搜索保留为快速入口。

该方案兼顾清晰主线和模块可发现性，也避免把新产品的五种责任直接变成五个必经模块。

## 5. 建议的信息层级

### 5.1 日常主线

桌面和手机保持同一组四个高频入口，对应现有稳定路由：

| 现有页面 | 试改名称 | 路由 | 备注 |
|---|---|---|---|
| Today | 今天 | `/app/today` | 看当前状态和现实行动 |
| Capture | 记录 | `/app/capture` | 先用自然语言留下内容 |
| Matters | 处境 | `/app/matters` | 找回持续影响自己的处境 |
| Review | 回顾 | `/app/review` | 查看发生了什么及后续反馈 |

导航入口、分组标题和页面栏标题优先用两个字；较完整的解释放在页面说明中。这些是待真实场景验证的文案候选，不在本设计阶段作为最终定稿。后台实体名称和 URL 保持原样。

### 5.2 扩展功能分组

扩展页面统一按用途分组。分组最多一层，避免形成多级管理菜单。

| 分组试改名 | 页面试改名 |
|---|---|
| 工作 | 看板、任务、目标、日历、飞书、周期 |
| 内容 | 收集、资料、探索、日记、文章 |
| 关系 | 人物、图谱、记忆（图谱保留“试验”标识） |
| 工具 | 习惯、财务、专注 |
| 试验 | 未来、场景 |
| 个人 | 我的、设置 |

分组名称仅用于帮助查找，不暗示因果、优先级或必须完成顺序。具体归组可在审阅时调整。

### 5.3 桌面与手机职责

- 桌面左栏显示日常主线和“功能”入口；后者打开分组目录。全局搜索可从侧栏和目录快速到达。
- 桌面右栏保留当前页面上下文和少量相关动作，不再重复提供一套全局模块目录。快捷动作可以随页面变化，但同一目的不同时作为全局菜单项重复出现。
- 手机底栏保留四个日常入口和“功能”。“功能”打开与桌面一致的分组目录，支持键盘/辅助技术语义和明确的关闭、焦点返回路径。
- 使用同一份导航定义维护桌面和手机的路由、名称、分组与试验标识，避免不同尺寸下入口和标题逐渐不一致。

### 5.4 “我的”与功能清单

`/app/profile` 当前同时承载本地用户概览、统计数据、全部模块入口和重复的系统入口。本地试改中：

- “我的”只保留个人会话、场景和个人数据概览；
- 所有模块入口统一出现在桌面/手机共用的分组目录中；
- 页面内重复的完整模块清单和系统链接已从试改版移除，保留 `/app/profile` 路由和概览内容；
- 设置、资料、人物、图谱和记忆各自只在对应分组中出现一次。

是否喜欢“我的”页变短、模块集中到功能目录，需要根据本地预览反馈决定。

### 5.5 试验能力的可见性

未来和场景页面继续显示“试验”标识，并放在“试验”分组。图谱留在“关系”中，但保留试验标识。未来页是否进入日常主线，需等完整真实场景、真实语言和个性化边界完成验证后再决定。

## 6. 实施顺序

1. 已将用户要求的两字模块名应用到本地试改；功能分组和“我的”页仍待完整体验反馈；
2. 根据后续反馈继续调整这版导航；
3. 若用户认可整体结构，再确定正式实施范围和验收；
4. 保留旧路由和书签，核验用户可见入口、键盘操作、窄屏布局和兼容路由。

## 7. 验收标准

- 用户无需知道 Matter、Action、Record、Cycle、Stage 或 Seed 等内部概念，也能找到日常主线和扩展功能。
- 日常主线保持少量固定入口；任何普通模块都可通过清晰的分组目录找到，不要求用户依赖搜索。
- 每个扩展页面在分组目录中仅出现一次；设置和同步只有一个导航入口。
- 桌面左栏和手机“更多”使用同一名称、分组和入口顺序；右栏不再重复完整模块目录。
- “我的”不再承担第二份完整模块导航；其个人概览和统计仍可访问。
- 扩展功能没有被删除，当前路由、旧别名、用户数据和同步行为保持兼容。
- 试验能力有明确标识；试验页面不会因导航收拢而被误述为已验证的正式主流程。
- 桌面、键盘操作、窄屏和辅助技术仍能找到当前页面、主行动、搜索和离开/关闭入口。
- 核心入口的最终文案经真实场景的语言验证后再确定。

## 8. 试改范围之外

- 不修改路由、后台对象、数据存储或同步协议；
- 不删除兼容别名、扩展能力或既有用户数据；
- 不重命名 URL 或领域对象，不删除兼容路由；
- 不增加新的工作流页面或 Situation 聚合；
- 不把五种产品责任做成必经步骤；
- 不决定 AI、检索、飞书默认模式或其他外部集成；
- 不将本功能地图视作用户研究结果。

2. `/app/profile` 是否只承担“我的”概览，完整模块目录集中到功能目录是否顺手。
