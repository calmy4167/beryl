# Calmy 系统管理模块设计

**日期：** 2026-09-30  
**状态：** Draft，待产品负责人审阅  
**产品范围：** 用户账号、系统角色权限与账号安全管理  
**产品模型约束：** 不新增部门树或全局岗位。Calmy 的 `Space`、`Person`、`Relation`、`SceneParticipant`、`Owner/Steward` 和上下文角色模板承担现实组织、关系、参与身份和数据责任表达；账号身份及系统管理权限与这些业务概念分离。

## 1. 目标

将当前仅有的管理员/普通用户两级账号管理，扩展为独立、可配置、可审计的系统管理模块，提供若依/芋道常见的后台账号治理能力，同时沿用 Calmy 的 Vue + Cloudflare Worker + D1 技术边界，并使用 Calmy 自己的 Person、Space、Scene、Relation 和 Ownership 语义。

首期覆盖用户、系统角色、管理功能权限、密码与登录安全配置、登录日志、操作日志和在线会话管理。功能完整性以这些系统管理能力为目标，不移植 RuoYi/Yudao 的 Java、Spring、Redis、部门表、岗位表或其业务模块。

## 2. 架构选择

采用现有架构扩展方案：Vue 管理界面调用 Cloudflare Worker API；Worker 对所有管理操作执行身份、角色和功能权限校验；D1 保存账号目录、系统授权关系、安全参数和审计元数据。

不引入单独的认证服务或第二套身份事实源。稳定 `userId`、密码哈希、会话和现有 Vault 用户隔离继续由当前账号系统负责。

## 3. 管理界面与功能

新增独立“系统管理”一级模块，内部提供以下页面：

1. **用户管理**：分页/筛选用户；创建、编辑、启用、停用、逻辑删除、重置密码；分配一个或多个系统角色；查看最后登录时间及基本账号状态。不得把部门、岗位或上下文身份当作账号必填字段。
2. **系统角色管理**：创建和维护系统角色；为角色配置系统管理菜单、页面操作和 API capability。Calmy 的产品上下文角色模板不在此维护。
3. **安全设置**：维护登录密码长度与复杂度规则、失败次数与锁定时长、登录验证码开关、初始密码修改提示及密码有效期策略。
4. **登录日志**：查询成功与失败的登录事件，按用户、结果、时间和来源筛选；展示锁定原因，并允许有权限的管理员解除账号登录锁定。
5. **操作日志**：记录谁在何时对哪个系统管理对象执行了什么动作及结果；敏感请求字段一律脱敏，不记录密码、令牌、Vault 内容或解密密钥。
6. **在线会话**：查看活跃会话的用户、设备标识、创建/过期时间及必要网络元数据；有权限的管理员可撤销指定会话或指定用户的全部会话。

现实关系与上下文角色继续由 Calmy 业务模型表达：`Space` 表达长期共同关系环境；`Person` 与 `Relation` 表达现实人物及其关系；`SceneParticipant` 表达某个情境中的参与人及身份；`Owner/Steward` 表达数据归属和管理责任；“本人、伴侣、家庭成员、访客、管理者、审核者”等权限模板作用于明确的业务上下文。系统管理页不复制这些对象，也不把它们转换为 User 的全局部门或岗位字段。

### 3.1 若依/芋道术语在 Calmy 中的适配

| 后台常见概念 | Calmy 对应表达 | 边界 |
|---|---|---|
| 部门/组织 | `Space` 可表达家庭、伙伴关系或长期小组等共同关系环境 | Space 不是强制的树状账号组织，也不属于认证目录；成员身份不授权查看数据 |
| 岗位/任职 | `Person` 在特定 `Space` 或 `Scene` 中的关系/参与身份，由 `Relation` 或 `SceneParticipant` 表达 | 角色依赖上下文，不能放成 User 的全局岗位字段，也不授予系统管理 API 权限 |
| 后台系统角色 | `SystemRole` 与 Calmy 产品角色模板分开 | 只控制系统管理页面和管理 API；不决定 Vault 内容可见性 |
| 组织数据范围 | Calmy 的 `Permission` / `Scope` | 作用于明确业务数据授权；不由 Space 成员、现实关系或后台角色自动推导 |

若未来要按 Space 委托管理账号，这属于新的系统管理授权需求：必须先定义可见的账号目录索引、用户确认、加密元数据边界及撤销语义，不能默认从 Space 成员关系推导。

## 4. 账号生命周期与密码策略

- 不开放公开注册；首位系统管理员仍通过受环境密钥保护的一次性 bootstrap 初始化，后续账号由有用户管理权限的管理员创建。
- 创建用户时生成一次性临时密码，仅响应创建操作一次；首次登录要求用户修改密码。管理员重置密码会撤销该用户现有会话，并要求其下次登录改密。
- 登录名仍为唯一标识并与稳定 `userId` 分离。用户资料可包括显示名称、邮箱、电话、性别、头像、状态、备注及创建/更新/最后登录审计字段；登录名编辑需避免影响既有数据引用。
- `User` 可与一个现实 `Person` 显式绑定，但绑定不由管理员通过部门/岗位代替，也不自动产生数据授权。是否允许管理员代用户建立绑定不在本期范围；绑定流程遵循既有身份设计的明确确认要求。
- 由系统安全设置持有密码规则：默认最小长度为 6，最大长度 256；默认不强制大小写、数字或符号组合，以允许用户明确设置 `123456`。管理员可启用复杂度条件和更高的最小长度。
- 密码继续使用服务端 PBKDF2-SHA256 + 每密码独立随机盐保存哈希。密码规则调整不会改变哈希方案，也不得把明文密码写入数据库、日志、导出或前端长期存储。
- 失败次数与锁定时长可配置；现有“30 秒窗口内 5 次失败、锁定 30 秒”转成初始配置值。账号锁定与账号停用为不同状态，解除锁定不等同启用账号。
- 登录验证码可配置开关及类型；启用时服务端验证且具备过期/一次性语义。默认关闭，避免阻挡单人本地初始化。
- 初始密码修改提示和密码有效期可配置。首次登录/管理员重置导致的强制改密不可由用户绕过；默认不强制普通密码过期，管理员可改为到期提醒或要求改密。

## 5. 角色、权限和组织边界

- 角色权限采用 RBAC：用户关联角色，角色关联系统管理菜单、页面操作和管理 API capability。界面隐藏菜单只改善体验；Worker 必须独立做相同授权校验，默认拒绝未配置的管理 API。此阶段不使用系统角色决定 Diary、Capture、Health、Finance 等加密业务内容的可见性或解密能力。
- 系统内置不可删除/不可停用的 Super Administrator 角色与首位管理员保护；禁止用户移除自己最后一个可用的管理权限，也不能禁用最后一个超级管理员。
- 系统角色仅授权系统管理能力。首期不建立部门驱动的数据范围规则；所有敏感管理 API 由 Worker 根据角色 capability 校验。若后续需要委托分层账号管理，应基于 Calmy 明确批准的账号管理范围模型另行设计，不能把业务 `Space` 成员资格直接用作账号管理权限。
- Calmy 的产品角色模板（例如伴侣、家庭成员、访客、管理者、审核者）属于加密业务语义和 Permission/Scope 模型，不等同系统 RBAC 角色；产品角色变化不改变登录、用户管理 API 或系统菜单授权。
- `Space` 成员关系、`Relation`、`SceneParticipant` 和产品上下文角色模板不自动授予任何 Calmy 业务数据权限。Diary、Capture、Health、Finance、Person、Scene、Space、Entity、Vault 与共享内容仍按认证 User 隔离，并遵循 Calmy 显式 Permission/Scope 和客户端加密规则。
- 系统管理员的组织管理权或 Super Administrator 身份不允许读取、导出或解密其他用户 Vault 内容。用户管理重置登录密码不得重置、替换或恢复内容加密密钥。

## 6. 会话、日志与可见元数据

- 会话继续使用高熵随机 bearer token；D1 只存 token hash；有效期保持现有 30 天，刷新时轮换 token；登出、改密、重置、停用、管理员强制下线均可撤销会话。
- 登录日志仅保存账号标识、结果/失败类别、发生时间及必要的 IP/设备元数据；不保存提交的密码或原始认证请求体。登录失败原因对客户端维持统一提示，避免账号枚举。
- 操作日志保存 actor userId、动作、目标系统对象、时间、结果和必要的脱敏前后差异。不得写入业务 Entity 内容或 Vault Payload。
- 本功能增加的网络和审计字段属于身份/管理元数据；它们不改变 ADR-001 的内容零知识边界。保留期限、清理频率和 IP 精度在实现计划中作为可配置/最小化要求，不记录比排障/审计必要更多的信息。

## 7. D1 数据模型方向

在现有 `users`、`sessions`、`login_limits` 上增量演进，不重建身份事实源。至少补充以下关系/实体：

- `user_roles`：用户与系统角色的多对多关系。
- `roles`：名称、唯一编码、状态、系统内置标记与审计字段。
- `role_permissions`：角色到受控管理菜单/页面操作/API capability 的关系。
- `system_settings`：版本化的账号安全参数，带合法值范围和更新审计。
- `login_logs`、`operation_logs`：可分页查询并有清理策略的审计表。
- `sessions` 的必要元数据列：最后活动时间、必要网络摘要；不得保存明文 token。
- 不新增 `departments`、`posts`、`user_posts` 或系统角色到 Calmy `Space` / `SceneParticipant` 的隐式映射。`User` 与 `Person` 的可选显式绑定按既有身份模型处理，不把 Person 变为账号表的部门或岗位字段。

具体字段类型、索引、迁移顺序、兼容旧 `role = admin | user` 的映射和 API 契约进入实现计划；禁止直接修改现有生产数据库或账户，除非另有明确部署授权。

## 8. 兼容与迁移

- 现有 `admin` 映射到受保护的 Super Administrator；现有 `user` 映射到不含管理 capability 的基础用户角色。
- 保留当前登录、bootstrap、改密、用户启停和重置语义的 API 兼容性，分阶段切换前端调用。
- 旧 `/api/setup` 同步密码路径保持隔离/退役状态，不得作为用户账号登录的后门；安全设置只应用于新 `/api/auth/*` 身份路径。
- 安全参数缺失时由 Worker 提供明确默认值并补齐 D1 配置，不允许未初始化配置意外扩大权限。
- 角色菜单与 API capability 迁移采用 deny-by-default；新旧授权结果不确定时保留已有用户可访问的业务个人数据，但不授予新的管理权限。

## 9. 分阶段交付

1. **阶段 A：管理 RBAC 基础**——数据库迁移、内置系统角色、用户角色关联、管理 API 权限、Super Administrator 保护；确认用户资料与显式 User-Person 绑定边界。
2. **阶段 B：账号安全策略**——安全设置、默认允许 6 位密码、复杂度配置、失败锁定配置、登录验证码策略、首次/重置改密、旧账号迁移。
3. **阶段 C：审计与会话管理**——登录日志、操作日志、在线会话列表、强制撤销与日志脱敏/清理。
4. **阶段 D：系统管理前端**——独立导航与页面、角色配置及操作授权、筛选/分页/确认和失败恢复体验；按已有产品信息架构确保名称与入口统一。
5. **阶段 E：迁移验证与上线准备**——旧角色映射、账户和会话兼容、越权用例、密码规则回归、数据库备份与部署说明。线上部署和数据库变更须依照已有远端授权边界另行处理。

## 10. 验收标准

1. 管理员能创建、编辑、启用、停用、重置和查询用户；普通用户不能执行管理 API。
2. 用户可绑定多个系统角色；用户不要求有部门或岗位字段。
3. 角色能授权实际的系统管理菜单、页面动作与 Worker API；绕过前端直接调用未授权 API 返回拒绝。
4. 系统角色不产生部门/岗位或 Space/Scene 权限；不能扩展到业务 Vault 内容。
5. 管理员可配置密码最小长度、复杂度、失败锁定、验证码、初始密码提示及密码有效期；默认配置允许 `123456`，密码仍安全哈希。
6. 登录失败达到当前配置门槛后锁定并能查看/解除锁定；返回错误不能泄露账号是否存在。
7. 首次登录和管理员重置后必须改密；改密/重置/停用/管理员下线会按规则撤销会话。
8. 登录、管理操作和活跃会话可查询；日志不含密码、令牌、解密密钥或业务内容。
9. 唯一超级管理员不可被误删、停用或剥夺最后的管理员权限。
10. 现有 admin/user 账户、数据隔离和 Vault 密钥封套不因系统角色、Person 关系、Space 成员或 Scene 参与关系变化而串户或被重置。
