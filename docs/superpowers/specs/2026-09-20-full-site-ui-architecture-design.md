## 1. 目标

为当前应用建立一致、可扩展、适配桌面与手机的 UI 架构，覆盖四个日常主入口、全部扩展模块、独立场景页和嵌入式 Vue 设置页。改善页面壳层、路由元数据、导航入口、可复用控件和各类页面的布局一致性，同时保持 Calmy 作为人与世界之间反思层的产品边界。

这次工作先形成可回退的视觉与组件试验。它用于验证代码结构和页面体验，不代表已完成真实用户研究、导航定稿或产品方向迁移。

## 2. 设计原则

1. **先保持熟悉，再提高一致性。** 延续 Calmy 现有白色、浅绿和森林绿识别、中文命名与主入口；通过间距、层级、版面和控件统一建立新体验，不以换肤为由改写产品概念。
2. **主线清晰，扩展入口有序。** 保留当前四个主入口和六个扩展分组。导航文字、顺序、归组和 `/app/profile` 的职责不在本规范中重新裁决。
3. **页面围绕真实内容。** 首页强调当下的一件行动和轻量记录；列表、回顾、资料和设置页服务其实际任务。不增加虚构的进度评分、使用统计、连续天数或个人资料。
4. **组件共享外观，不统一领域行为。** 页面可共享标题、内容区、卡片、列表行、空状态和状态提示；数据读取、保存、命令、领域状态机和外部集成仍由现有页面及领域层负责。
5. **各屏幕提供完整体验。** 桌面侧栏、手机主导航、功能目录、搜索、上下文栏和内容区有清楚职责；窄屏不把桌面双栏机械压缩。
6. **可访问性属于架构。** 保留可见键盘焦点、正确的当前页语义、标题层级、弹窗焦点管理、状态播报、窄屏可操作性和文字放大空间。

## 3. 视觉语言

- 默认画布以温暖白和浅中性灰为主，浅鼠尾草绿承载轻提示，森林绿用于主操作、当前入口和必要强调。用户可在外观设置中为浅色和深色外观分别自定义页面背景色，也可随时恢复该主题默认值。
- 使用细边界、克制阴影、适中的圆角和稳定的间距刻度建立分组；让文本层级和留白承担主要视觉组织。
- 中文正文采用系统可用的无衬线字体栈；标题、说明、次级信息和交互控件具有稳定的字号、行高与对比度。
- 图标使用一致的线性图标系统。保留深浅外观能力；两种主题使用语义化颜色令牌，不在页面样式中散落硬编码色值。
- 自定义背景色只覆盖应用的页面画布，不染色导航、卡片、输入框、按钮或语义状态色；选择后提供实时预览，确认后保存在本机 UI 偏好中。每种外观各自保存一个颜色值，未设置时使用对应主题默认背景。
- 背景颜色保存前检查对比度：普通文字至少 4.5:1，大号文字至少 3:1；在页面画布上为文字选择满足对比要求的语义令牌。颜色选择器、预设色块、预览和恢复默认均支持键盘与屏幕阅读器。
- 浅/深主题的背景分别保存在一个本机 UI 偏好中，不上传、不同步，也不进入业务数据导出。重置背景只恢复当前主题的默认画布色。
- 视觉概念板只用于颜色、层级、密度、页面壳层和组件关系参考。板中的文案、人物、日期、记录内容、插图和交互细节均为生成占位，不得作为产品事实复制进页面。

## 4. 信息架构和兼容边界

### 4.1 主入口

保持 `src/react/navigation.ts` 当前顺序、文案和路由：

| 标识 | 文案 | 路由 |
|---|---|---|
| today | 今天 | `/app/today` |
| capture | 记录 | `/app/capture` |
| matters | 处境 | `/app/matters` |
| review | 回顾 | `/app/review` |

### 4.2 扩展分组

保留当前六组及其现有项目归组、名称、顺序和路径：

| 分组 | 页面 |
|---|---|
| 工作 | 看板、任务、目标、日历、飞书、周期 |
| 内容 | 收集、资料、探索、日记、文章 |
| 关系 | 人物、图谱、记忆 |
| 工具 | 习惯、财务、专注 |
| 试验 | 未来、场景 |
| 个人 | 我的、设置 |

桌面显示主入口；扩展页面通过现有“功能”目录按分组浏览。手机保留四个主入口和“功能”入口。当前右侧上下文栏可以继续显示当前页面说明和相关快捷动作，但不得成为第二份全量模块目录。

### 4.3 路由、标题与旧入口

- 所有当前 canonical route、动态参数、旧别名、重定向、登录保护和功能回退都保持可用，包括 `/app` 下所有主页面和扩展模块、独立 `/scene`、`/app/home`、`items`、`cases`、旧 `module/*` 兼容入口及高级设置。
- 页面标题、说明、活动导航项和功能目录入口从一个经过类型约束的路由/导航元数据注册表派生，避免 `routes.tsx`、`navigation.ts` 与 `AppShell.tsx` 分别维护冲突映射。
- 元数据只描述标识、路径模式、中文标题/说明、主/扩展分组、活动匹配规则及兼容别名。认证边界和页面视图仍显式配置；元数据不得决定数据模型或领域流程。
- 动态路径（如 `/app/matters/:id`）应解析为正确的主入口和页面标题。旧路径跳转到现有兼容目标；浏览器书签、详情页和跨模块链接不因菜单重排失效。
- 第一期不批量重命名后台对象、不改变页面语义，不把 `/scene` 或试验页提升为正式主线，也不重新判断现有分组是否符合真实用户心智。
- `LegacyAdminHost` 仍使用 Vue 与 Element Plus 承载设置、同步和迁移能力；它属于全站视觉覆盖范围，沿用语义令牌，并在设置页前段增加“外观”区，不重写原有业务组件或数据操作。
- 独立 `/scene` 页保留独立入口与选择/保存/返回行为；共享配色、排版、表面和焦点令牌，不强行塞入常规工作区壳层。

## 5. 页面壳层与组件职责

全站共享壳层建议拆成以下边界，组件命名可在实施计划中结合现有文件调整：

```text
CalmyAppShell
├── DesktopPrimaryNav
├── WorkspaceFrame
│   ├── PageTopBar (页面身份、全局搜索、保存状态)
│   ├── RoutedPage
│   └── ContextRail (可收起、页面相关内容与快捷动作)
├── MobileHeader
├── MobilePrimaryNav
├── FeatureDirectoryDialog
├── GlobalSearchDialog
└── LiveFeedback (Toast / 保存状态)
```

- **应用壳层**：只负责响应式布局、路由上下文、导航、全局搜索、主题和共享反馈，不承载领域业务决策。
- **桌面主导航**：呈现四个主入口与进入分组目录的入口。扩展目录复用既有六组元数据。
- **功能目录弹层/抽屉**：桌面与手机复用相同的分组和目标页面；支持搜索、键盘导航、Escape 关闭、焦点圈定和关闭后焦点返回。
- **页面顶栏**：页面标题、简短说明、搜索和保存状态有统一位置；页面内主操作留给页面内容，避免两个互相竞争的主按钮。
- **上下文栏**：桌面可见时只显示当前页解释与少量相关动作。窄屏下按需移入页面内容或功能菜单，不挤压主内容。
- **移动主导航**：固定呈现四个入口和功能目录；确保安全区、横向空间、文字缩放和键盘可达性。
- **搜索与反馈**：保留全局搜索语义、快捷键、弹窗焦点和返回路径；保存中、已保存、冲突、失败等状态使用统一播报区域。
- **外观设置**：在 Vue 设置页标题之后、数据管理内容之前增加“外观”区，提供浅/深外观切换、自定义画布颜色、颜色预设、实时预览、应用/恢复默认和保存状态；保留原设置页其他内容，不改变业务状态。

## 6. 设计令牌和可复用 UI 层

建立主题级 CSS 令牌，至少覆盖：

- 画布、表面、边界、文字层级、强调色、交互状态和焦点环；
- 字体、字号、行高、字重和标题层级；
- 间距刻度、内容最大宽度、窄/中/宽断点、导航宽度和右栏宽度；
- 圆角、阴影、动画时长和层级。
- 浅色与深色主题分别可覆盖的页面画布颜色，以及通过对比度校验后使用的画布前景文字令牌；卡片和输入面保留自身表面与文字令牌。

基础 UI 层优先复用或扩展现有 `src/react/ui` 控件，不再新建语义重复的按钮体系。统一实现和文档化：

- `PageHeader`：标题、说明、可选主操作；
- `PageContent`：响应式宽度和页面内纵向间距；
- `Surface/Card`：有边界、有标题或无标题的内容面；
- `ListRow`：可点击行、次级说明、状态和键盘反馈；
- `EmptyState`：解释当前状态并给出一个自然的下一步；
- `StatusMessage`：成功、处理中、待确认、错误等可读且可播报状态；
- `PrimaryAction` / `SecondaryAction`：明确的优先级和触控尺寸；
- `Dialog` / `Drawer`：共享焦点和关闭约定。

令牌落地期间保留旧样式的隔离/回退入口，禁止一次性重写 `react.css` 中与功能行为耦合的规则。清理重复 CSS 只在新旧页面视觉与功能稳定后逐步完成。

## 7. 页面类型和覆盖范围

所有当前 React 主应用路由和扩展模块都进入迁移清单，按页面结构复用布局模板；模板只统一空间和表现，不强迫不同领域共享数据操作。

| 页面类型 | 覆盖页面示例 | 统一部分 | 保留部分 |
|---|---|---|---|
| 当下工作区 | 今天 | 内容宽度、行动卡、快速记录区、轻量时间线 | 现有行动排序、保存与上下文逻辑 |
| 快速输入 | 记录、收集 | 输入区、来源/标签辅助区、保存反馈 | 各自数据来源、提交语义和历史入口 |
| 列表与详情 | 处境、人物、目标、日记 | 列表行、选择态、详情页标题与动作区 | 领域状态、命令和关联关系 |
| 时间与回顾 | 回顾、周期、日历 | 时间范围控制、事件/记录行、来源标识 | 时间查询、回顾反馈和日历操作 |
| 资料与内容 | 资料、探索、文章 | 搜索/过滤栏、可读内容行、空状态 | 内容生命周期、Flow 约束和外部来源 |
| 看板与行动 | 看板、任务、习惯 | 列/组标题、卡片和触控/键盘状态控件 | Action 状态机、筛选、拖拽语义 |
| 个人工具 | 财务、专注、个人 | 工具页标题、摘要区、记录表单/列表 | Finance/Pomo/Profile 各自用例和指标边界 |
| 关系与理解 | 图谱、记忆 | 说明层、证据/来源行、空状态 | AI 判断权、来源链路、编辑/删除能力 |
| 外部集成与配置 | 飞书、设置、高级设置 | 分组偏好、权限说明、保存/错误状态；Vue 宿主采用兼容令牌 | 授权、同步、Vue 组件、迁移流程及数据边界 |
| 外观偏好 | Vue 设置页标题下方的“外观”区 | 主题模式、背景颜色、实时预览、应用、恢复默认和保存提示 | 本机 UI 偏好；不进入业务数据、导出内容或同步 |
| 试验能力 | 未来、场景 | 试验标识、内容宽度和说明层 | 未来回望双向可能、来源、不确定性和用户确认 |

不得仅为视觉一致而把不同页面压缩成同一表格、增加必填分类、虚构分析图表，或更改现有动作是否可撤销。

## 8. 响应式与可访问性

- **宽屏桌面**：固定主导航与工作区；上下文栏可收起；主内容有最大行宽。屏幕空间用于内容层级，不用于填入额外仪表盘。
- **窄桌面/平板**：收起次级栏和部分常驻导航内容；目录通过抽屉访问；表单和列表不被压成不可读的多栏。
- **手机**：顶栏、单列内容、四项底栏和功能目录；列表详情按现有路由进入详情页，不依赖 hover；表单控件适配触控。
- **键盘与读屏**：当前导航 `aria-current="page"`；页面切换后焦点/标题有可预测反馈；对话框有名称、焦点圈定、Escape 关闭和焦点返回；异步保存/错误通过 live region 播报；图标按钮有名称。
- **文字放大与对比**：长中文标题可换行；页面缩放时不遮挡操作；正文、禁用态、边框和焦点状态满足清晰可辨的对比。
- **自定义背景色**：浅色、深色外观分别保存画布颜色；卡片、输入控件、导航和状态反馈维持语义表面。普通文字对比度至少 4.5:1、大号文字至少 3:1；对比度不合格时不应用该值，说明和错误状态可由辅助技术读取；恢复默认不清除其他外观偏好。
- OW-04 要求的真实设备、屏幕阅读器、键盘和大字手工核验仍是独立未完成工作。本规范及代码静态语义不得被当作该验证已通过的证据。

## 9. 分阶段实施与回退

实施计划获批后，按下面的顺序提交可审阅的小批次：

1. **基础层**：定义样式令牌、组件边界、路由/导航元数据、浅/深主题画布颜色偏好与单一可回退开关；先选择一个代表页面验证布局。
2. **主线页面**：统一今天、记录、处境、回顾四个主入口和共享弹层/移动壳层，逐页核对原有操作。
3. **扩展页模板**：按第 7 节 archetype 覆盖六个分组中的全部页面、独立场景页和嵌入式 Vue 设置页；对特殊页面保留页面专用结构。
4. **收敛**：核对路由、活动态、文案、深浅主题、窄屏、空/加载/错误/保存状态；完成视觉对照后再移除已无调用的旧规则。

可回退开关的具体形态（开发构建标志或本地实验偏好）由实施计划确定，但必须满足：一次切换能返回原有 UI；试验期间不修改持久数据、路由语义、同步行为或外部服务；新旧样式不同时竞争同一页面选择器；清理旧实现前有完整的路由和页面覆盖清单。

## 10. 验收标准

### 架构

- 所有当前主应用路由、扩展页、动态详情、旧别名和回退均可到达；页面标题、说明和活动导航来自统一元数据，不再按 `pathname.includes()` 维护重复映射。
- 桌面/手机共用同一组导航名称、顺序、分组和链接；每个当前扩展页面都有一个可发现入口或明确的兼容定位。
- 应用壳层、基础 UI 和页面类型模板有清楚职责；页面没有从壳层复制领域读写逻辑。
- 初始试验可通过单一开关整体回退；不需要重建、迁移或恢复用户数据即可切换。
- 浅色和深色主题的自定义画布颜色分别保存在本机 UI 偏好中，跨路由与重载生效；未设置和恢复默认时回到主题默认色。颜色值不进入业务导出或同步。
- 自定义颜色对比度不合格时不会覆盖当前有效色；颜色输入、实时预览、错误提示和恢复默认可通过键盘及辅助技术完成。

### 体验

- 主入口、扩展页和全部页面 archetype 使用统一的标题、内容宽度、间距、控件、空状态和状态反馈。
- 页面操作与原页面的行为相同，用户原有路径、数据关联、保存反馈、导入导出、授权与同步语义不变。
- 不出现虚构指标/个人记录，不把功能数量、使用时长或完成度包装成产品价值。
- 桌面到手机布局各自完整，不出现被裁切的关键控件、依赖 hover 的操作或无法回到主线的页面。
- 预先定义的键盘焦点、弹层关闭、屏幕缩放、保存状态播报和对比度要求经过逐页人工审阅；外部真实设备/读屏器验证单独登记，不借此宣布 OW-04 关闭。

## 11. 不在本次范围内

- 更改主入口或扩展分组名称、顺序、路径、归属和菜单层级；将导航实验批准为正式 IA；
- 按用户意见之外批量重命名对象、重写全局导航或建立新的 Situation 数据模型；
- 修改业务规则、数据库 schema、业务存储键、数据迁移、Repository、同步协议、身份验证或外部服务。新增本机主题级 UI 背景偏好不纳入业务数据、导出或同步；
- 改变 Calmy 的产品概念、领域对象含义、AI 建议和记忆治理规则；
- 创造新的用户旅程、仪表盘指标、统计分数、内容和 AI 生成个人建议；
- 声称导航文案、分组、未来回望或完整产品已通过真实用户/设备验证。

特别说明：OW-21 仍要求真实场景、前台语言和体验反馈；本次方案只在已接受的当前本地 IA 上做可回退 UI 试验，不替代该验证。用户体验当前试改后如要求调整，必须先更新本规范和实施范围。

## 12. 需要实施前确认的开放项

1. 概念板中的风格、壳层和组件方向是否符合预期；
2. 是否接受本规范的“保留当前 IA 与行为、全站按类型迁移、通过开关回退”边界；
3. 可回退开关在计划中选用哪种本地机制；
4. 试验期间旧样式保留到哪个验收节点。

概念板确认了总体风格与组件关系；本规范需由用户审阅。第 3 项在实施计划中选择，第 4 项在任何全量清理前再核对。规范获批后生成分步实施计划，并按此前已确认的分阶段方案推进代码实施。
