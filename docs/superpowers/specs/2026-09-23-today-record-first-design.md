# Today 首页记录优先改造设计

日期：2026-09-23

状态：待用户审阅

## 1. 目标

将 Today 首页从行动规划工作区调整为当天记录入口。用户打开首页后，主要完成一件事：记录今天的事实或内心活动。页面不主动给出行动建议、心理分析、状态判断或催办。

## 2. 首页结构

主区域只保留：

1. 日期与页面身份。
2. 记录类别切换：`心`、`事实`。
3. 加大的自由文本记录框和明确的保存操作。
4. 今天的记录列表，只展示记录、不混入行动条目，按发生时间呈现，并为带类别的新记录显示其类别。

其余 Today 模块集中到主区域下方的 `其他` 折叠区，默认收起：主行动、有余力再做、身体状态、思考、轨迹、主动放下、添加行动。此次只移动这些模块，不改变其字段、回调、保存行为或路由；后续再单独讨论这些模块是否需要调整。

数据来源切换、全局导航和应用级状态仍位于现有位置，不移入 `其他`。本轮只改本地 Today 首页；切换到飞书数据源时，现有飞书任务工作区保持不变。

## 3. 记录类别与兼容性

- 在现有记录对象上新增可选类别字段 `journalCategory`，取值为 `mind | fact`，界面标签分别为“心”“事实”。字段与既有 `type: RecordType` 分离，避免复用 `observation`、`insight` 或 `negative` 后改变这些类型在其他页面的含义。
- 新首页记录必须保存所选类别；两种类别都继续使用现有记录创建、时间戳、编辑/修订和本地优先保存流程。
- 旧记录不回填、不迁移。缺少 `journalCategory` 的记录保持旧语义；历史列表不得把它们伪标为“心”。
- 新字段按可选、增量方式进入本地存储、同步与导入导出边界。旧版本或旧备份中缺失该字段时仍能读取；未知字段值不得导致记录丢失或页面崩溃。
- Today 列表只在字段确实存在时显示“心 / 事实”标签；其他页面的列表展示与筛选保持不变。

## 4. 交互与视觉

- 类别控件在记录框内清楚可见，默认类别为“事实”；切换类别只改变类别和中性占位提示，不自动生成内容。
- 文本框明显大于当前单行快速记录区，可容纳多行文字并允许用户继续手动调整高度；桌面与移动端均保持保存按钮可见、可操作。
- 保存后清空输入、显示现有保存反馈，并将新记录追加到今天列表。继续使用现有错误恢复和保存路径。
- `其他` 使用单一、键盘可达的折叠/展开控件；展开后按原顺序容纳原模块。不会为每个旧模块再套新的卡片层级。
- 记录框、类别控件、时间线、`其他` 在桌面与移动端的阅读顺序一致；尊重 reduced motion 与现有 focus 样式。

## 5. 范围与非目标

- 范围：React 本地 Today 页面组合、记录类别字段的端到端传递、Today 历史展示、字段兼容测试。
- 不改：旧记录内容、既有 RecordType、领域动作/计划/身体状态数据、`其他` 内模块行为、其他模块页面、旧版兼容 Today 页面、路由、认证与飞书任务工作区。
- 不做：AI 推断、自动情绪分析、完成率/统计卡片、记录提醒或新建议。
- 不删除旧模块，也不把它们改成新的全局导航页面；此次 `其他` 只作为 Today 页内的收纳区。

## 6. 验收

- 记录类别为“心”或“事实”的新记录可分别保存、刷新后读取，并在 Today 列表正确展示类别。
- 缺少新字段的旧记录仍可正常读取、筛选和显示；既有 `negative`、`observation`、`insight` 等语义不变。
- Today 首屏只突出记录入口和今日记录；其他模块默认折叠且仍可使用。
- 输入、切换类别、保存、错误重试、展开 `其他` 的键盘与触屏操作可用；窄屏无横向溢出。
- 相关测试、全量测试、构建、桌面/移动截图及差异检查通过。
- 不 commit、不 push。
