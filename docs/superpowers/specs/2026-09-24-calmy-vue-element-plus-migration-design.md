# Calmy Vue + Element Plus 前端统一迁移设计

## 状态

用户已确认完整保留功能迁移，并补充要求：迁移后的 UI 与功能必须和当前运行的 React 工作台一致。本规格据此更新为严格对照基线。

## 背景与目标

Calmy 仓库同时包含 Vue 3 / Element Plus 与 React 19 两套前端。当前 `index.html` 指向 `src/react/main.tsx`，实际工作台由 React 渲染；`src/main.ts`、`src/App.vue`、`src/router/index.ts` 和 `src/views/*` 保留了旧 Vue 应用，但路由和页面能力未覆盖后来加入的完整工作台。双运行时使入口、布局、组件和测试存在两套实现。

目标是将当前用户可见的 React 工作台完整迁移至 Vue 3 + Vue Router + Pinia + Element Plus，保持相同的路由、页面内容、布局、字号、间距、颜色、控件状态、动效、导航、工作区标签、搜索、响应式行为和操作结果。业务规则、领域模型、持久化、同步协议和数据格式保持不变。迁移完成后，Vue 成为唯一应用入口；不继续保留两个可运行的 UI 栈。

## 已确认范围

- 保留当前 React 工作台的完整用户可见功能，包括新增的主数据管理、下拉控件、导航和工作区行为。
- 旧 Vue 页面作为可复用实现和行为参考，不直接整体回退到旧版页面。
- 以 Vue 3 单文件组件、Vue Router、Pinia 和 Element Plus 作为目标 UI 栈。
- 复用 `src/core`、`src/domain` 中与 UI 框架无关的业务、数据、存储和同步能力；仅在 Vue 组件边界适配调用方式。
- 当前 React 运行界面是 UI 与交互的判定基准，迁移不重新设计。Element Plus 用于能达到同样外观和行为的基础控件；其默认 DOM 或样式造成可见差异时，使用 Vue 原生组件和现有 Calmy 样式实现等价外观。
- 测试先行；不提交、不推送；不修改数据 schema、存储格式、业务规则或远端服务。

## 路由与页面覆盖

React 路由来源为 `src/react/route-manifest.ts` 与 `src/react/routes.tsx`。规格基线为 `appPageRegistry` 中全部页面描述和应用路由，包括 Today、Capture、Matters / Matter Detail、Review、Cycle、Flow、Profile、Memory、Future、Admin / Advanced Admin、Calendar、People、Master Data、Library、Graph、Inbox、Tasks、Task Board、Feishu、Habits、Finance、Goals、Pomo、Diary、Posts、Scene，以及登录/口令和兼容重定向。

目标 Vue 路由集中到 `src/router/index.ts`，明确逐一映射当前路由清单。旧版路由可保留兼容重定向，但不能以隐藏页面、占位页或旧数据模型替代现有 React 页面能力。未知路由和未登录保护行为也需保留。

## 架构与迁移方法

1. 先固定当前工作区的 React 基线：记录 UI 文件版本、路由与交互清单、可重复的隔离测试数据、相同 Chrome 环境下的桌面/平板/移动截图与关键控件尺寸。现有未提交改动属于基线，不能以 Git HEAD 或旧 Vue 页面替代。
2. 在独立的 `vue-preview.html` 入口预览 Vue，保留 `index.html` 的 React 生产入口，直到所有页面验收。预览与基线使用隔离的浏览器数据目录，避免测试写入用户数据。Vue 应用继续由 `src/main.ts` 启动，完成 IndexedDB hydrate / migrations 后再挂载。
3. 在 `src/vue/shell/` 建立新的 Vue 主壳，旧 `src/views/AppShell.vue` 保留为对照参考。新主壳承载当前工作台导航、可折叠/可调整侧栏、二级功能目录、可拖动工作区标签、全局搜索、沉浸模式、响应式移动导航、键盘操作与页面过渡。优先复用现有 Calmy CSS token、类名和布局关系，减少渲染差异。
4. 当前 React 页面逐页移植到 `src/vue/pages/`。旧 Vue 页面作为可验证的实现参考，但逐项对照当前 React 行为补齐差异；新增页面由 React 实际行为和现有领域接口定义功能对等。
5. 页面组件直接调用现有 `src/core` / `src/domain` 服务；不在 Vue 层复制规则，也不将 React hooks 机械地翻译为新的业务抽象。必要的共享展示逻辑放到小型 Vue composables 或通用 UI 组件中。
6. Element Plus 控件通过全局主题/token 与少量 Calmy wrapper 对齐当前控件的尺寸、焦点、禁用、错误、加载、键盘及动效表现。复杂自定义菜单、拖拽 tab 和 Calmy 专属交互继续使用 Vue 原生组件/CSS。
7. 迁移按独立路由组逐批交付，每个路由通过截图差异检查和操作清单后才标记完成。全路由验收后切换 `index.html` 到 Vue 入口；确认真实入口可用后清理 React 运行依赖、入口、样式和死代码。

## 对照基线与验收标准

- 固定同一浏览器版本、设备像素比、字体、视口、主题、数据夹具和动画完成时刻，分别打开 React 基线和 Vue 预览。至少覆盖 1440×900、1024×768、390×844；现有 320px 与 200% 缩放 UI smoke 也继续通过。
- 每个页面记录默认、空数据、典型数据和其特有的关键交互状态。侧栏展开/收起、二级目录、下拉打开、弹层、标签激活/移动、沉浸模式、保存中/成功/错误等共享状态按实际适用页面拍摄对照。
- 对同一状态截取两套界面，逐项检查截图像素差异和关键元素的 `getBoundingClientRect`、字体、颜色、边框、阴影、滚动区域。动态时间和随机内容用固定夹具替代。任何可见差异必须修正或记录为用户明确批准的例外；默认无例外。
- 功能清单逐项验证鼠标、键盘和触控路径、表单值、错误反馈、持久化与刷新后状态。不能仅凭截图或页面能打开判定完成。

- 每个当前注册路由都有 Vue 实现或明确兼容重定向，页面标题、入口、主要操作和空/错误/加载状态齐全。
- 现有用户数据可以在 Vue 入口读取、创建、编辑和持久化；数据迁移与同步测试保持原语义。
- 导航、工作区标签的开关/拖动/键盘操作、全局搜索、侧栏尺寸与折叠、沉浸模式、移动端抽屉行为保持可用。
- Element Plus 控件在 Calmy 主题下呈现与现状相同的外观；点击按压、页面/菜单/弹层过渡及 `prefers-reduced-motion` 行为与当前界面一致。
- UI 和功能按同一基线验收，不因使用 Vue/Element Plus 改动文案、控件几何、布局或交互顺序。
- 构建、单元测试、浏览器运行验证均通过；在所有路由达到等价之前，不移除 React 入口或依赖。

## 测试策略

- 每个迁移页面先添加或改写 Vue Test Utils 行为测试，观察失败后再实现。
- 为 Vue 路由表、应用壳、登录保护、Element Plus 主题适配、菜单/标签/抽屉/搜索交互建立可重跑的测试。
- 保留并运行所有领域、存储、备份、同步和 IDB 运行时测试，确保迁移没有业务及数据回归。
- 阶段性运行 `npm test` 与 `npm run build`；入口切换前执行路由覆盖检查和人工页面巡检。
- 复用 `test/ui-runtime.mjs` 的 Chrome/CDP 隔离运行方式，建立 React/Vue 同状态截图、几何与交互对照；截图本身不包含用户真实内容。
- 删除 React 代码前检查实际引用与动态加载入口，确认没有用户可访问路径继续依赖 React。

## 非目标

- 不重写业务逻辑、领域服务、IndexedDB / OPFS / Vault / 云同步、数据模型或 API。
- 不新增产品模块或改变信息架构，不因参考芋道/若依而复制其后台产品结构。
- 不做一次性全量重写后才验证；不以旧版 Vue 功能缺失换取更快切换。
- 不在本次迁移中发布、提交或推送代码。

## 风险与缓解

- **两套页面不完全等价：** 维护路由功能矩阵，按路由验收，禁止先切入口后补缺失页。
- **现有工作区有未提交改动：** 这些改动属于用户现有工作，执行计划必须逐项保留，避免覆盖；迁移前记录并做基线验证。
- **Element Plus 默认视觉与 Calmy 不一致：** 建立集中主题和控件契约，优先用主题变量与 wrapper 做统一，而非散落页面覆盖。
- **旧文档方向冲突：** `PRODUCT.md` 与 `docs/product/OPEN_WORK.md` 当前把 Vue 视为待退出兼容层；用户本次决定改为 Vue 目标主栈，实施计划须同步标记旧方向已被取代。
- **迁移造成业务/数据回归：** 页面测试之外持续运行领域、存储和离线同步测试；限制生产改动只在 UI/路由边界。
- **清理过早：** React 源码和依赖最后清理，必须有引用扫描和完整验证证据。
