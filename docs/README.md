> 状态：当前入口 · 更新日期：2026-08-22

## 先读这五份

1. [产品重设计](product/PRODUCT_REDESIGN_2026-08-22.md)：产品承诺、范围、功能分层与关键指标。
2. [UI / UX 重设计](product/UX_UI_REDESIGN_2026-08-22.md)：信息架构、导航、核心页面和交互规则。
3. [工程评审](product/ENGINEERING_REVIEW_2026-08-22.md)：设计与代码差距、风险和目标架构。
4. [路线图与验收](product/ROADMAP_AND_ACCEPTANCE_2026-08-22.md)：实施顺序、停止线和发布门槛。
5. [产品评审会纪要](product/REVIEW_MEETING_2026-08-22.md)：多角色评审意见、分歧和最终裁决。

## 权威层级

```text
已接受的产品决策
  ↓
2026-08-22 重设计文档组
  ↓
2026-08-19 领域、流程、协议执行文档
  ↓
实现总档案与交接档案（只描述实现事实）
  ↓
Beryl 历史文档（只作迁移参考）
```

发生冲突时，先遵循产品决策记录，再遵循 2026-08-22 重设计文档；实现状态必须以代码和可复现验证为证据。

## 维护规则

- 新功能先更新产品决策与验收标准，再进入代码。
- UI 不得直接扩展领域范围；试验能力默认放入“更多”或设置中的实验区。
- “已有页面”“已有类型”“测试通过”都不等同于产品闭环已经可用。
- 历史文档不删除；通过登记册标注其状态，避免丢失演进依据。
