# Beryl v2 · 设计文档

> 个人管理体系（Vue 3 + Element Plus + TypeScript，Cloudflare Pages 静态托管 + D1 云端同步）

---

## 一、设计原则

设计原则是 Beryl 一切界面决策的上位准则。所有页面、组件、动效、配色改动都必须能对到某条原则上；对不上原则的改动不做。

### 1. 内容优先，界面退后
背景与容器保持中性，让数据与内容自己说话。界面元素（边框、底色、装饰）只承担分层职责，不承担注意力职责。
- 落地：白底/深底 + 1px 细边框卡片；无重阴影、无玻璃拟态装饰、无渐变炫技。

### 2. 清晰的视觉层级
全站统一三级字号（标题 / 正文 / 辅助小字）与三级文字色（主 `--c-text` / 次 `--c-text-2` / 弱 `--c-text-3`）。任何一屏内，用户应在 3 秒内说出"先看什么、再看什么"。
- 落地：hero 2.25–2.5rem → 正文 14px → 辅助 10–12px；字重 700/600/400。

### 3. 单强调色 + 中性色
全局只有一个交互强调色（天蓝，场景模式可替换为场景色），只用于：选中态、主按钮、链接、进行中状态。其余一切用中性灰阶。
- 语义状态色（绿/红/琥珀）只表示结果（成功/错误/警告），不参与装饰。

### 4. 一致的节奏（4/8px 网格）
间距、圆角、边框遵循同一节奏：大卡 16px、小卡 10px、卡片间距 10–14px、区块间距 16/32px。同类元素必须长得一样。

### 5. 克制的动效
动效只做反馈，不做表演。时长 150–200ms，缓动 ease；hover 上浮、箭头位移、折叠展开、主题切换、加载渐入是允许的；弹跳、循环、放大镜式效果禁止。

### 6. 状态可见
选中 / 悬停 / 禁用 / 加载 / 错误 / 拖拽中，每个状态都有明确视觉表达。不允许"点了没反应"的控件。
- 落地：导航激活 = 天蓝浅底 + 左侧 2px 强调条；按钮 loading；卡片 hover 描边；拖拽插入线 = 天蓝粗边；键盘焦点可见。

### 7. 可访问性
- 正文对比度 ≥ 4.5:1（WCAG AA）；辅助文字 ≥ 3:1。
- 全部交互元素可键盘操作且有可见焦点（focus-visible 天蓝环）。
- 语义化标签（button / nav / label），不滥用 div 承担交互。

### 8. 响应式与自适应
- 触屏设备（手机/平板）一律移动布局：无常驻顶栏，仅悬浮 ☰ 按钮，抽屉导航。
- 桌面：侧边栏可完全收起（`width/min-width/flex-basis` 全 0，不占空间），左上角悬浮 ☰ 展开。
- 内容容器上限 960px，网格 auto-fill 自动增列，内容永不横向溢出。
- 移动端触屏交互：⤡ 手柄可拖动调大小（`touch-action:none`）、↑↓ 按钮排序。

### 9. 温柔的随机（随机性 / 未知性，但不包含恐惧与得失）
系统应当有"活着的感觉"，但随机性只作用于**呈现层**，绝不触碰**数据层**。这是本项目随机性的总纲：

> **定义**：随机的未知性 = 每次进入/刷新/操作时，呈现上有可预期范围内的变化，给用户"惊喜感"而非"失控感"。
>
> **允许的随机**（无恐惧、无得失）：
> - 内容类：随机名言、随机引言、随机卡片组合与排列顺序、大卡标题语料池随机
> - 呈现类：卡片间距微调、装饰色从预设色板内随机取色
> - 文案类：欢迎语、空状态提示语在预设语料池中随机
> - 时机类：加载完成后的短暂渐入（不做循环动画）
>
> **禁止的随机**（含恐惧/得失）：
> - 随机删除、修改、移动用户数据
> - 随机改变功能行为（按钮做了 A 却触发 B）
> - 随机改变已保存的设置与主题
> - 无限循环 / 不可关闭的自动变化
> - 会让用户担心"是不是出 bug 了"的视觉突变
>
> **检验标准**：任何一个随机元素被问"它为什么会变？"，答案只能是"为了让界面有生气"，而不是"系统失控了"。
>
> **血的教训**：曾有一次"自动清洗"把数字 id 的历史数据当脏数据删掉（误删用户数据）。此后**任何代码都不自动删除用户数据**；脏数据显示层过滤（隐藏不删），删除必须用户手动逐条操作。

### 10. 直接操纵与可逆性
用户可以直接拖拽卡片调整顺序、拖动手柄调整大小，操作即时生效且视觉反馈明确（插入线、虚线框）。布局类操作**只影响呈现**、可持久化、可随时重排，永不触碰数据内容。
- 落地：大卡拖拽排序（天蓝插入线）、大卡 ⤡ 手柄调大小（1 列 ⇄ 整行）、小卡组内拖拽排序；触屏用 ↑↓ 按钮；布局存 `b_wall_layout`。

### 11. 数据本地优先
所有用户数据先落本地（localStorage + IndexedDB 持久镜像），网络只做可选同步与内容增强。断网时系统完整可用（离线名句池兜底）。

## 四、卡片墙架构（首页核心）

### 层级
```
QuoteWall（容器：构建大卡组 + 布局持久化 + 换一批 + 骨架屏）
  └─ GroupCard（大卡片：标题栏 + 拖拽排序/↑↓ + ⤡ 调大小 + 内部小卡网格）
       └─ QuoteCard（小卡分发器：类型注册表 RENDERERS，未知 kind 兜底）
            ├─ cards/PersonQuoteCard.vue   人物+名句小卡（头像块嵌套）
            ├─ cards/QuoteOnlyCard.vue     单独名句小卡
            └─ cards/PersonCard.vue        人物小卡
```

### 数据流（`src/core/quotes.ts`）
```
buildGroups()
  ├─ 网络源（多源备用）：一言 hitokoto → 今日诗词 → 离线池（18 条随机不重复）
  │    有作者 → person-quote；无作者 → quote
  ├─ 本地源：人物库（b_chars）→ person 小卡
  └─ 组装三张大卡：
       🖋 名句组（标题随机：灵感碎片/思考片刻/远方与诗…）
       💬 人物·语录组（网络带作者名句 + 本地人物配离线名句）
       👥 人物库组
```

### 布局持久化（`b_wall_layout`）
`{ orderKinds: string[], spanByKind: Record<kind, 1|2> }` —— 大卡顺序 + 跨列数**按大卡类型（kind）存储**，
换一批后依然保持用户排好的顺序与大小。

### 解耦约定
- 新增小卡类型：`quotes.ts` 加 kind → `cards/` 加渲染器 → `QuoteCard.vue` 注册表加一行
- 新增大卡类型：`quotes.ts` 的 buildGroups 加一组即可
- 小卡不感知大卡结构，大卡不感知小卡内部实现

## 九、同步架构（阶段 2–5 落地）

### 存储与协议
- 本地：localStorage（同步 API）+ IndexedDB（kv 持久镜像 + changes 变更日志 + 自动恢复）
- 云端：D1（SQLite）records 表（key/value/ts/device/deleted），`value` 存本地同一 JSON 字符串的 **AES-GCM 密文**，云端不解析 JSON（纯 KV 容器）
- 协议：`POST /api/sync/pull {since}` / `POST /api/sync/push {changes}`；游标 `b_pull_cursor`、本地时间线 `b_sync_ts`、推送游标 `b_push_cursor`；服务端 SQL 级 LWW（`WHERE excluded.ts > records.ts`）
- 旧 Worker（KV 全量 `/api/data`）自动回退（404 检测）；KV 旧数据/密码自动迁移；D1 无密码时回退 KV auth

### 与 v1 文档 §14.3 的差异（如实记录）
v1 规划为**条目级**（每条记录一行，updatedAt/deviceId/deleted 墓碑，条目级 LWW）；
当前落地为**键级**：云端每键一行，同步增量到"键"粒度，冲突按键 LWW（整键覆盖，最后写入者胜）。

**取舍原因**：条目级要求本地也条目级存储（IndexedDB 主存储 + 9 个模块按条读写改造），
改动面大、数据层风险高；键级让本地零改动、格式两端天然一致，并可通过端到端自测
（`npm run test:e2e`，12 项断言）验证协议。

**代价**：单键内任何变化整键重传（当前数据量下单键 ≤ 几十 KB，可接受）；
双端同时改同一键为整键覆盖而非条目合并。

**升级路径**：条目级同步 = 阶段 2 完整主存储化后，把 Worker 表结构按 §14.3 扩展，协议不变。

### 验证
- 单元测试：`npm test`（31 项：加密往返/密文字符串/LWW 合并/坏值/迁移）
- 端到端：`npm run test:e2e`（12 项：真实 SQLite + _worker.js，setup→push→pull 全链路）
- 后台「🔍 同步诊断」：游标/云端记录数/上次推送/本地值

## 十、关键修复记录（排查经验）

| 问题 | 根因 | 修复 |
|---|---|---|
| 刷新丢数据 | `restoreSync` 全量拉取无条件覆盖本地 | 增量 LWW 合并（仅应用 `ts > localTs`）+ 本地回推 |
| 手机看不到数据 | ① 字符串密文被当明文直接存储 ② 连接后 `sync.mode` 未设置 → 推送/轮询/按钮全失效 | ① `decryptRecordValue` 识别字符串密文 + 清除本地密文残留 ② 6 处连接分支补 mode |
| 添加失败"请重试" | localStorage 存了非数组坏值（`"null"`） | 读写统一数组校验 + 坏值规范化 |
| 空数据删不掉 | 脏条目无 id，按 id 过滤永远删不掉 | 按索引删除 + 显示层过滤（不自动删数据） |
| 自动清洗误删用户数据 | 清洗条件基于类型假设（数字 id 被误删） | 彻底移除自动删除逻辑；改显示层过滤 + 手动索引删除 |
| 侧边栏折叠残留空白条 | flex 子元素 `min-width:auto` 撑开 `width:0` | `min-width:0; flex-basis:0` |
| 折叠后 logo/标题占空间 | 侧边栏头部设计冗余 | 头部只留折叠按钮；手机端去掉常驻顶栏，改悬浮 ☰ |
